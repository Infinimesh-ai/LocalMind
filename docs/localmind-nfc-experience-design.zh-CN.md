# LocalMind NFC 宣传体验与注册转化设计

> 日期：2026-10-25
>
> 状态：早期设计讨论稿。2026-10-27 起，当前 NFC 周边方向见 [LocalMind 周边 Idea](localmind-merch-ideas.zh-CN.md)：每张卡对应独立存储、一段游客对话和一份文档，替代下文按浏览器隔离游客草稿的方案。下文保留页面、认证衔接与验收参考，冲突内容不作为当前实施要求；不代表相关功能已经开发或上线。
>
> 面向：产品、设计、前后端开发及线下推广负责人。

## 1 体验目标

首版围绕一个具体任务展开：**碰一下，把零散记录变成一份能用的汇报。**

首次接触 LocalMind 的用户，通过手机浏览器完成“生成汇报、提出一次修改、保存并继续编辑”。用户先看到完整成果，再因为保存和继续工作的需要进入注册或登录。注册成功后，继续处理刚才的成果。

这条体验需要让用户理解三个价值：LocalMind 能整理材料、能按要求修改成果、能把成果留下来继续工作。首版重点验证这条路径，不展开全部产品功能。

### 1.1 目标用户与使用环境

- 在展会、活动、办公桌牌或宣传卡片上首次接触 LocalMind 的用户。
- 主要使用手机，可能只有短暂注意力，现场网络也可能不稳定。
- 未必准备了自己的材料，也未必愿意立即注册。
- 已有账号的用户可以体验同样的流程，但不重复注册。

### 1.2 首版范围

| 纳入首版                               | 留待后续评估                       |
| -------------------------------------- | ---------------------------------- |
| NFC 与二维码进入同一移动端体验         | 多种能力卡、盲盒任务、展台大屏共创 |
| 虚构示例与用户自行输入的文字           | 文件上传、录音转写、外部系统接入   |
| 一次生成与一次 AI 修改的体验建议额度   | 多轮开放式 Agent 工作流与无限试用  |
| 完整结果阅读、原材料查看与内容复制     | 公开分享、群发、邀请团队和复杂导出 |
| 注册或登录后保存并继续编辑             | 团队配置、付费引导和完整产品教学   |
| 恢复未完成体验、失败重试和活动结束状态 | 跨设备匿名草稿同步                 |

具体额度、保留期限和保存资源类型在第 10 节讨论。首版不宣传尚未确定的免费权益、生成时长或导出能力。

## 2 入口与整体旅程

宣传卡片建议使用以下文案，配清晰的感应位置、产品名称、访问域名和二维码：

> 碰一下，把零散记录变成一份清楚的汇报。
>
> 无需安装，可先体验再注册。
>
> 手机靠近感应区，按系统提示打开；也可以扫码体验。

贴片保存活动入口网址。NFC 和二维码指向相同的体验，可带不同的来源标记。入口标识只用于识别活动，不代表访问者身份，也不授予内部资源权限。每位访问者的草稿与结果独立保存，不能因为使用同一张贴片而共享内容。

| 阶段         | 用户看到什么                 | 主操作                     | 完成后进入             |
| ------------ | ---------------------------- | -------------------------- | ---------------------- |
| 系统打开链接 | 手机系统的链接提示           | 打开                       | 开始体验               |
| 开始体验     | 已填好的虚构材料与说明       | 生成我的汇报               | 生成中                 |
| 生成中       | 真实任务阶段与原材料入口     | 等待；可取消               | 汇报结果               |
| 汇报结果     | 完整汇报、来源材料与修改入口 | 修改这份汇报；也可直接保存 | 修改结果或保存         |
| 保存意图     | 成果预览与保存价值说明       | 保存并继续编辑             | 身份验证或保存位置确认 |
| 注册或登录   | 邮箱入口及可用的验证方式     | 继续                       | 保存并打开成果         |
| 进入产品     | 刚才保存的文档               | 使用自己的材料再做一份     | 正常产品工作流         |

这些阶段不要求对应七个独立页面。开始、生成、结果与修改优先在连续的体验界面中切换，减少跳转；身份验证后必须恢复原成果上下文。

## 3 页面内容与交互

### 3.1 开始体验

首屏采用手机单列布局，显示 LocalMind 品牌、一句用途说明、材料输入区和一个主按钮。

**标题：** 把零散记录，变成一份清楚的汇报。

**说明：** 材料已经准备好了，你也可以换成自己的内容。无需安装，可先体验再注册。

**默认材料：**

> 官网页面已经完成。
>
> 支付联调还没完成，需要继续跟进。
>
> 20 人参与试用，其中 6 人觉得注册步骤太多。
>
> 下周准备优化注册流程，完成支付联调。

材料区标注“虚构示例”，并提供“换成我的内容”。选择后清空输入区，提示“贴几条工作记录就行”；“恢复示例”可以恢复默认材料。用户直接修改示例也可以生成，但不得继续把修改后的内容标为固定示例。

**主按钮：** 生成我的汇报。

**额度说明建议：** 本次体验可生成一份汇报，并让 AI 修改一次。

输入为空时给出就地提示；长度限制与服务端一致，超限时说明如何缩短。提交后防止重复请求。首屏不要求选择行业、职位、团队规模或模型。

用户输入自己的内容时，应有简短、可展开的数据处理说明，涵盖模型处理方式、草稿保留期限与清除方式。具体措辞随实际部署确定，不承诺未经实现的本地处理或即时清除。

### 3.2 生成中

保留材料查看入口，结果区域根据服务端真实状态显示处理阶段，例如“正在整理材料”“正在生成汇报草稿”。只有后端确实提供对应阶段时，才展示更细的进度。

- 不使用虚构百分比或通过计时模拟完成状态。
- 刷新或临时离开页面后，恢复同一次任务及其结果。
- 用户可以取消。取消请求与取消完成需要分别反馈，避免任务已完成时仍显示已取消。
- 等待较久时提供“先看示例效果”。预制结果始终标明“示例效果”，不得冒充当前材料的实时生成结果。
- 查看示例不覆盖自己的任务；自己的结果完成后，提供“查看我的结果”。

生成耗时、出现等待提示的阈值及重试策略，在模型和运行环境确定后测量与配置。

### 3.3 完整结果

结果按手机自然文档流展示，可以连续滚动、选择和复制文字。默认结构为“本周完成、需要关注、下一步”，但标题和条目应与输入内容一致。

默认示例的预期结果：

> **项目进展简报**
>
> **本周完成**
>
> 官网页面已完成，已有 20 人参与试用。
>
> **需要关注**
>
> 支付联调尚未完成；6 位试用者反馈注册步骤过多。
>
> **下一步**
>
> 优化注册流程，继续推进支付联调。

结果要求：

- 提供“查看原始材料”，便于核对数字和事实。
- 不补造负责人、截止日期、完成比例或业务结论。
- 用户看得到完整成果，不在正文中途遮挡并要求注册。
- 复制操作有成功或失败反馈；复制失败时仍允许手动选择文字。
- 保留“保存并继续编辑”，允许用户不修改就直接保存。

成果的产品形态是“可以继续编辑的汇报文档”。最终使用 BlockSuite 页面、原生 Docs 或其他资源类型，见第 10 节；本节不预先冻结底层格式。

### 3.4 提出一次修改

结果下方显示：**你可以直接告诉它，哪里需要调整。**

提供两个快捷选项：“压缩成三条”“改成更正式的语气”，以及一句话输入框。快捷选项填入修改要求，由用户点击“修改这份汇报”提交；不因误触选项立即消耗额度。

修改针对当前成果，完成后展示新版本，提供“查看上一版”和明确的版本选择。保存应对应用户明确选中的版本，不能把正在浏览的旧版与实际保存的新版混淆。

修改期间保留上一份完整成果；修改失败时上一版仍可查看、复制和保存。恢复上一版不触发模型调用。模型修改结果必须保持原材料事实边界，不能为迎合语气要求改动数字或虚构进展。

### 3.5 保存引导

第一次结果生成后即可保存；修改完成后进一步突出保存入口。

**文案：** 已按你的要求调整。保存到 LocalMind，之后可以继续编辑、补充材料，并在电脑上接着做。

未进行修改时使用“汇报已准备好”等适配文案，不声称执行过修改。

**主按钮：** 保存并继续编辑。

**次要操作：** 复制内容、继续查看。

点击主按钮表达的是保存当前成果的意图。注册入口围绕这份成果展开，不自动遮挡正文，也不通过虚假倒计时催促注册。暂不注册时，告知真实的草稿有效期；具体期限上线前确定。

### 3.6 注册或登录

身份验证页保留成果标题与简短预览：

> 把这份汇报留在你的 LocalMind。
>
> 完成登录或注册后，继续编辑刚才的内容。

复用现有邮箱入口与实例允许的认证方式：输入邮箱后按服务端返回的方式进入验证码或密码流程；第三方登录只展示实际配置并可用的方式。

- 不要求公司名称、职位或团队规模；不默认订阅营销消息。
- 已登录用户跳过本阶段，继续确认保存位置或保存。
- 关闭验证界面返回原草稿；验证码错误、过期、重发或登录失败不删除成果。
- 邮箱验证完成、OAuth 返回、刷新及浏览器返回都需要恢复原保存意图。
- 在邮箱应用打开另一浏览器的情况下，不能仅凭活动链接领取草稿。应提示回原体验页面完成验证，或采用经过验证的安全接续机制。
- 实例未开放注册时如实展示状态，仍按活动策略允许查看和复制已有结果。

### 3.7 保存成功与首次使用

身份验证成功后，继续执行用户明确发起的保存操作。仅在目标资源实际持久化成功后显示：**已保存，可以继续编辑。**

新用户的目标体验是保存到本人拥有的个人空间；该空间不存在时，需通过明确的初始化或位置选择流程建立，不能静默写入某个共享 Workspace 或 Project。已有用户确认目标位置，按实时 ACL 保存。目标位置的可见范围应清楚显示，不新增普通 Workspace 的 actor-only 写入限制。

保存后直接打开成果。主区域保留文档；如接入 AI 修改，沿用现有模型配置、权限和审批规则。体验额度是否包含注册后的 AI 使用，在第 10 节单独决定。

页面突出一个后续操作：**现在，用你自己的工作记录试一次。** 用户点击后创建新的工作内容，保留第一次体验成果；继续使用 AI 前，应如实说明模型可用性和额度条件。

保存失败时保留游客成果并允许重试；保存完成但跳转失败时，显示“已保存，打开文档”。同一次保存意图的重复点击、登录回跳或重试，不应创建多个副本。

## 4 状态与异常处理

| 情况                   | 用户看到的反馈                 | 内容与操作约束                                   |
| ---------------------- | ------------------------------ | ------------------------------------------------ |
| 无输入或超过限制       | 输入区附近的具体提示           | 不启动生成，不消耗成功体验次数                   |
| 网络断开或刷新         | 恢复连接或恢复任务的提示       | 找回同一次任务，不自动新建                       |
| 请求已经提交但响应丢失 | 正在确认任务状态               | 先查原任务，再决定重试                           |
| 生成失败               | 未能完成，可重试或看示例       | 保留材料；失败任务的额度处理规则见第 10 节       |
| 修改失败               | 修改未完成，上一版仍可用       | 不覆盖旧成果，不错误标记修改成功                 |
| 取消与完成同时发生     | 展示最终实际状态               | 不把已完成结果误标为已取消                       |
| 游客额度用完           | 说明已使用的体验与后续条件     | 已有结果继续可读、可复制，不宣传注册即无限使用   |
| 验证码错误或登录失败   | 具体错误与重试方式             | 草稿与选中版本保持不变                           |
| 目标不可写或保存失败   | 选择其他位置或重试             | 不绕过 ACL，不自动换目标、不创建同名副本         |
| 草稿到期或已清除       | 说明原因，允许开始新体验       | 不显示空白加载，不承诺能恢复已删除内容           |
| 活动结束               | 活动状态、可用的示例或产品入口 | 在约定保留期限内，已有草稿仍按活动策略可访问     |
| 再次碰同一贴片         | 继续上次、重新体验             | 仅恢复当前访问者能访问的草稿；新体验仍受额度约束 |

## 5 移动端和视觉要求

沿用 LocalMind 的现有组件、字体、色彩与交互习惯。体验页减少导航干扰，身份验证和保存后自然衔接产品界面。

- 以手机单列布局为主，支持 320px 至桌面宽度；汇报自然滚动，不缩放固定 16:9 画布。
- 每个阶段只有一个突出的主操作，其余操作降低视觉权重。
- 键盘弹出时，输入内容、错误提示和主操作保持可达；底部控件不能遮挡正文。
- 文本可缩放，焦点和按钮名称清晰，触摸目标足够大；状态变化兼容辅助技术。
- 动效只辅助理解状态，尊重减少动态效果设置；不依赖动画才能阅读结果。
- 检查浅色、深色、横竖屏、弱网、前后台切换和浏览器返回。
- 在支持的 iPhone 和安卓实机验证 NFC 打开后的全流程，同时验证二维码入口。

## 6 草稿归属与信任边界

NFC 标签是公开入口，不是身份凭证。入口链接被转发或复制时，不能泄露其他访问者的输入、结果或登录状态。

游客输入、生成结果、版本与任务状态应有独立的持久生命周期，支持恢复、到期与清除。草稿不成为现有业务 Workspace 或 Project 的公开资料，不贡献到业务共享 Memory。

游客生成只能使用当前草稿与受控的公开示例。开放体验不应扩大已有 Workspace MCP 凭据、Project 成员权限或冻结任务的工具能力；不允许匿名执行内部资源读写、外部发送或成员管理。

保存时绑定经过验证的账号、草稿、选中版本和明确目标，保留保存回执。身份切换或目标权限变化时重新确认，不能将草稿误保存到另一个账号。

模型凭据由服务端管理。推广模型的提供方、费用承担及预算需单独配置，不默认借用某个业务 Workspace 的凭据，也不改变全局 Project BYOK 的既有契约。

活动统计只记录必要的渠道、阶段、耗时和结果，不把邮箱、输入全文、生成正文或认证凭据写入分析事件。日志和错误沿用仓库的有界脱敏要求。

## 8 体验成效与观察方式

活动先建立实测基线，再讨论转化率目标，不预设未经验证的提升比例。

| 指标             | 观察口径                                                   |
| ---------------- | ---------------------------------------------------------- |
| 入口到达         | 成功打开体验页的会话，区分 NFC、二维码等渠道               |
| 开始体验率       | 提交生成的会话数除以到达会话数                             |
| 首份成果可见率   | 实际展示本人生成结果的会话数除以提交生成会话数             |
| 修改参与率       | 提交修改的会话数除以看到本人结果的会话数                   |
| 保存意愿         | 点击保存的会话数除以看到本人结果的会话数                   |
| 新用户注册完成率 | 成功注册的新用户数除以进入新用户认证流程的人数             |
| 成果保存成功率   | 成功保存的独立意图数除以发起保存的独立意图数               |
| 首次激活         | 成功保存后，又完成编辑或提交本人材料的新用户；时间窗口待定 |

阶段事件去重，区分新注册与已有账号登录。预制示例展示不计入实时生成成功；浏览器打开次数也不等于实际 NFC 感应次数。

同时观察首份成果耗时、排队时间、错误率、修改成功率和单次体验成本，避免只看注册数而忽略体验完成度。

## 10 下一轮实现讨论

以下问题按依赖顺序讨论。建议值不视为已经确认的技术方案。

| 问题           | 当前方向或建议                                          | 需要明确的决定                                                                |
| -------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------- |
| D01 入口与部署 | 从手机可访问的 HTTPS 活动地址进入，并与正式账号体系接续 | 同站新路由还是独立体验站；目标实例、域名与注册开放范围                        |
| D02 成果类型   | 先完成一份可编辑的汇报文档                              | BlockSuite 页面、原生 Docs 或独立网页汇报；保存后使用哪个编辑器及 AI 修改入口 |
| D03 游客草稿   | 独立持久草稿，按访问者隔离，认证后领取                  | 会话识别、保留期限、清除入口、跨浏览器验证恢复与过期策略                      |
| D04 模型与成本 | 服务端配置推广模型和总预算，建议一次生成加一次修改      | provider、模型、并发、文本限制、失败与取消计额规则、活动停用方式              |
| D05 保存位置   | 新用户目标是个人空间；已有用户确认位置                  | 空间初始化、资源创建和幂等保存契约；不得隐式加入共享空间                      |
| D06 注册后权益 | 保存和人工编辑连续可用；AI 条件如实显示                 | 是否提供后续 AI 试用、额度与凭据如何配置，缺少模型配置时如何引导              |
| D07 活动测量   | 使用必要的服务端与页面阶段事件                          | 来源标记、去重、激活窗口、保留期限与已有统计设施的复用                        |

建议先确定 D01 和 D02，再确定 D03 至 D06。随后制作可点击的手机原型，让 5 位未使用过 LocalMind 的人独立完成“生成、修改、保存”，据观察修正文案与跳转，再进入代码实现。
