# LocalMind 周边 Idea

> 创建与更新日期：2026-10-27
>
> 用途：记录 LocalMind 周边创意及其设计。当前包括 Idea 1：NFC 卡片，以及 Idea 2：LocalMind 四键键盘。
>
> 状态：创意与设计记录。各条目区分用户已明确的方向、设计建议和待讨论问题，不代表已开发、上线或投产。

LocalMind 周边可以把实体物件与产品体验连接起来。用户拿到物件后，应能理解它有什么用、如何进入体验，以及体验完成后如何继续使用 LocalMind。

## Idea 1：NFC 卡片

**每张 NFC 卡片对应一个独立的对话体验空间，包含一片存储、一段游客对话和一份成果文档。**

用途是线下宣传与真实产品体验：用户碰卡打开专属入口，在预置材料与提示词引导下完成一次有边界的 AI 体验，看到对话如何生成和修改实际文档，再引导注册使用 LocalMind。

体验路径：**碰卡 → 本卡入口 → 开始或继续同一段对话 → 生成并调整同一份文档 → 注册或登录继续使用。**

### 1.1 产品定义

#### 用户已明确的核心

1. NFC 卡片提供一次性的产品体验。
2. 存储跟随卡片，每张卡对应独立的一片存储、一段游客对话和一份文档。
3. 不采用按浏览器另建游客草稿作为内容归属单位的方案。
4. 通过预定义提示词、预置材料和受控能力，提高展示效果，体现 LocalMind 的特点。
5. 除体验流程外，还需要设计刷 NFC 后出现的卡片入口。
6. NFC 周边当前只记录这一项卡片创意。

内容保存在服务端，以卡片体验身份关联；实体 NFC 卡保存进入该空间的链接。浏览器仍可维护访问会话，但不因换手机或刷新而生成另一份卡片对话、文档或额度。

#### 一次性体验与再次访问

**一张卡对应一个可延续、额度有限的 LocalMind 体验空间。**

卡片关联预置场景及版本、一段对话、一份成果文档及其版本、任务状态、额度和生命周期状态。不同卡片的体验相互隔离，同一张卡的再次访问回到原体验。

“一次性”建议解释为一份有边界的完整体验。用户首次点击“开始体验”才激活，重复感应不重新赠送额度，也不因为误碰一次就使卡片作废。次数、期限和领取规则仍需确认。

默认按一人领取一张、可以带走的宣传卡设计。卡片转交或由其他手机打开时，仍进入同一个空间、使用同一份额度，不为新的访问者另建体验。

### 1.2 实体卡片设计

#### 正面建议

- LocalMind 品牌与本张卡的主题，例如“项目发布体验”。
- 一句用途说明：**碰一下，让想法变成一份能用的方案。**
- 清楚的感应位置标记，用户无需猜测贴近哪里。
- 可选的系列编号或主题图案，用于识别和收藏；展示编号不作为访问凭据。

视觉延续已提供官网的浅灰底、红色品牌强调与深色文字。实体材质、尺寸、印刷与 NFC 天线位置在打样阶段确定。

#### 背面建议

主要说明：**手机靠近感应区，按系统提示打开；也可以扫码进入。**

二维码指向本卡的同一体验空间，另附品牌域名，便于用户识别来源。简短说明“无需安装，先体验再注册”，并提示本卡访问入口关联同一段体验内容。具体额度和期限以页面展示的真实配置为准。

卡片生产前，核对 NFC 与二维码是否对应同一卡片，验证真机读取、最终贴装后的感应效果，以及不同卡片不会误指向同一空间。

### 1.3 刷 NFC 后的卡片入口

#### 入口归属与路径建议

官网用于宣传，与实际服务站 `https://localmind.infinimesh.cloud` 分开。建议由官网提供稳定的卡片入口，真实体验与邮箱认证在服务站完成。

建议路径关系如下，均为待实现的路由设计：

| 入口               | 职责                                               |
| ------------------ | -------------------------------------------------- |
| 官网的卡片短入口   | 识别本卡并导向有效体验地址，方便后续调整活动或部署 |
| 服务站的卡片体验页 | 校验卡片状态，展示本卡内容，执行受限 AI 任务       |
| 服务站现有认证入口 | 邮箱注册或登录，并恢复本卡的领取意图               |
| 服务站正式资源页   | 按确定的领取规则保存成果，进入正常使用             |

官网实际域名、托管方式和卡片 URL 格式尚未确定。入口中不携带模型密钥、用户账号或文档正文。

手机系统显示的 NFC 通知与网页入口是两个层次。品牌入口设计从用户按系统提示打开网页后开始，不假设网页能定制系统感应通知。

#### 未激活卡片的首屏

首屏应让用户感到“这张卡准备了一件我能亲手完成的事”。推荐内容顺序如下：

| 位置       | 展示内容                                           | 交互                               |
| ---------- | -------------------------------------------------- | ---------------------------------- |
| 顶部       | LocalMind 品牌、云端体验标识、可公开显示的卡片编号 | 可查看简短体验说明                 |
| 主视觉     | 与实体卡一致的主题卡面或主题标题                   | 保持信息清楚，不依赖动画才能进入   |
| 标题       | **你的 LocalMind 体验已准备好**                    | 无需先注册                         |
| 场景说明   | 例如“用一份项目材料，和 AI 一起完成发布方案”       | 能理解将得到什么成果               |
| 内容摘要   | 已准备的材料、将使用的一段对话和一份文档           | “看看准备了什么”展开只读材料       |
| 额度与期限 | 本卡真实可用的操作次数及有效规则                   | 配置未确定时不写具体承诺           |
| 主按钮     | **开始这张卡的体验**                               | 点击后激活本卡，进入对话与文档界面 |
| 次要入口   | 了解 LocalMind                                     | 跳转官网介绍，不占用主操作位置     |

建议首屏说明：**对话和文档会保留在这张卡的体验空间中，再次感应可继续查看。**

对于云端体验，应说明提交的内容由本体验服务及配置的 AI 模型处理。官网的本地优先定位不等于这次云端体验在手机本地执行；默认使用虚构示例，实际数据处理与保留规则需与实现一致。

页面打开、卡片校验和查看预置材料不应触发付费模型调用。激活后可先展示固定欢迎语，由用户明确点击任务按钮再执行模型任务。

#### 进行中与再次访问

再次碰卡后，不重复展示完整欢迎介绍。入口卡展示场景标题、上次进展、剩余额度和最近成果摘要，主按钮变为 **继续这张卡的体验**。

进入后恢复同一段对话与同一份文档。手机采用“对话／文档”切换，桌面可采用两栏；这只是显示布局，不拆分为两个独立体验。

正在执行任务时展示真实状态。多个设备打开同一张卡时共享进展，同一卡片同时只允许一个修改任务，避免覆盖和重复扣额。

#### 其他入口状态

| 状态         | 入口内容                         | 主操作与处理                                   |
| ------------ | -------------------------------- | ---------------------------------------------- |
| 正在校验     | 简短加载状态                     | 校验完成后再展示内容，不短暂显示他卡数据       |
| 额度用完     | 本卡体验已完成，展示可访问的成果 | 查看成果；按领取方案引导注册                   |
| 暂时失败     | 保留原成果，说明请求未完成       | 重试原任务，不新建另一份对话或文档             |
| 领取处理中   | 正在确认账号与保存结果           | 防止重复领取，失败后可恢复                     |
| 已领取       | 本卡成果已归入账号               | 要求本人登录；不向匿名访问者展示账号或成果摘要 |
| 已过期或停用 | 清楚的状态与可访问范围说明       | 按保留政策查看结果，或前往官网；不自动重置卡片 |
| 卡片无效     | 无法识别这张体验卡               | 提供重新感应或扫码提示及官网入口               |
| 网络不可用   | 网络提示                         | 支持重试，不消耗体验额度                       |

“已领取”相关行为属于下文“注册领取与内容归属建议”的方案，尚待确认。活动结束、额度耗尽和内容清除应作为不同状态处理，不混用一个“已失效”提示。

### 1.4 体验内容与展示效果

#### 建议的第一套场景

**项目发布体验：把预置材料整理成一份可继续编辑的发布方案。**

用户接到一份虚构项目背景，材料包含现有进展、用户反馈和待解决的问题。建议通过三步展示能力：

| 操作           | 页面引导                         | 应展示的真实能力                                     |
| -------------- | -------------------------------- | ---------------------------------------------------- |
| 生成第一份成果 | “根据这些材料，帮我整理发布方案” | 读取限定材料、保留事实来源、创建实际成果文档         |
| 按要求调整     | “重点讲风险”或由用户输入一句要求 | 理解当前上下文，修改同一份文档并展示变化             |
| 继续推进       | “补上接下来的行动”               | 在现有成果中形成行动清单，未知负责人和日期标为待确认 |

预定义提示词负责角色、步骤、内容结构和输出质量；高质量示例与明确的推荐操作降低用户上手难度。生成结果仍应对应用户真实选择，不用预制动画或示例冒充实际执行。

修改失败时保留上一版。聊天中“完成了”的回答不等于文档已保存，必须以实际文档状态反馈结果。查看来源、阅读成果和切换版本不额外调用模型。

#### 能力和预算建议

首版建议每卡开放一次生成、两次修改，再配置总 token 或成本上限。具体次数、输入长度、超时、保留期限和总预算需要实测后确定。

所有额度由服务端按卡片记录。刷新、换手机和复制链接不重置额度；失败重试沿用原任务身份并受重试预算约束。除单卡额度外，还需活动级并发、每日预算及总预算。

可开放范围限定为本卡预置材料、本卡对话和本卡文档。提示词不承担权限检查职责；服务端必须校验每次访问和写入范围。首版不开放任意内部资源搜索、业务 Project Memory、外部发送、成员管理或任意 MCP 调用。

### 1.5 注册领取与内容归属建议

领取入口建议使用文案：

> 把这张卡里的成果，带进你的 LocalMind。
>
> 注册或登录后，保存这份文档并继续工作。

建议流程：用户选择领取成果 → 在服务站完成身份验证 → 明确保存位置与内容范围 → 保存成功后打开正式资源。是否同时带走对话，需要根据正式会话绑定能力和用户选择确定。

建议每张卡只允许一个账号领取。领取成功后关闭卡片入口对原体验内容的匿名读取，之后只有本人登录才能访问已领取成果；领取失败不应提前销毁卡片内容。并发领取、重复回跳和重试必须能准确确认同一结果。

这些规则尚未全部确认，不能提前宣传“注册即拥有无限 AI 使用权”。注册后模型可用性、额度及后续卡片用途需另行决定。

未领取前，同卡持有者进入同一个空间。普通静态卡片链接也可能被复制，因此要明确共享访问规则，优先使用预置示例和非敏感内容。不得仅凭展示编号或可枚举 ID 访问卡片内容。

### 1.6 待讨论与设计交付

| 事项           | 已知方向                           | 下一步要确定的内容                                 |
| -------------- | ---------------------------------- | -------------------------------------------------- |
| 发放方式       | 以每张卡对应一个游客体验空间为基础 | 是否一人一张；是否允许转交或多人共同体验           |
| 卡片实体       | 品牌、主题、感应区与二维码         | 材质、尺寸、正反面视觉、打样与成本                 |
| 刷卡入口       | 未激活与继续体验有不同页面状态     | 首屏视觉、状态反馈、手机可点击原型                 |
| 体验场景       | 预定义提示词提高展示效果           | 首个场景、预置材料、三步引导与评价标准             |
| 服务接入       | 宣传官网与云端服务地址分离         | 官网域名、稳定卡片入口和服务站路由                 |
| 文档形态       | 一张卡对应一份可编辑成果           | BlockSuite、原生 Docs 或其他明确资源类型           |
| 额度与生命周期 | 跟卡片走，重复访问不重置           | 次数、期限、预算、到期读取与清理规则               |
| 注册领取       | 建议将成果归入账号并关闭匿名访问   | 是否领取、领取对象、对话保留、转交与领取后卡片用途 |

后续设计交付包括实体卡正反面稿、感应后入口页、各状态页面、对话与文档体验页、注册领取衔接，以及对应的测试与打样记录。当前仅记录设计内容，不把这些交付物标记为完成。

## Idea 2：LocalMind 四键键盘

**用「叫我、记住、再想想、成稿」四颗实体按键，连接进入对话、提供材料、推进思考和留下成果四个动作。**

用户希望制作 LocalMind 专属键盘作为周边发放；当前已有 USB 连接的键盘，提供四个可用按键。以下记录讨论中的交互方案，具体键值、固件能力及 LocalMind 软件接入尚待确认。

### 2.1 产品定位

四颗键可以串起一次完整的现场体验，也可以作为用户日常操作 LocalMind 的快捷入口。首版围绕现有四键设计，使用单击触发，每颗键固定一个含义。

体验路径：**叫我 → 记住材料 → 再想想 → 成稿。** 日常使用时可按需要独立操作，不强制每次完成四步。

### 2.2 四颗按键的玩法

| 按键     | 建议键帽       | 建议交互                                                     | 结果反馈                                           |
| -------- | -------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| ① 叫我   | LocalMind 标志 | 呼出 LocalMind 小窗口，回到当前对话；再次按下收起            | 显示当前对话及所属工作区或项目，收起不结束任务     |
| ② 记住   | ＋             | 打开收集卡，预览用户已复制的文字，确认后作为材料加入当前对话 | 显示“这段材料已加入”，可查看本次加入的内容         |
| ③ 再想想 | ↻              | 围绕当前想法或方案，提出新角度、发现遗漏或给出替代方案       | 显示本轮思考角度与实际生成的建议                   |
| ④ 成稿   | 文档图标       | 把当前讨论整理成实际文档；已有成果时，预览对同一份文档的更新 | 保存成功后打开成果，反馈“文档已创建”或“文档已更新” |

“记住”在本方案中指将材料加入当前对话，不自动写入长期记忆或公开共享记忆。剪贴板读取由用户主动触发，并提供预览；未取得读取权限时可手动粘贴。

“成稿”应明确展示保存位置和资源类型；更新已有文档时，由用户查看修改后确认应用。重复操作沿用同一份成果，失败时保留原文档，不因重试创建同名副本。

### 2.3 「再想想」的趣味设计

这颗键作为四键方案的主要记忆点。建议提供三个清楚可见的思考角度：

1. **找遗漏**：检查当前想法缺了哪些条件、步骤或依据。
2. **换位思考**：站在实际使用者的角度，提出一个值得回答的问题。
3. **大胆替代**：给出一个不同的可行方案，说明它适合什么条件。

默认可按以上顺序轮换，用户也能在屏幕上直接选择。本轮采用的角度始终可见；每次只发起一轮任务，结果返回后再继续。建议保留在当前对话中，不直接覆盖已有文档，由用户决定哪些内容进入成果。

### 2.4 首次体验示例

以“策划一次 LocalMind 线下活动”为例：

1. 按 **叫我**，输入：“我想做一个让人记住 LocalMind 的活动。”
2. 复制活动场地、人数和预算，按 **记住**，预览并将材料加入对话。
3. 按 **再想想**，围绕活动目标获得一个新的思考角度。例如，引导参与者现场带走一份自己完成的作品。
4. 讨论满意后按 **成稿**，确定保存位置，得到一份可编辑的活动方案。

示例用于解释操作方式；实际建议与文档由当前材料和用户选择生成，不用固定答案冒充 AI 执行结果。

### 2.5 屏幕反馈与周边设计

- **四颗虚拟键**：软件中显示对应按钮，实体按下时同步反馈；未连接键盘时也能通过点击使用。
- **简短结果提示**：例如“这段材料已加入”“这次从用户角度想想”“文档已更新”，与实际任务及保存状态一致。
- **四步体验卡**：包装或首次引导中展示四个动作，帮助用户完成第一份成果。
- **键帽识别**：使用品牌标志、加号、循环箭头和文档图标，可配文字说明；具体配色、布局及印制方式待设计。

没有材料或对话内容时，引导用户先输入；任务执行中显示进展并防止重复触发。失败时保留输入和已有成果，给出可恢复的操作，不显示成功反馈。

### 2.6 接入边界与待确认事项

首版建议先完成四个单击动作。长按、双击、组合键及额外硬件能力暂不纳入本条目的首版范围。

| 事项     | 下一步需要确认的内容                                                                        |
| -------- | ------------------------------------------------------------------------------------------- |
| 四键识别 | 每颗键向电脑发送的键值或事件、能否改键，以及能否与普通打字键盘区分                          |
| 软件接入 | 首先支持 LocalMind 网页内操作，还是配套桌面端的全局呼出；后台唤起与剪贴板访问按所选平台验证 |
| 对话绑定 | 如何选择或恢复当前对话，未登录或没有活动对话时如何引导                                      |
| 成稿行为 | 默认资源类型、保存位置、修改预览及同一份成果的持续更新方式                                  |
| AI 使用  | 使用当前会话的模型及额度策略；若做宣传演示，另行确定演示范围与预算                          |
| 实体交付 | 四键布局、键帽图案、外壳与包装、首次体验卡及真机测试                                        |

USB 连接和四个可用按键是当前硬件信息，不代表上述应用联动已可用。接入后应抑制按住重复事件及任务中的连按，避免重复执行或扣额。键盘操作继续使用当前账号、会话和资源权限，不自动套用 NFC 卡片的“一硬件一游客存储空间”规则。
