# LocalMind 用户使用指南

本指南面向使用 LocalMind 工作区、文档和 AI 功能的普通用户、团队成员及
工作区管理员。界面中的英文名称会保留，方便用户直接找到对应入口。

应用内可从左侧栏的 `Others > Help & guide` 打开可搜索的配套帮助页面。

> [!IMPORTANT]
> AI Chat 在读取工作区文档、引用文档或上传文件时，会为当前对话保存一份
> 内容快照。修改源文档后，已有对话不会自动拉取新版本。需要最新内容时，
> 当前对话会在检测到文档保存新版本后显示可关闭的提示。请点击提示中的
> `New Chat` 新建对话，并重新选择或引用该文档。关闭提示只隐藏当前保存
> 版本；文档再次保存后会重新提示。切换回另一个旧对话也不会更新它原来
> 保存的快照。

## 1. LocalMind 可以做什么

LocalMind 将文档、团队协作和 AI 上下文管理放在同一个工作区中。主要功能
包括：

- 创建和组织页面、白板及项目资料；
- 在 AI Chat 中引用工作区文档、标签、集合或上传文件；
- 使用长期 Rule 约束 AI 的回答方式；
- 让 Automatic Memory 保存当前用户的稳定偏好和决定；
- 用 Context Project 把一组文档组织成项目上下文；
- 为项目保存仅属于当前用户的 Project Summary；
- 在长对话中使用滚动摘要保留重要上下文；
- 按工作区文档权限过滤搜索和 AI 可见内容。

## 2. 使用前准备

### 2.1 登录和工作区

要使用完整的 AI 上下文功能，请确认：

1. 已登录 LocalMind 账号；
2. 当前服务器已启用 Copilot/AI 功能；
3. 当前工作区已经同步到服务器；
4. 左侧导航栏中能够看到 `AI Chat`；
5. `Workspace settings` 中能够看到 `AI context`。

本地未同步工作区可以管理个人 Rule，但 Automatic Memory、Context Project
和工作区级 AI 上下文需要先同步工作区。若 Automatic Memory 开关不可用，
先完成登录和工作区同步。

### 2.2 常用入口

| 功能          | 入口                                    |
| ------------- | --------------------------------------- |
| 全部文档      | 左侧导航栏 `All docs`                   |
| AI 对话       | 左侧导航栏 `AI Chat`                    |
| 新建 AI 对话  | AI Chat 顶部 `+`，悬停提示为 `New Chat` |
| 对话历史      | AI Chat 顶部历史图标 `Chat History`     |
| AI 上下文管理 | `Workspace settings > AI context`       |
| 团队成员      | `Workspace settings > Members`          |
| 工作区索引    | `Workspace settings > Embedding`        |

## 3. 五分钟快速开始

1. 打开一个已同步的工作区。
2. 在 `All docs` 中创建或打开文档，并补充需要 AI 使用的内容。
3. 点击左侧 `AI Chat`。
4. 点击输入框附近的 `+`，选择工作区文档、标签、集合，或上传
   PDF、TXT、CSV、DOC/DOCX、XLS/XLSX、PPT/PPTX、图片等文件。
5. 输入具体问题，例如：

   ```text
   根据我刚才选择的项目文档，总结本周已经完成的事项、风险和下一步。
   只引用文档中能够确认的信息。
   ```

6. 需要长期约束 AI 时，进入 `Workspace settings > AI context` 添加 Rule。
7. 需要自动积累个人偏好时，在同一页面开启 `Automatic memory`。
8. 修改已被对话读取的文档后，点击 `New Chat`，重新添加文档，再询问最新
   内容。

## 4. 使用工作区和文档

### 4.1 创建和组织文档

从 `All docs` 创建页面后，可以在页面模式中编写结构化内容，也可以切换到
白板模式组织自由布局内容。可使用标签和集合管理跨文档主题。

为了获得更好的 AI 结果：

- 标题应准确表达文档主题；
- 决策、负责人、截止日期和状态尽量使用明确字段；
- 同一事实只保留一个权威版本；
- 已失效内容应删除、归档或明确标注；
- 不要把密码、API Key、访问令牌或私钥写入文档或对话。

### 4.2 文档快照

每个 AI 对话都使用开始读取时的文档快照。这样可以保证历史回答可复现，
不会因为源文档后来被修改而悄悄改变旧对话的依据。

下面的操作不会刷新已有对话：

- 编辑源文档；
- 修改文档标题；
- 调整 Context Project 的文档列表；
- 关闭再重新打开同一个历史对话；
- 从历史记录切换到另一个旧对话。

要让 AI 使用最新文档：

1. 等待文档保存和同步完成；
2. 等待输入框上方出现文档更新提示；
3. 点击提示中的 `New Chat`；
4. 在新对话中重新选择、引用或上传该文档；
5. 明确要求 AI 基于最新文档回答。

提示右侧的关闭按钮只隐藏当前对话、当前文档保存版本的提醒，不会刷新
快照。文档再次保存后，新的版本签名会使提示重新出现。

### 4.3 导入 PDF 和 Office 文件

打开工作区的 `Import` 对话框时，`.docx`、`.xlsx`、`.pptx` 和 `.pdf` 的主选项
会创建 LocalMind 原生 Office 资源，并直接打开对应的 Docs、Sheets、Slides 或
PDF 页面。原始文件证据和每次保存的版本都保存在不可变 Revision 中；编辑不会把
文件隐藏转换成普通 BlockSuite 页面。

原生页面支持按格式提供的编辑、预览、下载、打印、历史和比较能力。PDF 保持固定
版式，只允许批注、表单、页面操作、签名外观和涂黑等已支持修改；“重写正文”或
“重新排版”需要显式转换为 Docs，不能作为原 PDF 的普通编辑。

如果只需要提取内容到普通页面，请选择带有 `as BlockSuite page` 的显式转换项：

- `DOCX as BlockSuite page`：把正文转换为普通页面；
- `XLSX as BlockSuite page`：把工作表转换为页面表格；
- `PPTX as BlockSuite page`：把幻灯片文本和表格转换为页面内容；
- `PDF as BlockSuite page`：把文本层转换为标题和段落并保留分页分隔。

这类转换不会保留所有原格式能力。复杂排版、图表、宏、完整公式行为、主题、动画
和媒体可能丢失。管理员启用扫描版 PDF OCR 后，`PDF as BlockSuite page` 会把无
文本层页面经 LocalMind 后端发送到管理员配置的 OCR 服务；OCR 结果需要人工复核，
一次最多处理 100 个扫描页。旧版二进制 `.doc`、`.xls`、`.ppt` 目前不属于原生
可编辑格式。

## 5. 使用 AI Chat

### 5.1 开始和管理对话

- 点击左侧 `AI Chat` 进入独立对话页面；
- 点击顶部 `New Chat` 创建全新的对话；
- 使用 `Chat History` 查看并切换历史对话；
- 可以固定需要长期保留的对话；
- 一个对话尽量只处理一个持续主题。

新建对话不会删除长期 Rule、Automatic Memory 或 Project Summary。它只会
创建新的会话上下文和新的文档快照。

### 5.2 添加上下文

点击输入区旁的 `+` 可以添加：

- 当前工作区文档；
- 标签下的文档；
- 集合中的文档；
- PDF、TXT、CSV、DOC/DOCX、XLS/XLSX、PPT/PPTX 等文件；
- 图片。

优先只添加回答问题所必需的资料。添加大量无关文档会降低相关信息的占比，
并增加处理时间。

### 5.3 写出更可靠的问题

一个可执行的问题通常包含：

1. 任务：希望 AI 做什么；
2. 范围：使用哪些文档或项目；
3. 输出：需要表格、清单、摘要还是草稿；
4. 约束：不能猜测什么，必须保留什么；
5. 验证：要求指出依据或无法确认的信息。

示例：

```text
只根据“发布计划”和“风险清单”两份文档，整理下周发布检查表。
按负责人分组，保留原始日期；文档没有说明的内容标记为“待确认”，不要补写。
```

### 5.4 在原生 Office 页面中使用 AI

在 Docs、Sheets、Slides 或 PDF 页面点击 AI 按钮，打开现有 LocalMind AI Chat。
发送请求时，系统会自动附加当前文件、Revision 和提交瞬间的稳定选择区；顶部
chip 会显示这些上下文，选择区可以单独清除。

Office 写操作需要工作区中有效的 BYOK 模型配置。AI 会先读取当前 Revision，再
提交结构化单命令或原子批量命令。预览出现后可以选择 `Approve`、`Reject` 或
`Cancel`：批准前不会创建 Office Revision，拒绝、取消、权限变化、版本冲突或
预览漂移也不会修改文件。只有 worker 完成并返回新的不可变 Revision 后，页面才
会自动刷新；仍存在的选择区会恢复，已删除的目标会被清除并显示提示。

PDF 页面中的 AI 同样遵守固定版式边界，不会直接重写 PDF 正文。未配置 BYOK 时，
请求会明确提示需要管理员配置，不会回退到平台额度模型。

### 5.5 长对话

LocalMind 会保留最近消息，并为较早内容建立滚动摘要。滚动摘要属于当前
对话，不是长期记忆，也不会显示在个人 Memory 列表中。

出现以下情况时建议新建对话：

- 目标已经改变；
- 需要读取修改后的文档；
- 旧对话中存在大量已经失效的假设；
- 需要用干净上下文验证 Rule 或 Memory；
- 对话中的资料属于不同项目。

## 6. AI Context 的四类信息

| 类型             | 用途                             | 是否长期保存 | 用户能否管理               |
| ---------------- | -------------------------------- | ------------ | -------------------------- |
| Rule             | 明确约束回答风格、格式或工作方式 | 是           | 可以创建、编辑、停用、删除 |
| Automatic Memory | 从对话中识别稳定偏好和决定       | 是           | 可以查看、编辑、停用、删除 |
| Project Summary  | 当前用户为项目保存的稳定背景     | 是           | 可以创建、编辑、停用、删除 |
| Rolling Summary  | 压缩当前长对话中较早的内容       | 仅属于该对话 | 不在 Memory 列表中管理     |

所有 Rule、Automatic Memory 和 Project Summary 都属于当前用户本人。将作用
范围设为团队或项目，只决定这条个人记忆在哪里可以使用，不会把它共享给
其他成员。

## 7. 使用 Rule

### 7.1 创建 Rule

1. 打开 `Workspace settings > AI context`。
2. 在 `Your rules and memories` 中选择 `Rule`。
3. 选择作用范围：
   - `Every workspace`：跟随当前用户，在所有工作区生效；
   - `This team`：只在当前工作区生效；
   - `Project`：只在选定 Context Project 中生效。
4. 输入 Rule。
5. 点击 `+` 添加。

适合保存为 Rule 的内容：

```text
回答项目进度时，按“完成、风险、下一步”三个部分输出。
```

```text
所有日期使用 YYYY-MM-DD 格式。
```

```text
不确定的信息必须标记为“待确认”，不要自行补全。
```

不要把临时问题、一次性任务或敏感凭据保存为 Rule。

### 7.2 编辑、停用和删除

在 Memory 列表中：

- 直接编辑文本后点击保存图标；
- 使用开关临时停用或重新启用；
- 使用删除图标永久删除；
- 使用 `Rules`、`Automatic`、`Summaries` 标签筛选；
- 使用搜索框按内容、范围、类型或项目名称查找。

停用只会阻止后续注入，不会删除内容。删除后无法通过界面恢复。

## 8. 使用 Automatic Memory

### 8.1 开启

1. 确认已经登录并使用已同步工作区；
2. 打开 `Workspace settings > AI context`；
3. 在 `Ownership and scope` 中开启 `Automatic memory`。

该设置按“当前用户 + 当前工作区”保存。关闭后不会再创建新的自动记忆，但
已经保存的记忆仍会保留并继续显示，用户可以逐条停用或删除。

### 8.2 适合记住的内容

Automatic Memory 主要用于稳定、可长期复用的偏好和决定，例如：

```text
记住：我更喜欢先看结论，再看详细依据。
```

```text
我们决定项目状态报告统一使用红黄绿风险等级。
```

```text
The deployment codename is ORCHID_FACT.
```

单纯提问通常不应被保存。例如“部署代号是什么？”只是问题，不是新的长期
事实。

### 8.3 检查保存结果

完成包含稳定偏好或决定的对话后：

1. 打开 `Workspace settings > AI context`；
2. 选择 `Automatic`；
3. 检查是否出现正确内容和作用范围；
4. 必要时编辑、停用或删除；
5. 点击 `New Chat`，在新对话中询问相关内容，验证是否能够正确召回。

Automatic Memory 不应被当作秘密保险箱。即使系统会过滤常见凭据格式，也
不要在对话中输入密码、API Key、Token、私钥或客户敏感数据。

## 9. 使用 Context Project

Context Project 将一组工作区文档组织成同一个 AI 上下文边界。项目本身属于
工作区，项目中的 Rule、Automatic Memory 和 Project Summary 仍分别属于创建
它们的用户。

### 9.1 创建项目

只有工作区 Owner 或 Admin 可以管理 Context Project：

1. 打开 `Workspace settings > AI context`；
2. 在 `Context projects` 输入项目名称和说明；
3. 点击 `Select documents`；
4. 选择 1 到 100 个文档；
5. 点击创建图标。

普通成员只能看到包含其有权读取文档的项目，不能修改项目配置。

### 9.2 修改、归档和删除

Owner 或 Admin 可以：

- 修改项目名称和说明；
- 调整项目包含的文档；
- 使用开关将项目归档或重新启用；
- 删除已经归档且没有个人记忆引用的项目。

归档会停止项目上下文的后续注入，但不会删除用户的私人项目记忆。如果删除
失败，请先保持项目归档，并由各记忆所有者删除自己关联的项目记忆。

### 9.3 添加 Project Summary

1. 在 `Your rules and memories` 中选择 `Project summary`；
2. 选择 `Project`；
3. 选择目标项目；
4. 输入简短、稳定、可复用的项目背景；
5. 点击 `+` 添加。

推荐写法：

```text
本项目目标是将客户知识库迁移到 LocalMind。当前阶段为试运行，
正式切换前必须完成权限抽查和恢复演练。
```

Project Summary 适合记录稳定背景，不适合复制每天变化的完整进度日志。

## 10. 团队和权限

### 10.1 管理成员

在 `Workspace settings > Members` 中邀请和管理成员。工作区 Owner/Admin
负责成员管理及 Context Project 配置。

### 10.2 AI 可见范围

LocalMind 在搜索排序前先检查文档权限：

- 用户只能检索和使用自己有权读取的文档；
- 无权限文档不会因为相关度较高而进入 AI 上下文；
- 普通成员不能通过 Context Project 绕过原有文档权限；
- 每个用户只能管理和使用自己的 Rule 与 Memory；
- 团队成员之间不会自动共享私人 Memory。

不要使用个人 Rule 或 Memory 代替团队制度。需要所有成员共同遵守的要求，
应写入团队可访问的权威文档，并通过正常权限管理。

## 11. 工作区索引和搜索

已同步工作区可以在 `Workspace settings > Embedding` 管理语义索引：

- 开启或关闭 Workspace Embedding；
- 查看索引进度；
- 上传额外文件；
- 选择不参与索引的文档。

刚创建或刚同步的文档可能需要等待索引完成。遇到搜索结果为空时，依次检查：

1. 自己是否拥有文档读取权限；
2. Workspace Embedding 是否已开启；
3. 索引是否仍在处理中；
4. 文档是否被加入忽略列表；
5. 当前对话是否实际选择了相关文档或项目；
6. 查询是否过于宽泛。

## 12. 推荐工作流

### 12.1 建立个人工作习惯

1. 添加少量明确的个人 Rule；
2. 开启 Automatic Memory；
3. 定期在 `Automatic` 标签中检查记忆；
4. 停用过时内容，删除错误内容；
5. 用新对话验证关键偏好。

### 12.2 开始团队项目

1. Owner/Admin 创建 Context Project；
2. 选择权威项目文档；
3. 成员分别添加自己的 Project Summary 或项目 Rule；
4. 从项目文档进入 AI Chat 或在对话中选择对应文档；
5. 项目结束后归档 Context Project。

### 12.3 文档更新后重新分析

1. 修改并保存源文档；
2. 等待同步和索引完成；
3. 等待原对话输入框上方出现更新提示；
4. 不要继续使用原来的对话；
5. 点击提示中的 `New Chat`；
6. 重新选择更新后的文档；
7. 要求 AI 指出最新版本中的变化。

### 12.4 验证权限隔离

1. Owner 创建包含受限文档的 Context Project；
2. 邀请普通成员加入工作区；
3. 仅授予该成员必要的文档权限；
4. 成员从 AI Chat 搜索项目内容；
5. 确认只能看到已授权资料；
6. 分别创建个人 Memory，确认成员之间不能互相查看或召回。

## 13. 使用提示

- 一个对话处理一个主题，目标变化时使用 `New Chat`；
- 文档一旦修改，要读取新版就必须新建对话并重新添加文档；
- Rule 应短、明确、可执行，避免互相矛盾；
- Project Summary 只保留稳定背景，不复制频繁变化的流水账；
- 每隔一段时间检查 Automatic Memory，及时清理错误或过期内容；
- 提问时明确资料范围、输出格式和“不允许猜测”的边界；
- 优先选择少量权威文档，不要一次加入大量无关资料；
- 不要在文档、Rule、Memory 或对话中输入密码和密钥；
- 项目结束后先归档，确认不再需要后再删除；
- 重要结果应回写到权威文档，不要只留在聊天记录中。

更多可直接分享给用户的简明提示见
[LocalMind 使用提示](./localmind-usage-tips.zh-CN.md)。

## 14. 常见问题

### Automatic Memory 为什么无法开启？

确认已经登录，当前工作区已经同步，并且服务器启用了 Copilot。LocalMind
本地未同步工作区会禁用 Automatic Memory。

### AI context 为什么没有显示？

`AI context` 只在服务器提供 Copilot 功能时显示。请检查服务器连接、AI
功能配置和当前登录状态。

### 修改文档后，AI 为什么仍然引用旧内容？

这是文档快照机制的预期行为。已有对话不会自动刷新源文档。文档保存后，
系统会在原对话输入框上方显示更新提示。点击提示中的 `New Chat`，然后重新
选择或引用更新后的文档。提示可以关闭；同一版本保持隐藏，文档再次保存后
会重新出现。切换到另一个旧对话也不会刷新旧快照。

### Automatic Memory 已开启，但没有保存某句话？

系统只尝试保存明确、稳定的偏好和决定，不会把每句话或普通问题都保存。
可使用“记住：……”或“我们决定……”表达长期信息，然后在 `Automatic`
标签中检查。

### 关闭 Automatic Memory 后，旧记忆为什么还在？

关闭开关只停止创建新记忆，不会删除已有内容。请在 Memory 列表中逐条停用
或删除旧记忆。

### 为什么普通成员不能创建 Context Project？

Context Project 会改变工作区级文档分组，因此只有 Owner/Admin 可以管理。
普通成员仍可使用自己有权访问的项目和自己的私人 Memory。

### 为什么 Context Project 无法删除？

项目必须先归档，而且不能仍被任何用户的私人项目记忆引用。请保留归档状态，
并让相关用户删除自己的项目 Memory 后再删除项目。

### 为什么搜索不到已存在的文档？

检查读取权限、Embedding 开关、索引进度、忽略列表和查询范围。权限过滤发生
在相关度排序之前，无权限文档不会出现在结果中。

### 修改 Rule 或 Memory 后如何验证？

保存修改并确认它处于启用状态，然后使用 `New Chat` 创建干净的新对话进行
验证，避免旧对话内容干扰判断。

## 15. 数据管理说明

- Rule、Automatic Memory 和 Project Summary 由创建它们的用户拥有；
- 用户可以查看、编辑、停用或删除自己的 Memory；
- 退出某工作区后，Memory 不会在该工作区继续注入；
- 删除账号时，该用户的 Memory 会随账号清理；
- 删除文档会移除文档专属 Memory 和项目成员关系；
- 项目级 Memory 可能仍会保留，因为它可能总结项目中的其他文档；
- 禁用 Memory 不等于删除；
- 清除聊天记录不等于删除长期 Memory。

## 16. 术语

| 术语             | 含义                                               |
| ---------------- | -------------------------------------------------- |
| AI Chat          | LocalMind 的独立 AI 对话界面                       |
| New Chat         | 创建全新会话和新文档快照                           |
| Rule             | 用户明确维护的长期 AI 约束                         |
| Automatic Memory | 从对话中自动识别并保存的用户长期信息               |
| Project Summary  | 当前用户为 Context Project 保存的背景摘要          |
| Context Project  | 将多个工作区文档组织为项目上下文的工作区对象       |
| Rolling Summary  | 当前长对话中较早内容的压缩摘要                     |
| Scope            | 一条私人 Memory 可以在哪些工作区、文档或项目中使用 |
| Embedding        | 用于工作区语义检索的文档向量索引                   |
| Snapshot         | 某个对话读取资料时保存的内容版本                   |
