## 1. 决策与契约边界

1. 关系图使用独立的 React + SVG 只读组件，右侧工单清单使用现有 HTML/UI 组件。
   复用 LocalMind 的 GraphQL、权限、主题 token、i18n 和路由，不为关系图扩展
   BlockSuite Surface/YDoc 格式，也不创建第二份持久关系数据。BlockSuite 继续负责真正
   的 Page/Edgeless 编辑。当前 `CollaborationGfxCanvas` 的临时 GFX 宿主由新视图替换。
2. 图、右侧清单和会话协作角色均从工单、交付要求与回执确定性投影；Agent 只负责
   形成待用户确认的结构化工单，不根据聊天频率或自由文本临时造边。修改关系仍在
   会话或工单内进行；图只提供查看、有限视角缩放/平移和工单定位。
3. 未发送关系只投影**当前有效、属于当前登录用户**的 `WorkOrderDispatch` 草稿。
   `status = draft`、`expiresAt > 服务端当前时间`、来源会话仍由本人持有且可读时，
   每个草稿收件人形成一条「待确认·尚未发送」关系；过期、确认、来源不可读后移出。
   草稿不会出现在收件人视图，不产生接单会话、通知或交付义务。当前 30 分钟确认
   窗口保持不变；本专项不新增长期保存的协作计划。
4. 「已交付·已纳入上下文」只在对应来源会话的持久
   `WorkOrderAdoption` / `WorkOrderAdoptionItem` 确实采用了**当前展示的交付版本**时
   显示。仅有 `WorkOrder.status = delivered`、查看回执、历史上采用过旧版或别的来源
   会话采用过，都不满足。双方参与者可看到这个有界状态，不获得 adoption 记录、
   私人会话正文、来源项目文件或其他参与者工单。
5. 图上箭头表示**交付方向：工单接单人 → 发单人**，指向交付接收人。这与参考 v9
   SVG 的实际方向一致，覆盖旧设计 D13 中「发单人 → 接单人」的画法；文字仍分别
   标明发单人、接单人与「向我交付／接收我的交付」，避免把派单与交付混为一谈。
6. 本专项覆盖旧 v9 方案的「优先复用 BlockSuite GFX」和旧 Goal 的 GFX 宿主要求；
   其余个人工单授权、不可变交付版本、Project 资源与独立副本、会话隔离、审计和
   Docker 规则继续有效。不得修改旧执行记录的既有通过结论，也不得宣称本专项已上线。

## 3. 数据契约和权限

### 3.1 关系投影

在现有 `myCollaborationGraph` 上演进类型化字段，不建并行的前端数据源。每条关系
至少有稳定 `id`、`kind`（已发送工单／待确认草稿）、现有 `from`（发单人）与 `to`
（接单人）、来源分组、标题、按原顺序排列的必交付项标题、
文件/文字类型、展示状态、最近业务时间、本人导航目标及草稿 `expiresAt`。节点姓名来自当前允许展示的
账号资料；草稿 ID 使用 dispatch ID 加收件人序号，避免同一批次的多张草稿互相合并。
现有 GraphQL `from/to` 的派单语义保持兼容，SVG 在视图模型中计算
`deliveryFrom = to`、`deliveryTo = from`；`project-context-panel.tsx` 等消费者不得
因画法调整而悄然反转其文字。
标题和交付项保持已有长度/数量界限；不返回草稿确认 token、`draft` 原始 JSON、
要求说明全文、私人消息或文件正文。GraphQL schema、operation 和生成类型同步更新。

服务端只以登录用户为 actor：已发送工单要求 `senderId = actor OR recipientId = actor`；
草稿要求 `senderId = actor`、状态与有效期同时匹配，并重新检查来源会话所有权、
未删除和当前打开权限。接单人只有确认发送后才能看到自己的工单。历史工单的来源
项目名可沿用发送时冻结的 snapshot；项目名不会授予项目成员权限。查询上限与
`truncated` 必须覆盖已发送和草稿合并后的实际返回范围，排序稳定；检查
`senderId/status/expiresAt` 与 adoption 批量查询的索引/查询计划，确需索引时新增
Prisma 迁移，不只改 schema。

草稿过期以服务端时间判定。客户端收到 `expiresAt` 后安排最近一次到期移除与重新
查询，页面重新聚焦、重连和既有用户作用域工单事件也重新对账；断网时不得把已过期
草稿继续当成有效关系。确认发送的同批草稿与真实工单用稳定身份去重，不短暂显示
两套待办。

### 3.2 状态与交付版本

| 事实                                          | 显示                                       | 约束                                                                                        |
| --------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 有效且本人拥有的 dispatch 草稿                | 待确认·尚未发送                            | 仅发单方可见；图上定位工单，清单会话按钮进入本人来源，不从图直接确认发送                    |
| `open`                                        | 发单方「等待对方交付」；接单方「待我交付」 | 按交付方向区分，双方看到同一条工单                                                          |
| `waiting_sender`                              | 追问中·等待发起人答复                      | 不能误写为已交付                                                                            |
| `validating`                                  | 验收中                                     | 保留后端真实中间态，不用 v9 的已交付标签掩盖                                                |
| `delivered`，当前交付版本未被来源会话采用     | 已交付                                     | 已交付事实与采用事实分开                                                                    |
| `delivered`，当前交付版本已被对应来源会话采用 | 已交付·已纳入上下文                        | 按 `deliveryRevisionId` 匹配 `WorkOrderAdoptionItem` 和来源会话；历史旧版采用不提升新版状态 |
| `refused` / `cancelled`                       | 已拒绝／已取消及可操作的既有详情入口       | 弱化颜色与明确文字，不计作成功交付，不虚构采用                                              |

状态判断在服务端用持久事实一次性生成有界布尔值/枚举，前端只做本地化文案和颜色映射。
展示最新版本时若 v1 已采用、v2 已交付但未采用，图仍显示「已交付」；
历史 v1 采用记录继续在工单详情可查。用户不可仅从图修改状态。

### 3.3 导航

图上点击只定位相关工单；清单右上角的会话按钮调用服务端打开/创建动作。接单方进入自己的工单会话；发单方优先进入
本人可读的来源会话。对 Project 来源使用项目会话路径；对 Workspace 来源验证其
实际可用的原会话路径；会话缺失时按第 4.1 节补建，失权时明确报错。草稿只导航本人来源会话。服务端只返回当前 actor
的目标，不下发对方私人 session ID；路由本身继续实时校验授权。删除、失效或
不可达目标显示可恢复提示，不猜测另一个用户的会话。

## 4. 图、清单和交互（2026-09-28 已确认修订）

本节按用户确认的有限协作图替代旧的项目分组、无限画布及图上直接进入会话；
有限内容范围内允许缩放和视角平移。
箭头仍为成果交付方向：接单人 → 发单人；GraphQL `from/to` 的派单语义不变。

1. 全部来源合并为一张有限图，全图只有一个「我」。协作者按「用户 ID + 成果交付方向」
   分组：左侧为对方交付给我，右侧为我交付给对方。同一用户有双向交付时可分别出现在
   左右两侧，两处共享真实用户身份但使用独立分组 key；同方向跨项目合并。人数按用户
   ID 去重，左右分别统计分组数，工单按 ID 统计。项目保留为筛选和工单归属。
2. 默认每个方向分组与我之间一条实线，只显示该方向的箭头；独立的「N 张工单」按钮
   展开该组。每张工单以稳定 ID 对应唯一一个摘要框及一条虚线，框内使用整单任务标题。
   文件、文字等具体要求只在右侧工单展示，不能拆成多个图上摘要。各组独立展开、收起，
   不隐藏其他协作者；提供「全部收起」。图中移除协作者分页和工单分页。
3. 布局是与视窗尺寸、缩放比例无关的有限世界坐标。每组根据展开工单数计算高度，
   左右分别纵向排列并整体居中；「我」在完整图的垂直中点，协作者在各自分组的中点。
   只有一个协作者时，不论单向还是双向、不论两侧工单数是否相等，人物都垂直对齐。
   左 7 人、右 8 人时各侧独立排列，不强行逐行配对。单侧采用人物—摘要—人物三列，
   双侧采用人物—摘要—我—摘要—人物五列，预留可读宽度。初次展示按宽度适配，
   窄窗口可放大后通过平移查看局部。
   顶部提供左右方向定位入口，按当前比例平移至相应一侧。「展开视图」增加图的可视
   高度，并在桌面收起项目导航，与图的缩放比例分开。
4. 人物、摘要和 SVG 连线使用同一套世界坐标、同一个视角变换，不能单独拖动或编辑。
   摘要框左右中点水平进出，两侧连接占据相同宽度；框内只显示整张工单任务摘要，
   最多两行，人物、项目、状态及完整要求放在节点或相关工单。
   缩放锚点固定为关系图可视区域中心，不跟随鼠标，不包含右侧工单面板；边界约束
   优先防止图被移入无限空白。缩放操作最大 200%，最小为 50% 与全图适配比例中的较小值；
   后续尺寸变化即使提高了缩小下限，也保留已有适配比例，平移和选中不隐式放大。
   内容比视窗小时居中，较大时限制在有限边缘。拖动空白区域或按住空格拖动任意位置
   只平移视角，滚轮/双指滑动平移，Ctrl/⌘ + 滚轮缩放；触屏单指平移、双指缩放。
   拖动与轻点通过位移阈值区分，取消手势和窗口失焦释放拖动状态。
   人物不再固定在可视区域，放大局部时可移出视窗。固定工具栏提供缩放、100% 复位、
   「查看全图」和「定位选中」；键盘方向键平移，加减键缩放，Home 查看全图。
5. 点击摘要打开相关工单，滚动、聚焦并持续高亮整张工单，不导航到会话。
   点击人物筛选该用户在该方向的工单；点击工单主体或其中任一要求，左侧均定位并高亮该工单
   唯一的摘要框和连线。定位时保留当前比例，摘要已可见则不移动，否则仅平移至可见；
   单个协作者手动展开时视角对准内容中点，多协作者展开时尽量保持操作对象的屏幕位置；
   普通数据刷新和视窗尺寸变化不重置比例。右侧仍可精确选中要求，但不会额外生成图上文字框。
   再次选择不会取消选中；「展开/收起说明」独立于
   选择状态。图上选择会清除右侧不兼容的状态筛选，右侧选择会展开并定位被收起或
   搜索隐藏的对应方向分组。工单右上角独立「打开对话」或「新建对话」按钮才执行会话
   导航。列表按状态、任务标题、成果方向与项目、文件/文字要求短标题排列，要求默认
   可见，提供全部/待我交付/待对方交付/已结束筛选；未确认草稿只在全部中显示。
   已发送工单的详细说明按需通过已有参与者授权的 `myWorkOrder` 查询读取，不放入
   关系图批量投影。草稿继续通过本人原会话查看完整要求。桌面关系视图提供「展开工作区」，临时收起项目
   导航并将关系图、工单列表排为独立两列；「恢复项目导航」保留原导航宽度和图的
   展开状态。切回条目、进入项目/会话或切到手机宽度时退出展开工作区。手机（≤760px）
   继续使用可关闭的右侧工单抽屉，不再移到图下方。验证见
   `.codex-artifacts/project-graph-workspace/REPORT.md`；长图、双向联动和列表完整修订见
   `.codex-artifacts/project-graph-complete/REPORT.md`。后续「一张工单一个摘要」修订覆盖前述
   历史报告的逐交付项展开行为，验证见 `.codex-artifacts/project-order-summaries/REPORT.md`。
   有限画布缩放和平移覆盖历史报告的固定人物/独立摘要滚动行为，验证见
   `.codex-artifacts/project-graph-camera/REPORT.md`。方向分组、多组展开和内容居中覆盖历史报告
   中的同一协作者只出现一次、人员分页和按视窗高度定位行为，验证见
   `.codex-artifacts/project-graph-directions/REPORT.md`。
6. 实线/虚线只表达汇总/展开层级；草稿、取消、拒绝、交付和采用等业务状态由工单
   文字明确显示，颜色不单独承担状态语义。保留草稿仅本人可见、到期移除、重连对账、
   版本精确的采用状态及 500 条截断提示。
7. 使用原生 HTML 按钮与输入承载交互，SVG 只负责几何连线。保留键盘焦点、回车、
   错误重试、防重复提交及窄屏关闭工单面板后的焦点恢复。

### 4.1 会话缺失时的创建与审计

- `openWorkOrderConversation` 仅接受工单参与者，服务端重新判断当前用户的导航目标。
  接单人进入本人工单会话，发单人优先进入自己的有效原始来源会话。
- 接单会话缺失或已删除时创建新的私人 `work_order` 会话并更新原生会话绑定。
  已结束工单的新会话仍保存完成原因和完成请求标识，不重新打开工单。
- 发单人缺失来源会话时，在仍有权限的原 Project/Workspace 范围创建后续会话。
  创建在工单行锁和事务中完成，追加不可变 `conversation_created` 事件（actor、
  sessionId、role、version、fingerprint）；重试从本人事件定位现存会话。
  不覆盖 `sourceSessionId`、派单快照或历史 adoption，也不复活或复制已删除聊天。
- Project 重新检查有效成员，Workspace 文档入口由 `PermissionAccess` 检查实时
  `Doc.Read`，模型同时检查有效 Workspace 成员。来源资源已失权或无法确定合法
  创建范围时明确报错，不选择其他项目或对方会话作为兜底。
- 本修订复用既有会话、绑定和不可变工单事件，无新增 Prisma 表或迁移。
