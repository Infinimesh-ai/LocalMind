# Project v9 工作台适配实施方案

日期：2026-09-22。版本：1.0。状态：实施方案，尚未执行。

本方案将[设计讨论稿](project-workbench-v9-design.zh-CN.md)中已确认的决定（整理基线 v0.17），
适配到当前 LocalMind 工作树。配套执行入口是
[Project v9 Goal 指令](project-workbench-v9.goal.md)。生成这些文件不启动 Goal，
不代表后端、正式前端、迁移或运行环境已经完成改造。

## 1. 结论与适配原则

这不是将 HTML 复制进 React 的换皮任务，而是保留 LocalMind 原生能力、重组工作台
交互，并新增个人协作工单领域的跨层改造。

1. **保留底座**：独立 Project 壳、现有 AI Chat、原生文件树、Page/Edgeless、Office
   编辑器、共享 Project Memory、授权、审批、租约、通知和可恢复 Agent Runtime。
2. **重组入口**：个人三栏会话总览、左侧项目/会话树、复用聊天 UI 的新会话、右侧
   上下文/文件树/资源编辑区、只读协作关系图。
3. **新增业务**：一会话一卡的持久工作状态、个人独立工单会话、结构化交付要求、
   完整返回门禁、不可变回执、显式采用版本，以及补充/替代工单。
4. **不照搬模拟逻辑**：HTML 的 A/B/C、关键词生成固定工单、内存状态、附件占位、
   扩展名校验、静态编辑内容和身份切换均不进入生产。
5. **不破坏旧能力**：旧 `/tasks`、未结文件请求、来源复制审批、项目管理、发布/导入、
   回收站及现有 Workspace AI 不因新工作台上线而消失或扩权。

## 4. 实施默认建议与确认边界

以下为使方案可执行而提出的保守默认值，并非历史上已获用户逐条确认。使用配套 Goal
启动实施时可按这些默认值推进；若用户指定不同选择，以新决定为准并记录。涉及新的
数据共享、权限、破坏性迁移或范围扩大时，不得以本表代替明确授权。

| 编号 | 默认建议                                                                               | 约束/理由                                                                         |
| ---- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| E01  | `/project` 默认个人“条目”总览；直接访问 `/project/:projectId` 保留当前项目落地行为     | 左栏点击项目仅展开，不自动跳转；不另猜“恢复上次会话”                              |
| E02  | 新左栏成为 v9 会话主导航，不再重复显示横向会话 Tab；原 runtime tab 状态机制可复用      | 仅隐藏重复入口，不能丢失历史、草稿或切换能力                                      |
| E03  | 各列按最后业务活动降序、稳定 ID 次序；服务端分页，已完成可继续加载全部历史             | 不沿用最近七天作为全部已完成；计数与当前页数量分离                                |
| E04  | 草稿先按账号、服务端及 draft ID 隔离保存在本次页面生命周期内；不新增跨设备草稿同步     | 必须提示刷新未发送草稿可能丢失；已上传临时附件有 TTL 清理；不得在持久日志保存输入 |
| E05  | 标记完成时，如本人还有运行/审批/未答问题，也先提示处理；停止 Agent 是明确独立动作      | 不能用“完成会话”暗中取消运行或批准工具；查看消息不自动清除待处理                  |
| E06  | 待我行动优先于进行中；新回执/拒绝/追问可把已完成会话重新变为待处理                     | 多原因均持久记录，不能因一个原因消失把其他事项清掉                                |
| E07  | 收件人以精确账号 ID/邮箱查找，匹配后确认身份；不提供全站账号遍历                       | 有界返回、节流、实时账号状态检查；同名不自动发送                                  |
| E08  | 新增工单开启新的待返回集合；之前已解锁或采用的历史版本仍可查看，新集合不完整时只给进度 | 不撤销已合法采用的旧上下文，也不提前暴露新的部分交付                              |
| E09  | Agent 无法验证约定内容时保留接单方待处理，说明哪项无法判断、允许补证/重试              | 不伪造通过、不增加 A 的主观批准门槛；首期不做“人工强制通过”                       |
| E10  | 搜索/通知/账号复用 LocalMind 现有入口；补齐工单通知，移除“全部团队”和预览身份切换      | 无真实能力的原型控件不伪装可用；不要求新做语音或搜索引擎                          |
| E11  | 个人工单首期使用私有交付草稿、上传和既有支持格式生成；交付快照只读                     | 不扩大为个人完整文件管理器；Project 中的现有文件编辑仍完整保留                    |

已拒绝的工单对 A 的未结处理沿用原型：明确撤回/关闭后从待返回集合排除，不等于成功
交付。账号删除、法规保留和永久清理沿用实例已有政策，不在本方案新定保留年限。

## 5. 前端适配

### 5.1 页面与路由

建议新增以下语义路由；实施时先验证现有 router 匹配和 Electron 深链，名称可调整，
但不能只靠组件内状态或标题定位会话。

| 路径                                           | 页面                                                   |
| ---------------------------------------------- | ------------------------------------------------------ |
| `/project`                                     | 本人的跨项目会话与个人工单总览，条目/关系切换          |
| `/project/conversations/new`                   | 无默认项目的现有聊天空白态，项目选择仅在输入框上方     |
| `/project/:projectId/conversations/:sessionId` | 当前用户的具体 Project 会话                            |
| `/project/work-orders/:workOrderId`            | 当前用户作为接收人的独立工单会话                       |
| `/project/:projectId/resources/:resourceId`    | 保留既有原生资源路由；可附带经校验的自己的会话定位参数 |

静态 `conversations`、`work-orders` 路由需先于 `:projectId` 匹配。旧项目资源 URL
及 `/intelligence` 等重定向保持可用；无权/删除的会话统一返回不泄露身份的错误。
关系、通知和任务卡从服务端获得“我自己的导航目标”，不得接受对方 session ID。

左栏保留项目管理和返回 Workspace。项目名点击只展开/收起；会话点击导航，双击或
F2 改名，提供键盘/菜单等价入口。个人工单独立分组。项目和会话各自有分页/加载/
失败/空状态，不预取所有项目历史。原项目列表/设置入口可收纳，但不能移除管理能力。

### 5.2 共享会话组件

将 `WorkbenchConversation` 的 Project 配置与通用展示分离，复用 `AIChatRuntime`、
消息组件、composer、工具进度、审批和错误状态；以明确的 scope adapter 提供会话
加载、创建、模型元数据和资料选择。不通过给 required `projectId` 填空串来模拟工单。

- 新会话先显示空白态；不选择项目时保留输入、显示“请选择项目”，零模型调用/召回。
- 用户刚创建项目后可以显式预选新项目；其他入口不能默默继承上次项目。
- 创建与首条消息需要幂等关联；模型发送失败保留可重试会话，不能重试建出多张卡。
- 名称记录 `manual/auto/pending` 与 revision。自动摘要仅对首次成功输入生成一次，
  写回时 CAS 检查名称仍未人工修改；失败显示稳定占位，不能将截断当成模型摘要。
- Project 有共享 Memory 说明；各 session 的资料选择、附件和摘要独立。
- 个人工单只有自己的上下文与明确交接资料，无项目选择器/项目文件树/项目 Memory。
- “标记完成”与 Agent 停止、工单交付、拒绝/撤回是不同操作，不共用一个含糊 mutation。

### 5.3 右侧面板状态

采用显式视图状态，不把多个互相覆盖的 CSS class 当成唯一事实：

`context | projectTree | resource(resourceId, openedFrom, treeOpen)`。

文件夹按钮：无文件时切换上下文/完整树；有文件时切换旁边窄树，不卸载编辑器。
切换文件先走未保存保护；关闭文件按 `openedFrom` 返回对应栏并恢复焦点。
打开文件不自动加入 AI 上下文；点击“引用”才更新当前会话的持久引用版本。

继续使用 `ProjectResourcePreview` → `ProjectOffice/ProjectDocument/ProjectFile`，
保留路径、全屏、发布/导入、只读、20 秒续租/60 秒过期、冲突及 AI 租约交接。
工单回执使用授权的不可变快照预览/下载，不伪造 ProjectResource 以套入编辑器。
支持的 Office 只读呈现可复用原生解析/渲染能力；不支持的类型明确下载或报错。

### 5.4 视觉与适配

参考 HTML 的浅灰导航、白色内容区、细分隔、紧凑卡片及聊天/右栏层级；采用 LocalMind
的 `cssVarV2`、`@affine/component`、`@blocksuite/icons/rc` 与现有字体，不引入另一套
设计系统，不复制内嵌 Base64 Logo 或数千行覆盖式 CSS。

建议起点：导航约 240–264px，上下文约 240–280px，可折叠文件树约 200–260px；
正文与输入保持可读，辅助字避免沿用原型 7.5–10px。尺寸属于适配值，最终按实际截图
调整。宽屏并排；约 1040px 折叠辅助栏；760px 以下左栏抽屉、聊天/文件切换，保留
草稿和编辑状态。检查 1440/1040/760/390px、浅深主题、长中文、键盘和 200% 缩放。

## 6. 领域模型与持久状态

以下模型名是建议，允许按现有抽象调整，但所有不变量必须落到数据库/领域层。

```text
本人总览 / 左栏 / 会话标题
             ← 会话投影（自己的 session，一卡一行）
                           ↑
     会话工作状态 + 待我动作 + 运行状态 + 工单事件
                                            ↓
         关系图 / 协作角色 / 通知（同源，按本人权限投影）
```

### 6.1 会话与注意事项

| 记录                 | 必要信息与约束                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| `AiSession` 扩展     | 明确 `workspace/project/work_order` 类型；个人工单绑定身份；现有 `userId` 为会话所有者           |
| `AiSessionWorkState` | session 唯一、owner、版本、人工完成时间/原因；看板分类由服务端统一计算，可物化但不能成为第二真相 |
| `AiSessionAttention` | 会话、处理用户、原因、来源实体、open/resolved、版本、解决证据；稳定来源唯一键防重复              |
| 会话标题元数据       | 手动/自动来源、命名 revision、待生成状态；历史 title 保留不重新总结                              |
| 回执采用记录         | source session、回执 revision 集合、context version、采用者和时间；历史不可被“最新”覆盖          |

工作状态、Agent run 状态和工单状态分开。待处理不是关键词识别结果：审批、结构化
反问、决策请求、未完整提交、异常、完整回执到达等事件，必须产生有来源的注意事项。
Agent 可通过经验证的结构化输出提出问题/需求，但不能任意覆盖整张卡片状态。

聚合顺序采用 E06：未解决的本人动作 → 待处理；否则已被本人合法完成 → 已完成；
否则 → 进行中。运行、等待他人和待租约作为标签。某个 run 结束不自动完成普通会话。
被拒绝/取消的接单会话自动收在已完成，结果标签不算成功交付；继续私人聊天只恢复
会话工作状态，不恢复工单。新的业务注意事项到达可重新置为待处理。

### 6.2 工单、交付与文件

| 记录                        | 必要信息与约束                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------- |
| `WorkOrderDispatch`         | 一次 A 确认的发送批次、原 session、sender、草稿版本/指纹、确认凭据、幂等键         |
| `WorkOrder`                 | 独立 ID、sender/recipient、原会话关联、状态/version、冻结要求；补充/替代关联原工单 |
| `WorkOrderSessionBinding`   | 工单与接收人自己的 `AiSession` 唯一绑定；发送者返回原会话                          |
| `WorkOrderRequirement`      | 稳定项 ID、类型、必填性、格式/数量/内容条件、验证方式；发送后只读                  |
| `WorkOrderExchange`         | 仅明确发送的说明、追问、答复、拒绝、撤回原因；不复制私人聊天                       |
| `WorkOrderDeliveryRevision` | 工单、递增 revision、要求指纹、提交人、文件/文字快照、检查证据、时间；不可原地更新 |
| `WorkOrderBlob` / 附件授权  | 私人暂存/明确交付、owner、工单、不可变内容身份、MIME/大小/摘要、受众与访问状态     |
| `WorkOrderEvent` + outbox   | 业务事件与状态变更同事务提交；通知/投影可靠重试，不以浏览器在线为条件              |

禁止使用 `AiSession.parentSessionId` 连接 A/B 会话：该字段表示 fork，既有来源继承
逻辑可能复制上下文。工单关联使用独立字段/绑定，不允许 A 读取 B 的私人消息。

禁止以 `deliveries[recipientId]` 作为真实存储：同一个人可收到多张补充工单。必须
使用工单 ID 和 revision；收件人姓名、文件名、项目名都不是稳定业务身份。

### 6.3 状态转换与完整返回

| 事件                           | A 原会话                                 | B 自己的会话 / 工单                      |
| ------------------------------ | ---------------------------------------- | ---------------------------------------- |
| Agent 形成草稿                 | 待处理：确认发送                         | 没有工单、通知或可见关系                 |
| A 确认并成功发送               | 进行中：等待返回                         | 待处理：按冻结要求交付                   |
| B 正在准备                     | 进行中                                   | 进行中；需要 B 补充信息时待处理          |
| B 追问                         | 待处理：答复；优先于其他部分回执         | 进行中：等答复                           |
| A 显式答复                     | 清除此原因，按其余事项聚合               | 待处理：继续完成                         |
| B 拒绝并说明原因               | 待处理：处理未结事项                     | 已完成列，已拒绝/未交付                  |
| 只有 B 成功返回                | 进行中，仅进度                           | 已完成：成功交付                         |
| 所有有效工单成功返回或明确撤回 | 有交付则待处理查收；全部撤回则可手动结束 | 各自结果不变                             |
| A 采用完整回执                 | 清除对应查收原因，可继续对话             | 不增加 A 的批准完成门槛                  |
| A 撤回未结工单                 | 重新聚合其他事项                         | 已取消/未交付；持久通知及原因            |
| B 显式提交新版                 | 全部条件满足时待处理，新版未自动采用     | 新回执版本；旧版保留                     |
| A 发送补充/替代工单            | 同一会话增加待返回集合                   | 新工单、新独立接单会话；旧工单不自动取消 |

“完整返回”按当前发起会话下待返回集合计算，含已确认的补充工单；拒绝不能自行从
分母消失。撤回不计交付。已解锁的历史集合与新集合分开（E08），避免新增工作使旧
回执和已采用上下文失效。

门禁必须同时覆盖 GraphQL 正文、Blob 下载、缩略图/解析结果、搜索/向量、通知正文、
SSE 和 Agent 上下文，不能只是禁用“查看”按钮。未齐时 A 仅见约定要求与进度，不
拿到新回执内容或可用下载 URL；B 仍可查看自己的提交。所有接口从当前 actor 校验。

### 6.4 完成检查与并发

- 文件核对真实 MIME/容器格式、非空、可读取、数量及要求；不能只按扩展名。文本按
  发送时的结构化内容条件核对，有界模型检查保留逐项证据，不能添加满意度标准。
- 工单草稿的要求要匹配当前检查能力。无法支持的格式/条件在确认发送前说明；旧版
  `.ppt` 与 `.pptx` 不能因 HTML 示例同时允许就声称都可解析。
- 暂存、检查中、需补齐和成功交付分开。仅成功检查后的持久回执触发 B 完成和 A 进度；
  检查超时可恢复，能力不足按 E09，不无限自动重试或伪造通过。
- 发送批次先校验所有收件人/要求，数据库内原子创建；outbox 失败重试，不呈现“全部
  已发送”而部分工单不存在。重试使用同一 requestKey 与指纹，不同 payload 拒绝。
- 撤回、拒绝、提交、采用、结束主会话均携带 expectedVersion、幂等键；锁定原会话
  聚合记录与相关工单，统一锁顺序。完成主会话和新增工单并发时只能有一个有效结果。
- 取消与交付同时到达以条件终态写入决定：已成功交付不能改为取消；取消成功后晚到
  检查/worker 不发布交付。已发生副作用保留真实回执，不声称取消已经抹除文件。
- 取消工单只停止属于该工单的运行；不能停止 B 的其他会话。执行前、提交前、重试及
  租约接管后重查状态、actor、会话 epoch、权限及模型配置。
- 完成普通会话不删除消息；删除使用现有持久清理任务。新工单快照和另一人的合法
  交付记录不能被私人会话级联误删；清理载体/保留政策见第 9 节。

## 7. 个人工单的模型、资源与运行时适配

### 7.1 新作用域，复用运行时

推荐扩展现有 session/run/step/timeline/result 的 owner union 为明确的
`workspace | project | work_order`，而不是平行再建第二套执行系统。个人工单以
真实 workOrderId 关联 scope，workspaceId/projectId 为空；actor 必须匹配接单会话
所有者。A 的主会话仍是原 Project scope。

必须联动修改 schema、所有者 CHECK、复合 FK、唯一键、source ledger 触发器、输入
与副作用约束、context/checkpoint、删除清理、provider、SSE、compat、worker、工具
快照和前端 scope 分支。现有两类 owner 约束不是可简单删除的“障碍”；迁移后保持
三选一及 actor/session/scope 一致性，并以伪造混合 scope 的拒绝测试证明。

Project 现有工具保持 `project_*`，Workspace 保持 `workspace_*`，旧名称不复活。
新增工单草拟/追问/交付等是独立协作业务工具（命名如 `work_order_*`），必须在契约
中明确登记作用域和确认要求，不作为读取任意 Project/Workspace 的资源工具别名。
旧 MCP 凭据不自动获得新能力；新工具也不能绕过用户 UI 等价确认。

### 7.2 模型与上下文

- 服务端先解析持久 session 并验证 owner，再选择全局 Project BYOK 记录；个人工单
  有独立入口权限，Project 分支原有成员校验保留。会话参数不能自行指定别人的项目。
- `getProfiles`、模型 metadata、后台标题、摘要、文件检查、重试和 worker 均复用同一
  管理员配置；缺失/停用时明确失败，不回退到用户/Workspace/local lease/平台额度。
- 共用配置只复用凭据来源，不共享历史、Memory、附件、向量、缓存、工具快照或审计。
- 工单初始上下文只装入明确发送的要求和允许交接的材料。B/C 相互不可见；项目名若
  未明确共享也不暴露。个人工单不自动创建或召回 Project Memory。
- A 采用回执冻结 revision 集合及 context version；更新只作用于后续轮次。旧轮次
  重试保持原快照并重查权限；过期摘要按依赖失效，不把新版静默混入旧摘要。

### 7.3 私密交付存储与后续使用

交付草稿/快照放在工单自有、参与者授权的存储命名空间，不能直接落到成员共享的
Project 目录或某个个人 Workspace。底层 Blob/对象存储可复用，授权和版本记录独立。

LocalMind 现有格式生成能力可在个人工单中生成私有交付草稿 bytes，之后走同一提交
验证链；不能先借用别的项目生成资源。首期不改造 OfficeArtifact 为第三类可编辑
个人 Office 容器，也不声称工单提供完整文件工作区（E11）。必须支持真实 PPTX/文本
示例闭环；支持格式依据现有 Office 能力，非静态占位文件。

明确交付给 A 不等于向 A 的整个项目共享。A 可在自己的原会话采用；要复制到项目
共享目录、导入 Office 编辑、发布 Workspace 或贡献共享 Memory，须有明确意图、
来源复制/分享授权和目标 ACL。原工单受众不因此被静默扩大；新副本和交付快照分离。

下载每次认证、授权；令牌短期且不绕过门禁，不开放按内容 hash 直接读。内容用专用
payload 保存，审计/outbox 不保存全文、密钥或可长期直接下载的 URL。缓存按服务端、
账号、scope、session、context epoch/revision 分离，退出账号清除个人缓存。

## 8. API、通知与关系图

### 8.1 领域 API 清单（建议名称）

| 能力       | 查询 / 命令                                                         | 关键条件                                              |
| ---------- | ------------------------------------------------------------------- | ----------------------------------------------------- |
| 会话投影   | listMyConversationCards、getOwnedConversation、completeConversation | actor 从登录态取得；分页/完整计数；未结检查           |
| 命名与创建 | createProjectConversation、renameConversation                       | 有效项目；首次发送幂等；名称 revision                 |
| 收件人     | resolveWorkOrderRecipient                                           | 站内已有账号、有界精确查找、节流、无全站枚举          |
| 工单草稿   | prepareWorkOrderDispatch、confirmWorkOrderDispatch                  | Agent 可草拟，只有 A 的显式确认可发送；草稿 hash 匹配 |
| 工单处理   | getMyWorkOrder、ask/answer/refuse/cancelWorkOrder                   | 操作角色与期望版本；必填问题/拒绝说明；取消通知       |
| 文件/交付  | stageWorkOrderFile、submitWorkOrderDelivery、getDeliveryRevision    | 私人暂存；解析/内容证据；完整返回门禁                 |
| 采用       | adoptWorkOrderDeliveries                                            | A 原会话；完整已释放集合；context CAS 与旧版保留      |
| 需求变更   | prepareSupplement/Replacement                                       | 新工单 ID，原要求固定，重新确认，不隐式撤回           |

这些不是现有接口名；落地时按 Nest resolver/model 与共享 `.gql` 规范实现类型化
输入输出，不做无界 JSON 通道。GraphQL schema/client、SSE 结构事件、通知 union、
i18n 与所有消费者一起生成/升级。下载走经授权控制器，不让前端自行拼原始存储路径。

### 8.2 实时与通知

新事件应以本人房间为边界（如 `conversation.workstate.changed`、
`work-order.changed`），登记到 realtime registry/required-handlers。复用订阅管理
和统一 15 秒快照兜底，不给每张卡/每条工单再开轮询。忽略过期版本，断线重连补快照。

业务提交和 outbox 同事务；持久通知以 `(eventId, recipientId, channel)` 去重。
收到工单、追问、答复、拒绝、取消、完整返回、新版交付通知指向自己的会话。
通知已读不等于业务已处理；部分返回默认仅更新进度，不泄露正文。首期站内通知，
不新增邮件/推送外发。重新投递通知不能重复建会话、工单或交付。

### 8.3 关系图复用方式

Agent 负责识别需求、生成经确认的结构化工单；程序从持久工单确定性生成图，不能让
模型每次重新猜边和状态。方向固定为交付人 → 接收人，节点/边关联工单及自己的 session。

先做 GFX 只读宿主验证：复用连接器、节点、视口和 zoom-to-fit；数据是内存中的
权限过滤投影，不注册成共享 Project 文档，不连接共享 Yjs 同步/搜索/自动保存。
仅提供平移、缩放、查看、导航；禁用编辑快捷键、拖节点、增删边和写回。
如果必须有内部 store，也只是可销毁的渲染容器，不成为第二套持久业务状态。

多项目按 A 可见项目分组；B 只看本人个人工单及明确共享的背景。不合并同一对人不同
工单的义务。接单方不因此看到 C 的其他工单。旁边同源列表提供键盘和读屏等价入口。
按分页/筛选范围显示图并提示范围，不把部分结果画成“所有关系”；空态不造假边。

若现有画布不能满足宿主隔离、只读或性能，记录可重现证据和替代方案并请求决定；
不得默默改成可编辑共享画布，也不能跳过关系图却将整体 Goal 标为完成。

## 9. 迁移、兼容与上线边界

1. 新增迁移，不修改历史 SQL。先盘点所有 owner 约束/触发器及新增加的在途迁移，
   避免覆盖 2026-09-21 会话/共享记忆/删除/整理工作。
2. 历史 Project 会话保留 ID、owner、名称、消息、项目和已选引用。建立会话工作状态
   时，有明确待办证据则待处理，正在执行/等待则进行中，其余默认进行中；不能因为
   最后一个 run 成功就把整个会话标成用户已完成。回填可重入、分批并核对数量。
   历史 Workspace-hosted Project 会话按既有契约保持原 owner 范围内只读，不自动恢复
   执行或改成新 native session。`selectedContextProjectId` 在旧记录里也可能只是
   上下文选择，不能机械地把它与 `workspaceId` 同时存在视为非法并删数据；所有者类型
   回填须按现有会话语义分类，对不能无歧义归类的记录保留并报告例外。
3. 旧 ProjectFileRequest 已授权给项目的交付保持原语义和入口，不偷偷改为私人；不
   迁移其授权为新工单。旧未结请求继续由旧通知/任务入口处理，并有明确的兼容入口。
4. 有 owner session 的旧运行/审批可作为该会话注意事项来源；无私人会话的行政、
   成员邀请、来源复制审批保留旧 `/tasks`/通知，不伪造会话或把别人的请求塞进自己的
   私人聊天。来源复制审批人仍不因为审批身份额外得到 Todo。
5. 新存储加入会话删除、账号删除、Blob 引用计数、清理任务及备份恢复清单。未共享
   草稿可清理；已交付独立快照按已授权保留政策处理，不能因删除 B 私人会话删除 A
   合法回执。法律保全、脱敏审计与会话 payload 分开，不新增永久保存私人全文的理由。
6. 验证空库全量迁移及从脱敏/授权快照升级；验证旧数据拒绝越权、新作用域约束、
   重启恢复、降级兼容。线上备份和停 worker 的操作须在有部署授权的阶段执行。
7. 建议受控功能开关分步启用新 UI/新写入。禁用新建不能抹除已有新工单的读取与收尾
   入口。新增 owner 数据写入后不能直接回滚到不认识该数据的旧 worker；需禁用新写、
   暂停相关 worker、保留兼容读取并按验证的前向修复/恢复方案处理，不删表回滚。
8. 本 Goal 默认源码与隔离验收交付，不隐含更新当前业务容器、生产库或线上服务。
   用户另行授权运行同步后，备份并按仓库脚本同步；不得手工复制散落文件。
