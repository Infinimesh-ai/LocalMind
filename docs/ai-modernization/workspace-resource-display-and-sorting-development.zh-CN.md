# Workspace 资源显示属性与排序开发方案

状态：P0—P3 源码已实现并完成隔离验证，尚未同步实际运行环境；逐项证据及部署限制见[实施记录](workspace-resource-display-and-sorting.execution.zh-CN.md)。需求整理日期：2026-10-08；实施日期：2026-10-09。P4 根目录统一排序仍为独立后续阶段。

Workspace 主列表的“显示属性”收敛为四项：**标签、创建者、更新、文档类型**。“创建者”同时展示创建者和创建时间；“更新”同时展示最后更新者和最后更新时间。页面、白板、原生 Office、PDF 和普通文件使用一致的显示、分组与排序规则。

本文保留开发契约与实施前基线；源码、迁移、测试结果以实施记录为准，不能据此推定运行环境已更新。“成员”已从需求中取消，不建设协作成员列、在线成员列或新权限体系。

## 1. 范围与文档关系

### 1.1 必做范围

1. 主列表菜单只提供四个属性开关，组合属性整体显示或隐藏。
2. 补齐原生资源的标签、创建信息和最后更新信息，消除原生行忽略显示设置的行为。
3. 排序字段与排序方向分别提供明确、可点击的入口。
4. 主列表按真实字段进行混合资源排序和分组，迁移旧显示偏好。
5. 保持目录归属、编辑模型、现有 ACL、版本检查和不可变修订规则。
6. 将侧栏文件夹的排序入口直接放到文件夹行右侧，与“＋”并列；沿用现有排序逻辑。

侧栏文件夹排序入口前置已确认，属于本期必做范围；交互见第 7.2 节。根目录统一排序仍是第 7.3 节的建议后续阶段，不与本次入口调整合并，也不作为四项属性改造的上线前置条件。

四项属性、明确排序方向及文件夹行内排序入口是本轮已明确的需求；默认展示、更新事件范围、字段集合与迁移细节是本文给出的具体实施方案。

实施顺序：先基于当前源码和目录模型独立完成本对话需求，不等待页面树、不为未来页面树预先迁移或改变本方案范围。后续页面树开发负责适配本方案届时已交付的元数据、显示偏好、排序及权限行为；不能反向要求本方案为其延期或重写。

### 1.2 适用边界

- 首要入口为 `/workspace/:workspaceId/all` 的“全部”混合资源列表，覆盖列表和卡片布局。
- 本次不重新设计文档编辑器、Office 编辑器、Project 工作台或回收站。回收站继续展示其必要的删除时间和恢复信息。
- 纯本地 Workspace 保留页面与白板能力，不借本方案新增原生文件离线存储。
- 图标、内容预览和快捷操作继续属于各自的视图设置，不计入四个属性开关；原生格式图标正确区分资源类型。不新增尚无能力兑现的正文预览。
- 共享 `ExplorerDisplayMenuButton` 还用于精选、标签等入口。采用显式配置或适配，不能修改公共注册表后意外删除其他界面的编辑器属性、筛选规则或既有能力。
- 标签筛选在本次主列表内覆盖原生资源；精选、自定义属性和其他专用页面的原生扩展不自动纳入范围，仍须明确其适用资源。

### 1.3 现有契约

- [Workspace 统一资源体验](workspace-unified-resource-experience-remediation.zh-CN.md)：现有入口、资源身份、目录、回收站及侧栏文件夹排序；第 7.7 节是已有排序实现依据。
- [Workspace 与 Project CRUD](workspace-project-document-crud-remediation.zh-CN.md)：原生资源读写、不可变创建证据、修订、授权及重试契约。
- [原生 Office](../office-native/README.md)：OfficeArtifact、OfficeRevision、WorkspaceFile 与编辑模型边界。
- [Project 原生资源](tracks/project-native-resources.md)：仅作为跨域边界，不将 Project 资源混入 Workspace 列表。
- [验证规范](validation.md)和 [Docker 开发约束](../localmind-docker-development-constraints.md)：实现阶段的验证与部署规则。

旧统一资源方案将“原生标签和文档属性扩展”列为范围外。本方案提出这一后续扩展；旧方案的完成记录保持原义，不作为本方案通过验收的证据。

## 3. 四项属性的产品契约

### 3.1 菜单与组合展示

菜单文案固定为：

| 开关     | 开启后展示                                               | 关闭后行为                         |
| -------- | -------------------------------------------------------- | ---------------------------------- |
| 标签     | 标签名称与颜色，溢出显示数量；无标签显示轻量空态         | 隐藏标签区域，不删除标签           |
| 创建者   | 创建者头像与名称，以及创建时间                           | 人和时间一起隐藏                   |
| 更新     | 最后更新者头像与名称，以及最后更新时间                   | 人和时间一起隐藏                   |
| 文档类型 | 页面、白板、Word、Excel、PowerPoint、PDF、TXT 等类型标识 | 隐藏类型文字，文件身份图标仍可保留 |

“创建者”与“更新”旁提供简短说明，分别为“创建者和创建时间”“最后更新者和最后更新时间”。不再提供独立的“创建时间”“最后编辑者”“更新时间”开关。

新增用户默认开启四项。已有用户按第 6 节迁移，不通过默认值强行覆盖其关闭选择。开关使用清晰勾选或开关状态，不能只靠浅灰背景表达选中与未选中。

列表中每项作为一个完整信息组；较窄布局将信息组换行或放入可展开的详情区。不能让用户开启属性后因固定宽度规则永久不可见，也不能仅隐藏组合中的姓名而留下时间。卡片视图使用相同开关和语义。

时间按用户当前语言与时区格式化，悬停及键盘聚焦可查看包含时区的完整时间。排序始终使用原始时间值，不比较“今天”“上周”等显示文本。

### 3.2 创建者和创建时间

- 表示当前资源在当前 Workspace 中创建的操作者与时间，创建后保持不变。
- 上传、复制或从 Project 发布独立副本时，新资源显示本次实际创建者和时间；源作者及源文件内部日期只属于来源信息。
- 后续内容保存、重命名、标签变更、移动或恢复，不改写创建证据。
- AI 受用户委托创建时保留已有真实委托身份和来源；不把模型名称当作用户，也不把后台 worker 当作创建者。

### 3.3 最后更新者和最后更新时间

“更新”表示该资源最近一次**成功提交的内容或资源元数据变更**。时间与操作者必须来自同一个事件，不能用最新时间拼接旧修订作者。

| 事件                                                   | 是否推进用户可见更新信息           |
| ------------------------------------------------------ | ---------------------------------- |
| 创建资源                                               | 是，初始更新信息与创建信息一致     |
| 保存页面、白板、Office、文本内容，替换文件版本         | 是，记录成功写入者及提交时间       |
| 从历史版本恢复内容                                     | 是，记录本次恢复者及新修订时间     |
| 重命名、实际增删标签、改变页面与白板的主模式           | 是，记录本次元数据变更者           |
| 无内容变化的保存、相同请求幂等重放、被拒绝或冲突的写入 | 否                                 |
| 打开、浏览、下载、在线心跳、索引回填、搜索缓存刷新     | 否                                 |
| 移动目录、手动调整目录位置、调整显示偏好               | 否，沿用目录或个人偏好的记录       |
| 权限变更、评论、移入回收站、从回收站恢复               | 否，沿用各自审计与生命周期时间     |
| 无可归属用户的系统内容修复                             | 是，明确显示“系统”；不能冒用创建者 |

每个成功变更路径在自己的事务或既有提交边界内更新这组信息；并发失败、旧事件迟到、任务取消、审批未通过都不能推进它。BlockSuite 保持 local-first 提交方式，离线记录同步后需保持事件归属一致，不能用“最后收到哪个网络包”决定最后更新者。

本方案中的更新语义是开发目标。实施时不得静默改变公开 MCP 的既有字段语义；必要时给列表增加明确的新投影字段，并保持旧协议兼容。

### 3.4 文档类型

统一提供稳定的 `documentType` 键与本地化显示名，列表、分组、排序和文件类型筛选复用同一映射。

| 真实资源                            | 类型显示                                                       |
| ----------------------------------- | -------------------------------------------------------------- |
| BlockSuite Page / Edgeless          | 页面 / 白板                                                    |
| Office Docs / Sheets / Slides / PDF | Word / Excel / PowerPoint / PDF；详情可补充 DOCX / XLSX / PPTX |
| WorkspaceFile 文本格式              | TXT / Markdown / CSV / JSON                                    |
| 图片、音频、视频                    | 图片 / 音频 / 视频，可补充 PNG、MP3 等实际格式                 |
| 其他已识别或未知二进制              | 实际格式如 ZIP；无法可靠识别时显示“其他文件”                   |

类型优先依据真实资源种类、Office kind 和当前有效修订的已验证格式；文件扩展名只作为受控的补充信息。改名不能把页面变成 Word，也不能把 ZIP 变成可编辑 PDF。旧 Office `doc` 目录节点按真实 Office 身份解析，不能重复显示成页面。

类型文字是否显示、文件类型筛选是否生效是独立设置，隐藏类型不清除筛选。

### 3.5 空值与加载

- 历史创建者或更新者无法确定：显示“暂无记录”，不能用当前登录用户、创建者或文件所有者补猜。
- 真实系统事件显示“系统”；已知账号已删除与无权查看用户详情分别使用合适占位，不输出邮箱等无关个人信息。
- 已知时间、未知操作者时保留时间并明确操作者暂无记录；不能把一组信息全部丢弃。
- 加载时使用占位，失败时提供就地重试；不能将请求失败显示成“无标签”或“暂无记录”。
- 所有展示只消费当前用户有权读取的资源元数据，用户详情批量获取且遵守既有公开资料边界。

## 4. 主列表排序与分组

### 4.1 排序入口

排序面板拆为两个区域，字段和方向均有明确的选中状态：

```text
排序字段  名称 / 创建时间 / 最后更新时间 / 文档类型
排序方向  最新在前 ✓    最早在前
```

| 字段         | 方向文案                    | 首次选择的默认方向 |
| ------------ | --------------------------- | ------------------ |
| 名称         | 名称正序 / 名称倒序         | 正序               |
| 创建时间     | 最新创建在前 / 最早创建在前 | 最新在前           |
| 最后更新时间 | 最新更新在前 / 最早更新在前 | 最新在前           |
| 文档类型     | 类型正序 / 类型倒序         | 正序               |

保留已保存的合法方向；重复点击当前字段不再隐式翻转方向。菜单收起时显示例如“最后更新时间 · 最新在前”。方向选项可用键盘操作，并具备单选状态语义。

本期不提供标签、创建者姓名、更新者姓名排序，避免多值及身份显示规则引入歧义。四个显示开关与排序字段相互独立：隐藏“创建者”仍可以按创建时间排序。

### 4.2 比较与分页

- 名称复用现有中文、数字感知的自然比较，使用实际显示名称；例如正序为 `文件2 → 文件10`。
- 类型使用固定、版本化的类型顺序：页面、白板、Word、Excel、PowerPoint、PDF、TXT、Markdown、CSV、JSON、图片、音频、视频、其他文件；倒序反转类型顺序。未知类型排在末尾。
- 主字段相同时以稳定资源身份打破平局；名称与类型的同值规则在服务端和前端适配中一致。
- 时间为空始终排在有值资源之后，不因升序或降序改变；禁止用 `0` 或当前时间冒充缺失值。
- 稳定资源身份包含 `workspaceId + kind + id`。比较器不得把未支持字段静默降级为更新时间。
- 先完成授权过滤，再比较与分页；不能各取页面、Office、普通文件第一页后排序并称为全量顺序。
- 第一阶段可保留现有有界完整目录策略，但必须等目录完整加载后呈现确定顺序，沿用超过 10,000 项显式失败的保护。改为服务端分页时，游标必须绑定作用域、筛选、字段、方向、排序版本和稳定身份，旧游标不可跨配置使用。
- 重命名、内容更新及元数据变更后重新定位条目，保留选择和焦点；搜索、类型筛选、标签筛选与排序组合生效。

### 4.3 分组

主列表提供“不分组、标签、创建者、创建时间、最后更新时间、文档类型”。取消旧菜单中不适用于混合资源的编辑器属性分组；不新增更新者分组。

创建者按用户身份分组，不按头像字母或姓名分组；时间按用户时区的自然日分组，未知日期单列。类型使用第 3.4 节同一分类。组内始终使用当前排序字段与方向，日期组由近到远展示，未知组置末。

标签沿用一条资源可出现在多个标签组的规则；无标签进入“无标签”。总资源数、批量选择和操作按资源身份去重，每组计数只表示该组条目数。无创建者数据的组明确显示“创建者暂无记录”，不再只显示一个“未”字头像。

## 5. 数据与代码方案

### 5.1 统一元数据读模型

在既有 Workspace scope 与资源服务上增加明确类型的展示适配，不另建内容存储，也不让原生文件冒充 `DocRecord`。建议字段如下；最终 GraphQL 命名遵循已有 schema 风格。

| 字段                             | 约束                                                    |
| -------------------------------- | ------------------------------------------------------- |
| `identity`                       | Workspace、资源种类与稳定 ID                            |
| `title`、`documentType`          | 当前标题与稳定类型；独立于本地化显示名                  |
| `tags`                           | 当前工作区的标签 ID、名称和颜色；加载状态不能伪装空数组 |
| `createdAt`、`createdBy`         | 成对来源于创建证据；允许明确的历史缺失                  |
| `lastUpdatedAt`、`lastUpdatedBy` | 成对来源于同一有效内容或元数据事件                      |
| `metadataVersion`、内容版本      | 沿用各资源现有版本，供并发与迟到结果校验                |
| `capabilities`                   | 复用现有真实 ACL；如需标签写能力，单独投影但不新增角色  |

操作者引用区分用户、系统、未知；用户详情复用现有资料服务并批量获取，避免每行一次请求。客户端投影只作派生缓存，资源内容和业务状态仍由各领域模型持有。

### 5.2 原生创建与更新信息

创建信息直接投影既有 `WorkspaceFile` 和 `OfficeArtifact` 字段。最后更新信息需要检查现有 revision、operation 与元数据写入记录，不能直接用 state 的 `@updatedAt`。

建议在原生当前状态层持久化用户可见更新事件的时间、操作者种类、操作者引用和来源版本／事件标识。只有第 3.3 节规定的有效写入可更新它；索引任务仍更新自己的状态，不触碰这组字段。Office 内容继续属于 OfficeRevision，WorkspaceFile 创建记录和历史修订继续不可变。

所有入口必须覆盖：UI 新建／上传／保存／改名／标签修改、Office 命令与批处理、版本恢复、复制、Project 显式发布、内部 AI 工具，以及现有已授权资源写入口。写入复用领域服务，保留实时 ACL、事务、CAS、幂等与审计。不得借新增字段注册新公开 MCP 工具或扩张旧冻结凭据。

BlockSuite 复用其现有创建和更新属性，但应审查本地编辑、同步、后端写入及 AI 写入的事件口径。若现有字段不足以表达新语义，只增加必要的事件关联和派生投影，不能改成原生 Office 的内容模型。

### 5.3 原生标签

- 复用工作区现有标签定义及稳定 ID，不能为原生文件复制另一套同名标签字典。
- 新增或扩展原生资源与标签的持久关联，明确 Workspace 与 file／office 身份、唯一性、资源存在性及删除行为。具体表名在实施阶段确定。
- 标签关联属于可变元数据，不写入创建证据或 OOXML 正文；变更使用资源 ID、预期元数据版本及稳定请求键。
- 标签编辑复用现有选择交互和标签管理规则；只读成员仍可显示、筛选，写入必须满足该资源实时写权限。
- 用户为某资源增删标签推进该资源的“更新”；全局标签改名或调色只改变标签定义，不伪造所有关联资源被同一用户修改。
- 跨 Workspace 的标签 ID 不可直接关联；复制／导入时沿用明确的来源和目标规则，不能自动创建同名标签并声称相同身份。
- 标签删除、资源回收／恢复、永久删除和权限撤回须定义一致行为。至少保证回收恢复不丢失合法关联，已删除标签不再展示或参与分组。

## 6. 历史数据与偏好迁移

### 6.1 数据迁移

1. 新增必要 schema 和迁移，不覆盖原生创建证据、不可变修订和旧回执。
2. 创建信息来自真实创建记录；最后更新信息仅从能确定操作者、时间、事件类型和资源版本的证据回填。
3. 仅有最后修订作者、却无法排除后续重命名时，不能直接认定其为最后更新者。信息不足保持未知，不用迁移执行时间或管理员身份补齐。
4. 历史原生资源无标签关联时明确为空，不从同名页面、目录名或文档正文推断标签。
5. 回填有界、可续跑、幂等；通过预期版本／条件更新防止旧回填覆盖实时新写入。记录总量、已回填、缺失和失败数量，不记录正文。
6. 验证全新数据库迁移和受影响旧状态升级，覆盖修订存在但状态投影缺失、元数据晚于修订、系统索引晚于用户更新等情况。

### 6.2 显示偏好迁移

为本入口使用新的偏好版本或独立键，明确保存四个布尔值，不再把任意系统属性 ID 列表作为新菜单的真相来源。旧键保留用于兼容，不能回写破坏其他页面的旧配置。

| 旧值                                     | 新值                                     |
| ---------------------------------------- | ---------------------------------------- |
| 标签开关                                 | 标签                                     |
| 创建者或创建时间任意一项开启             | 创建者组合开启；两者都关则关闭           |
| 最后编辑者或更新时间任意一项开启         | 更新组合开启；两者都关则关闭             |
| 旧配置存在可识别的文档模式属性           | 文档类型沿用其开启或关闭状态             |
| 旧版本没有文档模式属性，或没有旧配置     | 文档类型默认开启                         |
| 宽度、配色、模板、集成、Journal 等显示项 | 不进入本入口新配置；保留其他页面的原配置 |

迁移通过系统类型或工作区属性定义解析旧 ID，兼容 `system:*` 与 `property:*`，不按可改名的属性文字匹配。存在完整旧配置时，属性缺席视为关闭；只有能确定旧版本未提供该属性时才使用新默认值。

已有合法名称／时间排序及方向保留；无法表示的旧排序迁移为“最后更新时间 · 最新在前”，并以一次轻提示说明设置已调整。旧分组能对应新语义时保留，不支持时改为“不分组”。不能继续保留失效字段并悄悄使用另一种比较器。

显示偏好沿用当前主列表本地保存方式，区分工作区和视图模式；新增账号隔离并审查旧键迁移，避免同一浏览器切换账号后继承他人配置。未登录的本地 Workspace 使用独立本地身份。跨设备同步不在本期新增承诺内。

## 7. 侧栏排序入口与根目录扩展

本节以当前文件夹与资源目录实现为开发和验收基线，保留现有合法位置及多位置规则。已确认的入口调整直接在当前模型上完成，不以未来页面树为前置条件；建议的根目录扩展另行分期。

### 7.1 现有能力必须保留

- 文件夹菜单有名称正序、名称倒序、手动排序，作用于该文件夹的直接子项，普通文档与原生文件共用比较规则。
- 新文件夹共享默认值为名称倒序，历史文件夹没有该字段时保留手动顺序；用户个人选择优先。
- 名称排序是个人显示偏好；在线工作区保存在 Userspace，按实例、账号、Workspace、文件夹隔离。本地 Workspace 使用个人 settings。
- 同层拖动属于真实目录重排；自动排序下会提示切换为手动，成功后提供撤销。服务端检查目录版本、原顺序、同父级和权限，不改写不可见节点的槽位。
- 根目录文件夹之间可拖动；根目录未归档页面和原生文件没有统一手动排列模型。

### 7.2 已确认的文件夹行内排序入口

排序按钮放在侧栏每个文件夹名称所在行的右侧，与新建“＋”并列，顺序为“＋、排序、更多”。使用现有图标体系中的排序图标，点击后直接打开三项选择，不要求先右键或进入更多菜单。

```text
⌄ 📁 Infinimesh       [＋] [⇅] [⋯]
    📄 文件 A
    📄 文件 B
```

可见性与反馈：

- 文件夹展开时，排序图标常显；文件夹收起时，在行悬停或行内键盘聚焦时显示。菜单打开期间保持按钮可见。
- 无悬停能力的触屏设备保留可点击入口，不能要求用户先触发 hover。复用现有图标按钮、点击区域及焦点样式。
- 悬停或键盘聚焦显示提示“排序此文件夹内容 · 当前：手动排序”，当前模式变化后同步替换为“名称正序”或“名称倒序”；无障碍名称包含文件夹名、作用范围及当前模式。
- 点击直接显示“名称正序、名称倒序、手动排序”，当前项明确打勾；支持键盘打开、选择、Esc 关闭及关闭后焦点返回。
- 点击排序按钮或选择菜单项不触发文件夹展开／收起、打开资源、新建或拖动。菜单打开本身不改变排序。
- 只读成员仍可调整个人名称排序；加载、暂不可用和错误反馈沿用现有排序状态，不因行内入口而放宽目录重排权限。

该按钮只控制对应文件夹的直接子项，保留现有名称比较、个人偏好持久化、手动重排、版本检查和撤销行为。右键菜单继续作为补充入口，两个入口复用同一选项组件与状态，不能形成两套排序实现。

“文件”标题右侧的排序入口只用于根目录，属于下一节的建议扩展。本次不能把某个文件夹的排序按钮放到该标题上，也不能显示一个尚无根目录排序能力的可点击按钮。

实现主要涉及 `packages/frontend/core/src/desktop/components/navigation-panel/nodes/folder/index.tsx` 的行内操作和排序菜单；按需调整 `tree/node.tsx` 及既有样式。复用现有 `FolderNode`／`FolderSortingStore`，不为入口位置变化新增后端协议或排序存储。

### 7.3 建议的根目录扩展

在侧栏“文件”标题旁提供排序入口，先为根目录增加名称正序、名称倒序的个人显示能力，将目录、根页面、根原生文件合成同一受权兄弟节点序列后比较。统一排序不改变资源位置，也不将不可见目录中的资源误判为根文件。

主列表和侧栏分别保存设置。第一阶段仅控制根目录；已有子文件夹偏好与默认值保持不变。若后续需要“应用到全部子文件夹”，应增加明确的继承和覆盖协议，不在本次默认覆盖用户已有设置。

根目录现有显示方式作为兼容选项保留并明确命名。不得将简单前端拖动包装成“混合手动排序”：只有为所有真实根资源建立合法的稳定位置身份、持久顺序和受权原子重排后，才能开放此能力；不能创建隐藏目录实现它。

本阶段不新增文件夹按更新时间排序，避免把子孙文件更新时间或数据库技术时间冒充文件夹更新时间。若未来需要，另行定义目录时间语义。
