# Workspace 原生页面树开发方案

状态：页面唯一容器 v1 的历史开发契约；独立候选实现与验证见[执行记录](workspace-page-tree.execution.zh-CN.md)。决策日期：2026-10-08；源码基线复核与方案更新：2026-10-09。

2026-10-09 用户确认保留文件夹与页面两种容器，当前开发入口改为[双容器开发方案](workspace-resource-tree-dual-container-development.zh-CN.md)。下文“独立文件夹退出”“页面是唯一容器”“旧文件夹全部转页面”及对应迁移／验收预期被新方案覆盖；其余不冲突的唯一归属、内容、授权、审计及验证规则继续适用。下文保留用于解释 v1 设计及实现，不作为双容器 v2 的现状说明。

Workspace 将使用 BlockSuite 格式的 LocalMind 原生页面组织资源。页面既可以编辑正文，也可以作为父节点包含子页面、白板、Office 和普通文件。独立文件夹退出 Workspace 新建和导航入口；旧文件夹转换为同名原生页面。旧侧栏链接关系退场，被指向的资源本体只保留一份。

本方案记录 Workspace 页面树 v1 的目标契约，供理解前后端、编辑器、AI 工具和迁移边界使用。独立 worktree 的实现状态以执行记录为准；它不表示主线或业务运行环境已经切换，也不构成执行数据库迁移或部署的指令。

## 1 已确认的范围

| 编号 | 产品规则                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------- |
| D01  | Workspace 是最外层根节点；其下允许原生页面及各类独立资源。                                         |
| D02  | BlockSuite 原生页面是唯一可包含下级的资源类型。白板、Office、PDF 和普通文件首版作为叶子节点。      |
| D03  | 一份资源在主页面树中只有一个父级或一个根位置；移动不复制资源，不改变资源 ID、正文和历史。          |
| D04  | 原生页面具有真实 BlockSuite 正文；不以空壳文件夹加一个页面图标冒充页面。                           |
| D05  | 侧栏子项来自持久化归属关系，不再通过正文引用索引推导。                                             |

| D07  | 旧文档链接不自动转换成父子关系，不产生副本；未归入目录的资源本体保留在根层。                       |
| D08  | 正文普通引用、网址、反向链接和收藏保留其内容或导航用途，不决定归属。                               |
| D09  | 侧栏创建子页面与正文创建子页面使用同一领域行为；删除、恢复、排序和移动也必须跨入口一致。           |
| D10  | OfficeRevision、WorkspaceFile 及其 Blob 继续保存各自内容；层级调整不把它们转换成 BlockSuite 文档。 |
| D11  | 本期改造 Workspace。Project 内部文件树、成员规则、编辑租约和显式发布边界保持既有契约。             |

“旧链接仅保留本体”在本方案中指：停止展示和执行旧侧栏链接关系，保留被指向的同一资源，不保留重复树节点。迁移不批量删除用户正文中的文字链接、嵌入块或同步引用，也不按标题合并不同 ID 的文档。

本期不增加多父级、快捷方式节点、自动双向同步、白板容器、Office 容器或 Project 页面树。不重写编辑器，不建设另一套 Office 存储，不把跨 Workspace 的移动混入同 Workspace 归属调整。

## 2 设计依据和现状

### 2.1 wolai 的可复用行为

wolai 的[页面说明](https://www.wolai.com/wolai/iLJdcXJp8nByXA8KyWDCmN)定义了页面与子页面的父子关系，支持侧栏新建以及正文命令创建子页面。[页面引用说明](https://www.wolai.com/wolai/doMqLaba4V76PByjJXacSc)将层级与引用分开。[页面选项说明](https://www.wolai.com/wolai/4TsNd1GmGB3RYbahUZy1bz)区分“移动到”成为子页面与“嵌入到”形成引用。

LocalMind 采用这套归属与引用分离的交互原则。以下关于原生文件、权限、回收、迁移和技术实现的规则属于 LocalMind 的设计，不视为 wolai 内部实现或完整行为的复刻。

## 3 用户交互

### 3.1 侧栏和位置

页面树展示真实资源，页面节点可展开，其他节点显示对应格式图标。点击原生页面打开其正文，点击 Office 或普通文件继续进入现有编辑器、预览或文件视图。展开与打开是独立操作，键盘可分别完成。

Workspace 和原生页面旁的「＋」复用统一创建菜单：页面、白板、支持空白创建的 Office 和文本格式、上传文件；根层保留既有模板入口。菜单清楚显示目标 Workspace 和父页面，不再出现“新建文件夹”“添加链接页面”。PDF、图片、音视频按现有格式上传。

| 动作             | 结果                                                  |
| ---------------- | ----------------------------------------------------- |
| Workspace 新建   | 资源的父级为根                                        |
| 页面 A 下新建 B  | B 绑定 A 为唯一父级，新资源及位置共同完成后才提示成功 |
| B 拖入 A         | B 及其后代随归属一起移动，旧位置消失                  |
| 拖到同级上下间隙 | 调整同级排序，不改变内容                              |
| 移动到根目录     | 修改唯一父级为根，保持资源身份                        |
| 在 A 中引用 C    | 只改变 A 的内容，不移动 C，不将 C 添加到 A 的树子项   |
| 收藏或从搜索打开 | 仍打开原资源，不创建第二个树位置                      |

拖放反馈使用“移动到”，并展示目标；禁止投放到自身、后代、非容器、其他 Workspace 或无权目标。拖放失败恢复原显示并报告原因。提供“移动到…”对话框，覆盖键盘、触屏及无法拖放的情况。

侧栏、面包屑、位置选择器、搜索位置和主页列表读取同一归属。面包屑只显示有权读取的祖先，不通过根层降级或错误提示泄露隐藏路径。全局搜索和直接授权入口可以打开可访问资源，但不因此伪造主树根位置。

复用现有手动排序和名称排序规则：名称排序属于显示偏好；手动排序更新持久顺序。拖动同级节点后切换到手动排序，并使用既有带版本的撤销机制。根层和原生页面均支持一致行为。

页面容器行沿用现有「＋、排序、更多」顺序，排序菜单保留名称正序、名称倒序、手动排序。展开时按钮常显，收起时在悬停或键盘聚焦时显示，触屏入口可达，菜单打开期间保持可见。行内与右键入口复用同一状态；操作不误触展开、打开页面或拖动，关闭后焦点返回。只读成员可切换个人显示排序，真实重排仍须组织权限及版本检查。

文件夹转换后保留共享默认排序和个人覆盖值，不因节点类型或 ID 变化重置顺序。根层排序有独立偏好，不与主列表排序共用键；只有根节点身份、持久顺序和受权重排全部实现后，才开放根层手动排序。

### 3.2 父页面正文

原生页面可以同时包含文字、表格、图片等正常块，以及子页面入口。正文命令“子页面”创建真实 BlockSuite 文档，建立归属，再在父页插入具有明确子页面语义的入口块。入口不是旧 `LinkedPage` 的改名。

父页面还提供由页面树派生的直属资源列表，包含子页面、白板、Office 和普通文件，避免只有侧栏可见的下级。列表不把文件内容内嵌到父页面，也不要求所有文件都有正文块。

入口块只保存目标资源身份及展示位置；不保存一份可独立修改的 `parentId`。渲染前验证目标确实属于当前父页并检查权限。移动后，旧父页的入口失效或被清理，新父页列表立即显示；延迟的正文清理不能把资源移回去。

首版明确以下编辑器边界：

- 在同一页面内调整入口块排版，不改变资源归属；侧栏顺序仍由页面树顺序控制。
- 跨页面拖动子页面入口使用领域移动命令；普通复制粘贴不能隐式转移归属或生成副本，粘贴为普通引用时明确展示引用样式。
- 在子页面入口上删除，进入与侧栏相同的回收确认；普通正文引用的删除只删引用。
- 原始正文更新、Markdown 导入、AI 替换正文、内容历史恢复和 CRDT 撤销，不得仅凭入口块增删创建、移动或回收资源。直属列表保证未显示入口的真实子项仍可发现。
- 结构操作的撤销调用带版本检查的移动或恢复命令；不依靠父页面本地内容 Undo 恢复旧父级。

子页面入口与归属写入不能保证同一事务时，以归属为准，用持久化、可重试的投影任务补入口；不得用后台扫描正文来重建归属。

### 3.3 类型和复制

“容器”由文档的持久类型决定，不能根据当前打开的是 Page 视图还是 Edgeless 视图临时改变。沿用现有文档模式元数据时，改变持久模式必须进入统一校验：有任何尚未永久删除的后代或恢复依赖时，不允许将容器改成叶子白板。临时查看方式切换不改变类型。

扩展现有 `primaryMode` 写入和元数据事务，在同一提交边界内检查后代及恢复依赖并记录真实模式变化的更新事件。重复设置相同模式、权限或结构冲突不推进更新事件；不能另建只在 UI 生效的容器标记或绕过当前类型映射。

“创建副本”首版复制当前资源自身，分配新 ID；页面正文中的子页面入口不得把原子页面绑定给副本。副本不自动复制下级，菜单或确认文案明确“不包含子项”，入口按普通引用处理。递归复制整棵子树另立能力，不复用单资源复制来隐式实现。

### 3.4 状态和大树

每层子项独立加载、分页和去重；不能将第一页当作完整子树。折叠状态与选中状态按稳定节点 ID 保存，移动后尽量定位同一节点。切换账号或 Workspace 时取消旧请求，迟到响应不能写入新作用域。

覆盖首次加载、空页面、无权限、请求失败、保存中、重复点击、版本冲突、资源已回收和连接中断。被拒绝的操作不得静默创建根资源或同名副本。目录深度不得超过现有授权路径的 64 层限制；迁移遇到超限结构必须报告，不能截断。

### 3.5 资源属性、分组与列表偏好

Workspace 主列表及卡片继续使用标签、创建者、更新、文档类型四项组合属性。创建与更新的人、时间分别来自同一事件；类型依据持久模式、Office kind 或 MIME，不靠标题扩展名推测。父页直属资源列表复用现有资源行、元数据及权限读模型；侧栏保持紧凑，不要求在每个树节点铺开四项属性。

主列表排序保持 `title | createdAt | updatedAt | documentType` 与独立方向；重复选择字段不翻转方向。复用公共自然比较、空值末尾、稳定复合身份和排序版本，不能将不同资源类型的第一页拼接后称为全量排序。侧栏容器继续使用名称／手动排序，不因复用读模型而增加未定义的排序选项。

主列表按标签、创建者、创建日期、更新日期、类型分组的能力保留，多标签资源可以显示在多个组，但选择、数量和批量操作按同一资源身份去重。这属于列表展示，不生成多个父级或树节点。原生标签继续使用 Workspace 根文档标签字典和既有成员关系；退出主树的是旧 tag/collection 放置节点，不是资源标签、筛选或集合本身。现有自定义属性及集合入口仍按各自支持范围工作，不据此宣称所有旧文档入口已支持原生资源。

保留主列表 `allResources:v1` 偏好及实例、账号、Workspace、视图隔离，尊重显式关闭项、排序方向和分组。根树、页面容器和正文直属列表使用各自作用域；既有个人设置不由树迁移覆盖，也不新增主列表偏好的跨设备同步承诺。

## 4 资源身份与唯一归属

### 4.1 单一权威来源

优先在既有组织服务和 Workspace 目录存储上演进新的页面树契约。当前目录为 Yjs 表；本期不在 `DocRecord`、OfficeState 或 WorkspaceFileState 再增一份独立可写的父级。若后续实施因事务约束必须更换物理存储，应先修订本节并完成一次性权威切换，不允许两套目录长期分别写入。

以下是目标领域形状，不是已生成的 GraphQL 类型或已存在的数据库字段：

```ts
type WorkspaceTreeResource = { kind: 'doc'; resourceId: string } | { kind: 'office'; resourceId: string } | { kind: 'file'; resourceId: string };

type WorkspaceTreeNode = {
  nodeId: string;
  workspaceId: string;
  resource: WorkspaceTreeResource;
  parentNodeId: string | null;
  order: string;
};
```

文档类型、标题、内容版本和生命周期从各自资源服务读取；页面、白板共用 doc 身份，并有可校验的持久模式。`nodeId` 与资源 ID 是不同概念，父级只接受当前 Workspace 内的节点 ID；API 必须使用明确字段，不能让同一个字符串有时指文件夹、有时指页面文档。

所有尚未永久删除的资源，包括根层和已回收资源，均有唯一归属记录。根位置显式为 `null`；过滤查询未返回某节点，不等于它在根目录。永久删除后保留必要的墓碑、迁移映射和审计证据，拒绝旧客户端复活旧记录。

### 4.2 服务端不变量

1. `(workspaceId, resource.kind, resourceId)` 最多对应一个有效节点；同名不同 ID 的资源互不合并。
2. 节点只能指向当前 Workspace 的真实资源；Office 与文件不得伪装成 doc。
3. 非根父级必须是真实原生页面，存在且允许当前操作；禁止自环、祖先环和超深路径。
4. 资源创建、归属创建与结果回执必须协调，不产生成功但找不到资源或只存在目录空壳的结果。
5. 移动整个子树只改变顶层移动节点的父级和必要顺序，后代身份和内部边保持。
6. 排序键沿用 fractional indexing，并使用稳定 ID 作同键顺序兜底；版本冲突必须显式处理。
7. 内容、标题及历史读取不再隐式改变层级；正文引用索引仅服务引用相关功能。

Yjs 表没有 SQL 唯一约束，不能只在前端先查后建。在线写入必须复用 Workspace 级组织变更锁和最终图校验；确定性节点身份、迁移映射唯一键以及条件版本更新共同阻止重复和竞态。所有直接同步写、API、AI 和后台导入入口都必须经过等价校验。

### 4.3 版本和持久操作

每次树变更携带契约版本、期望树版本和请求键；权限版本也参与前置条件。根、父页面及目标资源在锁内重新读取，不能依据客户端先前计算的后代集合提交。

回执记录 actor、Workspace、资源身份、原父级、目标父级、变更前后版本、请求指纹和结果，不保存不必要正文。相同请求键和相同参数重放返回原回执；不同参数拒绝。事件在事务提交后发布，刷新树、资源列表、编辑器子项、搜索位置和面包屑。

BlockSuite、目录 Yjs 与原生资源状态不一定属于同一个物理事务。实施时先证明现有事务覆盖范围；无法原子覆盖的创建和迁移使用持久操作阶段与可恢复补偿。未完成对象保持受权的处理中状态，不对普通列表宣称成功；重试绑定原 ID，不新建同名副本。任务有租约、过期接管、重试上限和可审计终态，不能只在内存保存进度。

树查询、迁移预检和回执查询复用存储适配器 `observe`／`getDocReadOnly` 的权威读取路径，不能为了读取而压缩文档、写快照或获取组织变更锁。涉及多个读取的一致快照显式复用同一观察边界；已有事务内沿用该事务并读取自己的写入，不另套一个假定可以重置隔离级别或超时的事务。

同步广播沿用当前网关边界：socket 发现等可能等待 Redis 或其他节点的操作在数据库事务及授权锁外完成，准备好候选连接后在锁内检查实际接收者权限。新树刷新事件不将网络发现搬回组织锁内，也不能为了缩短锁而只依赖发现时的旧授权。

### 4.4 保留资源更新事件语义

复用当前 BlockSuite `displayUpdateEvent` 中的 `{ at, actor, by }` 原子事件，以及原生状态的 `lastUpdatedAt`、`lastUpdatedBy`、`lastUpdateActor`、`lastUpdateEvent`。列表按既有读模型展示，不将目录版本时间、数据库技术更新时间或接收同步包时间拼接成新的“最后更新者／时间”。旧协议中的 `updatedAt` 字段不因此被静默改义。

实际内容保存、重命名、标签增删及持久主模式改变继续记录真实事件；内容历史恢复沿用本次恢复写入的新修订语义。移动、重排、回收、回收恢复、权限变更、归属迁移和显示偏好不推进资源的可见更新事件；无变化、失败、冲突和幂等重放同样不推进。创建证据与不可变修订保持原样，未知作者保留未知，系统事件明确标记系统。

当前文档 `afterTransaction` 会观察本地 blocks 改动，服务端 writer 也维护更新投影。补齐或清理派生子页面入口时，必须区分真实正文编辑与结构投影维护：用户在正文创建、编辑入口按内容变更记录，后台因移动或迁移维护入口不应刷新父页或子资源的可见更新时间。优先使用不改正文的派生列表；确需维护块时，由受信任的内部事务来源或投影上下文识别，UI、writer 与重试路径一致适配。不得提供可由任意客户端声明的免记账参数，也不得事后写回旧事件来覆盖并发真实编辑。

文件夹转换产生的是新页面，单独记录迁移来源和本次真实创建证据；原有子资源不被改成迁移执行者或迁移时间。复制、上传及 Project 发布的新独立副本继续使用本次真实创建者与时间，源作者只保留在来源证据中。

## 5 权限与同步

### 5.1 页面内容与组织权限

父页面成为容器不自动授予它的读者对子资源的全部编辑权。沿用 Workspace、资源自身 ACL 和目录策略的交集；目录策略迁移为页面容器策略。新建子资源继承目标位置限制，既有资源移动保留其自身 ACL。

| 行为             | 必须检查                                                                         |
| ---------------- | -------------------------------------------------------------------------------- |
| 读取树或直属列表 | Workspace 访问、可披露的路径和目标资源读取权                                     |
| 新建子资源       | Workspace 对应创建权、父页面读取权和目标容器创建权；插入正文入口另查父页内容写权 |
| 移动或排序       | 源与目标组织权、资源状态、子树结构版本及全部受影响授权约束                       |
| 重命名           | 资源自身更新权，不以父容器组织权代替                                             |
| 回收或恢复子树   | 对本次涉及的每种资源逐项检查相应生命周期权限                                     |
| 修改容器策略     | 既有权限管理权限，不能由普通正文编辑隐式触发                                     |

旧 `canCreateFolder` 表示创建分类容器，不能直接当作创建任意内容文档的权限。迁移为新建子页面能力时仍需满足文档创建条件；旧 grant、事件及凭据按其原始语义保留。

移动可能改变祖先权限。提交前计算是否产生访问范围变化；普通移动不能偷偷扩大源资源的授权。可以保持现有有效限制的移动正常提交；需要扩大权限的情况进入既有显式权限管理流程或返回明确错误。AI 不获得修改或批准权限的额外能力。

公开分享父页面不自动公开全部后代；本期沿用现有分享契约。对于旧文档直链或直接授权，继续按实际资源 ACL 提供访问，不泄露不可见祖先，不伪造根层位置。

### 5.2 在线与本地适配

在线 Workspace 的结构命令统一进入服务端组织服务。即使用户有整表同步能力，也不能通过旧 `folders` Yjs 增量绕过契约版本、唯一父级或父类型校验。切换后的写入和重连同步都需识别旧契约，拒绝旧文件夹、链接放置和未经授权的结构复活。

纯本地 Workspace 继续保留原生页面和白板的 local-first 能力，使用相同不变量的本地适配及可恢复的本地迁移。纯本地原生 Office 和文件离线同步不在本期新增范围。

在线离线期间，已可用的正文编辑维持原能力；结构操作首版明确禁用或排为待服务端确认，不将乐观显示当作归属已保存。重新连接后先校验契约、树版本和实时 ACL，冲突保留待处理结果，不能以 CRDT 最后合并自动选父级。纯本地上传到服务器时同样经过协议协商和全图校验。

## 6 回收与恢复

### 6.1 回收页面子树

原生页面“移至回收站”默认包含其归属子树，不包含正文引用的外部文档。确认框展示可授权披露的影响范围和资源类型；过大的子树使用有界预览和明确的未展开提示，不以截断列表作为执行全集。

服务端在同一组织锁及生命周期协调边界内确定完整子树，并验证当前权限和版本。无法操作其中任一必要资源时整项拒绝，不先删除父页再留下活动孤儿。错误不得披露无权读取的子项标题或数量。

复用既有回收 claim、manifest、版本和不可变回执机制，将“文件夹回收声明”升级为“页面子树回收声明”。此前已单独回收的资源不能因父页面恢复而复活。旧声明身份与新节点通过迁移映射关联，不覆盖旧审计事件。

### 6.2 恢复和永久删除

恢复保留 ID、内容、历史及原内部层级。原父级可用且有权时恢复原位；父级在回收站、已删除或无权限时，提示先恢复父级或显式选择新目标。不得静默落到根目录。跨父级恢复也遵守权限不扩大和树版本检查。

永久删除仅在已回收状态下开放，并以独立确认执行。依既有各类型服务处理实际资源删除、引用保留、Blob 审计保留和失败重试。含尚未完成恢复依赖或不一致 claim 的操作必须先协调，不能物理删除父节点后丢失子项恢复路径。

回收中的资源禁止作为新父级，禁止通过普通移动逃出回收状态。恢复、删除、保存、移动和撤权并发时，只有满足当前版本与状态前置条件的请求可以提交。

## 7 API 与各入口接线

### 7.1 领域命令

以下为拟定的能力边界，实施时按仓库既有 resolver 和 service 风格命名并生成协议：

| 能力         | 关键输入                                       | 结果                               |
| ------------ | ---------------------------------------------- | ---------------------------------- |
| 列出直属资源 | Workspace、父节点或根、游标、页大小            | 授权节点、能力、树版本、下一页游标 |
| 创建资源     | 类型、父节点、内容或上传身份、期望版本、请求键 | 资源和节点身份、最终位置、持久回执 |
| 移动资源     | 源节点、目标父节点、相邻节点、期望版本、请求键 | 新位置和版本、无副本的移动回执     |
| 重排直属资源 | 父节点、明确节点顺序或锚点、期望版本           | 新顺序、版本、可检查的撤销信息     |
| 回收与恢复   | 节点、动作、期望版本、必要的恢复目标           | 类型化影响、生命周期结果和回执     |

游标绑定父级、排序和授权上下文。权限改变或结构变更使游标失效时返回可重载的冲突，不混合旧新快照。错误至少区分权限拒绝、父类型不符、循环、版本冲突、已回收、协议退役及迁移未完成。

共享 `.gql`、服务端 schema、生成客户端和所有消费者必须同步更新；生成命令沿用仓库流程，不手工改生成产物。

### 7.2 前端和编辑器

复用 `OrganizeService`、目录权限 store、`WorkspaceResourcesService` 和现有导航节点抽象，逐步退出依赖 folder 类型的分支。标题和图标依旧读取资源本身，资源 ID 保持现有路由。字段或类名是否重命名按必要范围决定，不为改名大规模重构。

`watchRefsFrom`、`DocLinks` 及引用索引保留给正文引用和知识关联；从侧栏结构路径移除。`showLinkedDocInSidebar` 退役或迁移为新的树显示设置时不得改变资源数据。收藏、标签、集合不再作为主归属树节点，但保留既有各自入口和数据。

网页、Electron、移动导航投影、导入、模板、日记新建、资源位置选择器以及 Project 发布到 Workspace 的目标选择器都需清点。Project 侧仅更新外部 Workspace 目标适配，不修改其内部目录。

### 7.3 内部 AI 和公开 MCP

内部 Workspace AI 的创建、移动、组织、回收工具与 UI 共用领域服务，参数明确绑定资源身份和目标页面，不能继续通过创建正文链接假装整理完成。工具名保持 `workspace_*`，与 `project_*` 按会话隔离。

旧 `workspace_folder_*` 中的创建链接、保留其他放置等语义不能原名原版本改成新行为。为新契约更新工具 schema、描述、完成证据和冻结快照；旧待执行任务在切换前排空或按既有退役脚本收敛，不能自动升级授权。成功证据包含真实父级及版本，文字回答或模型判断不能代替操作回执。

公开 MCP 已有 10 个直接资源工具和独立授权契约，本方案不自动发布新工具或扩大旧凭据。已迁移 Workspace 上，不兼容的旧 folder 写操作返回明确退役错误；同请求已完成的回执继续可查询。旧 folderId 不能静默解释为新 pageId 并执行新行为。仍兼容的按 ID 读取、内容更新必须保留原 scope、ACL 和冻结边界。

若上线要求公开 MCP 同时支持新页面位置，必须另行更新其 source of truth、协议版本和明确授权，再纳入同次切换验收；不能仅修改服务内部含义完成升级。

## 8 旧数据迁移

### 8.1 映射规则

| 旧数据                           | 迁移结果                                                                    |
| -------------------------------- | --------------------------------------------------------------------------- |
| 正常文件夹                       | 创建同名真实 BlockSuite 页面，记录 oldFolderId 到新 nodeId/docId 的稳定映射 |
| 嵌套文件夹                       | 转换后的页面保持原父子顺序；空文件夹也转换为空白页面                        |
| 单一文件夹位置的资源             | 本体不变，唯一父级改为该文件夹对应页面                                      |
| 无文件夹位置的资源               | 本体保留在 Workspace 根层，创建显式根归属记录                               |
| 文档正文中的链接、嵌入、同步引用 | 正文保持；停止将引用投影为侧栏下级，不据此设父级                            |
| 多文件夹位置的同一资源           | 保留一份本体和一个经过验证的目标位置，删除其余活动放置记录                  |
| 旧 tag/collection 目录节点       | 从主树退场，保留标签、集合本身及原专属入口                                  |
| 旧 Office 的 doc 放置            | 依据真实身份映射为 office，不创建新 Office，也不丢失旧位置权限              |
| 已回收文件夹及资源               | 保留回收状态、原层级和恢复依赖，转换映射及声明；不自动恢复                  |
| 指向不存在或已永久删除资源的记录 | 清理无效活动节点，保留必要证据，不创建占位文档                              |

文件夹是组织元数据，没有可伪称为原文档的正文历史；新页面记录迁移来源和创建证据。原 folderId 不冒充 docId，旧引用、收藏、排序偏好和有效内部位置记录通过稳定映射更新；旧审计和已冻结任务参数保持不可变。

保留既有文档标签、原生标签成员关系及标签字典，保持创建信息、成对更新事件和真实类型；不因为新增父页而触发原生修订或改写旧资源状态。原生标签仍指向同一资源 ID，不能重新绑定到转换后的父页面。

共享默认排序随容器映射迁移。个人排序位于在线 Userspace 或本地个人 settings，由所属用户在偏好加载后按 `oldFolderId → nodeId` 幂等迁移或兼容读取；Workspace 管理员的结构迁移不批量改写其他人的私人配置。新键已有用户选择时优先保留新值，不能被迟到迁移覆盖。保留实例、账号与 Workspace 隔离，主列表 `allResources:v1` 配置不参与文件夹 ID 替换。

### 8.2 多位置与权限

迁移清单按资源 ID 分组，不以名称合并。只有一个有效原目录位置时保持该位置。有多个位置且权限等价时，按原完整目录路径的手动排序键、各级稳定 ID 及放置 ID 确定一个目标，结果写入不可变计划，重跑不能重新选址。

若多个位置权限不同，先计算迁移前有效权限约束，并验证新唯一位置与资源策略能完整保留。不得把资源移到最宽松目录或根目录来消除冲突。可在既有授权模型中无损表达时保存等价限制及证据；无法证明等价则标记该 Workspace 为需要解决的迁移冲突，切换前由管理员确定映射及必要策略。不自动丢资源、扩大权限或任意减少已有用户的可访问内容。

迁移检查使用授权服务和完整资源清单，不依据某位用户的过滤视图决定“没有位置”。目录有引用但权限受限的资源不能误判成根资源。

### 8.3 持久迁移与切换

为迁移新增必要的 Prisma 模型和时间排序迁移，保存 Workspace、契约版本、计划指纹、源版本、映射、阶段、租约、重试、错误及检查结果。映射 `(workspaceId, oldFolderId)` 唯一；计划内容与审计证据不可被重试覆盖。具体模型名在实施时按已有 model 约定确定。

每个 Workspace 独立推进，阶段至少包括：预检、已冻结、应用中、校验中、已切换、需处理、可重试失败。worker 租约到期可接管，写入以计划版本和租约条件更新；“取消”不能把已切换数据当成未迁移状态。

切换顺序：

1. 只读预检，核对运行 schema 与资源显示版本，再完整分页清点正常和回收资源、目录、重复位置、权限、旧 Office 身份、标签、更新事件、默认排序及不可见路径，生成有界报告和可持久遍历计划。
2. 备份数据库、目录和文档快照、原生 Blob 引用及必要运行版本证据，并在隔离环境验证恢复。
3. 暂停所有相关结构和生命周期写入来源，包括 UI、AI worker、MCP、导入和同步；已进行的操作先完成或按旧契约退役。影响参与迁移的类型、ACL 和元数据写入也须冻结或以版本重检阻止漂移。
4. 重新核对源版本，持久化冻结后的计划；任一变化使旧计划失效，不能带漂移继续执行。
5. 按稳定映射创建真实页面、迁移根及子节点、权限和回收依赖。处理中对象不暴露为另一套可写树；每批有 checkpoint，重试只补缺项。
6. 验证完整性、身份、正文与元数据保真、权限等价、回收依赖、唯一性、无环、层数及全部入口兼容；个人排序映射由各自账号验证，不以管理员视图代替。
7. 原子切换 Workspace 契约版本和读写入口，发布刷新事件；阻止旧客户端及旧任务重新写入 folder/link 结构，再恢复新契约 worker。
8. 保留只读迁移证据和受保护备份，活动层不继续双写旧树。按既有保留策略清理，不能本轮随意永久删除备份或用户数据。

大 Workspace 采用分批持久执行，但切换单位仍是完整 Workspace。到达分页或数量上限时明确失败或继续有界遍历，不能以截断结果宣布成功。

当前依赖迁移为 `packages/backend/server/migrations/20261009000000_workspace_resource_display/migration.sql`，历史回填入口为 `packages/backend/server/scripts/backfill-workspace-resource-display.ts`。按迁移链先完成该基线，再应用页面树新增迁移；不能因本地源码或隔离验证通过而假定真实库已升级。沿用既有回填规则，缺少可信更新证据时保留未知，不用页面树迁移时间补齐。后续若基线继续演进，以实施前实际 schema 复核，不硬编码迁移总数。

### 8.4 验证与回滚

正常及回收资源按类型核对 ID 集合；迁移前已有资源不得多出副本或无故消失。迁移前后的 BlockSuite 内容、Office 修订、文件 Blob 证据保持，新增内容仅限文件夹转换页面及必要的派生入口。正文引用不被清洗。

逐资源比较标签集合、创建证据及可见更新事件，另核对默认排序与个人偏好映射；结构迁移不应造成旧资源按“最后更新”整体置顶。页面树回滚不得删除此前已上线的资源显示字段、原生标签或个人设置；备份和恢复版本必须覆盖这些已有能力。

切换前失败可按 checkpoint 修复，或在冻结状态恢复到备份；迁移创建且未承接新用户写入的对象依据映射安全撤销。不得按标题批量删除。

切换后已有新写入时，不允许只关闭开关重新使用旧树。优先向前修复；必须回滚时再次停写并备份新状态，采用经过验证的完整恢复或逆迁移，协调全部内容、权限、生命周期和事件状态，防止丢失切换后的用户数据。

- `packages/common/graphql/src/graphql/workspace-directory.gql`、`workspace-native-resources.gql`、`workspace-lifecycle.gql` 和相关生成文件：新协议与兼容结果。
- `packages/common/graphql/src/workspace-resource-display.ts`：复用真实类型、稳定资源身份、排序与更新事件契约，不复制一份树专用实现。
- `packages/frontend/core/src/modules/organize/`、`modules/db/`、`modules/workspace-resources/`、`modules/doc/`：共享状态、领域调用和本地适配。
- `packages/frontend/core/src/components/root-app-sidebar/`、`desktop/components/navigation-panel/`、`components/native-files/` 及移动投影：用户操作和状态反馈。
- `packages/frontend/core/src/components/explorer/resource-preferences.ts`、`components/native-files/resource-metadata.tsx`、`resource-groups.ts` 及现有资源行：保留主列表偏好和分组，复用直属资源列表展示；`modules/organize/stores/folder-sorting.ts` 适配容器身份映射。
- `blocksuite/` 及 `packages/frontend/core/src/blocksuite/`：按既有注册方式实现子页面入口块、命令、渲染及撤销边界，禁止编辑器直接依赖后端实现。

## 11 验证与交付

文档阶段执行 Markdown 格式检查和 `git diff --check`，不构建镜像或同步运行环境。代码阶段按风险执行聚焦 lint、格式、类型检查、GraphQL 与 Prisma 生成、迁移及行为测试。

实现必须在 Linux 容器证明关键行为，优先复用 `localmind-affine:test`。重建前运行 `docker system df`，遵守 [Docker 开发约束](../localmind-docker-development-constraints.md)；仅运行时、打包或里程碑验证才考虑固定 `localmind-affine:local`。不得创建专属 tag 或删除持久卷。

数据库新增模型需要空库全量迁移及旧版本 fixture 升级。迁移演练至少包括真实备份的隔离恢复、已含资源显示元数据和标签的旧库升级、Yjs 目录版本升级、原生资源关联、权限对比、故障重跑和旧客户端重连。已有测试数量或 schema 生成成功不能替代 A01—A46 的行为证据。

资源显示实施记录中的后端、前端及组件浏览器验证作为既有基线引用，不计为页面树验收通过。页面树开发需回归相关显示、标签、比较器、偏好和行内排序测试，并补充真实页面树路由及迁移后的集成验证；源码完成、隔离验证、历史回填与运行部署分别记录。

实施开始后单独建立执行记录，逐项保存阶段、验收编号、精确命令、结果、容器和固定镜像、是否重建、备份与恢复证据、截图及剩余风险。敏感正文与凭据不进入报告。只有实际通过的项目才能标记完成。

上线前同步用户指南、使用提示、部署切换步骤和相关协议 source of truth。运行同步必须沿用 `yarn localmind:sync:*` 及其备份、迁移和同平台证据要求；仅编写本开发方案不执行同步、commit、push 或发布。
