# Workspace 统一资源入口、主页与回收站修复方案

状态：P0—P6 已实现并完成本轮验证；实际覆盖与产品上限见第 7 节。实施日期：2026-09-28。基线为当前未提交工作区；保留已有 CRUD、关系图、上下文等改动。

承接 [Workspace / Project CRUD 方案](workspace-project-document-crud-remediation.zh-CN.md)与[实施记录](workspace-project-document-crud.execution.zh-CN.md)。已有记录证明资源领域服务和分离入口的本地能力，不证明原生文件已经完整接入主页主列表、侧栏根目录、全局搜索和既有 Trash。本方案补齐这些交互及相关服务缺口；此前的测试数量不能作为本方案通过的证据。

## 1. 产品目标与范围

Workspace 的侧栏「＋」统一创建和上传；主页统一浏览；侧栏文件树统一组织；搜索统一查找；既有 Trash 统一恢复和永久删除。完成替代入口后删除主页独立「文件」折叠框及其重复工具条。

所有独立资源遵循同一生命周期：正常 → 移入回收站 → 恢复，或正常 → 移入回收站 → 永久删除。正常列表、编辑器菜单和删除快捷键只提供「移至回收站」；永久删除仅出现在回收站上下文，并在服务端检查资源确已回收。

统一的是用户操作与状态规则，底层仍使用各自的资源、权限、版本和编辑模型。

| 资源                         | 新增方式                   | 打开与内容操作                        | 生命周期                                 |
| ---------------------------- | -------------------------- | ------------------------------------- | ---------------------------------------- |
| BlockSuite 页面 / 白板       | 现有新建、模板、显式导入   | 原编辑器和 local-first 行为           | 同一 Trash 入口；保留文档专有能力        |
| DOCX / XLSX / PPTX           | 空白创建或原格式上传       | 现有原生 Office 编辑器、修订          | 回收、原位恢复、受控永久删除             |
| PDF                          | 上传导入；保留已有导出路径 | 原生 PDF 预览、批注和现有固定版式命令 | 与其他独立资源相同                       |
| TXT / Markdown / CSV / JSON  | 空白创建或原格式上传       | 现有完整文本编辑、版本管理            | 与其他独立资源相同                       |
| 图片、音视频、其他二进制文件 | 上传                       | 支持的预览、下载、显式替换版本        | 与其他独立资源相同                       |
| 文件夹                       | 侧栏创建                   | 文件树和目录组织                      | 接入已有目录回收、恢复、永久删除领域服务 |

文档内部的附件块、图片块属于宿主内容，删除块继续遵循编辑器撤销/历史，不将所有 Blob 自动提升为独立文件。已导入的原生 PDF/Office 与旧附件页面必须按真实资源身份识别；不能通过扩展名把旧附件页悄悄改成新资源。

本次完整范围包括共同的创建、上传、发现、打开、重命名、移动、独立复制、搜索、回收、恢复、永久删除、批量操作及状态同步。标签、收藏、集合和文档自定义属性的原生扩展、纯本地 Workspace 的原生离线同步、PDF 任意正文重排不在本次范围；已有文档能力继续保留，界面明确特定筛选的适用范围。

Project 保留自己的文件树和回收站入口；同步复用公共交互规则并做生命周期回归，不把 Project 资源混入 Workspace Trash，不改变项目任务、租约、审批和显式发布边界。

## 3. 最终交互

### 3.1 侧栏「＋」

Workspace 行与文件夹行的「＋」始终打开菜单，不再因默认文档模式而跳过格式选择。现有文档快捷键可继续按默认模式快速创建。

菜单按轻量分组排列：页面、白板、模板；Word（DOCX）、Excel（XLSX）、PowerPoint（PPTX）；「文本文件」子菜单内的 TXT、Markdown、CSV、JSON；新建文件夹；上传本地文件。PDF 和其他二进制格式通过上传进入，不提供不能兑现的「新建空白 PDF」。

选择格式后只需命名并创建，不再弹出第二次格式选择。Workspace 行默认根目录；文件夹行默认该目录；提交时重新检查目标权限和有效状态。菜单显式标注创建位置，禁止创建失败后静默落到根目录。

统一文件选择、拖入上传和重试流程，保留原格式；「导入并转换为页面」若继续保留，使用独立明确入口。支持多文件上传及逐项状态；沿用当前大小/格式限制。稳定请求键使超时重试不产生副本，同名不同文件不自动覆盖，更新已有文件必须显式选择目标 ID 与版本。

### 3.2 主页与侧栏

主页默认「全部」展示混合资源，一套行样式、一套选择状态、一套公共操作菜单。名称、类型、更新时间可比较；原生资源支持列表/卡片视图，以格式图标或现有缩略图展示。保留原有页面/白板预览和已支持的分组，缺少的字段显示合理空值，不编造大小、标签等属性。

提供「全部、页面/白板、Office、PDF、文本、其他」等类型过滤；与现有通用搜索、名称/更新时间排序协同。文档集合、标签或自定义属性筛选仍明确标注只作用于文档，不能一面显示「全部文件」一面悄悄排除原生文件。

侧栏显示所有授权可见的根资源与目录资源。全部列表按资源身份去重，目录树按合法位置展示；多位置不等于多个副本。后端返回授权后的目录/位置判定，不能因为前端看不到受限位置就将资源误判为根文件。保留树的展开、焦点和键盘导航；原生节点接入相同的改名、移动、复制、回收菜单，移动入口始终可用，拖拽复用同一受权命令。

### 3.3 删除、恢复与永久删除

正常资源菜单统一为「移至回收站」。单项、批量、行菜单、编辑器工具条和删除快捷键走同一动作；确认规则沿用现有 BlockSuite 交互。成功后从正常列表与搜索移除，打开的视图切换到回收提示，禁止继续保存。存在未保存草稿时复用现有离开/丢弃确认；跨标签页回收也要停止写入并保留冲突反馈。

Trash 展示名称、类型、删除时间及有权查看的原位置；提供单项与批量恢复/永久删除，不再按文件格式分两个回收入口。

恢复优先原位置，保留资源 ID、内容与历史版本。同名不覆盖、不新建副本。原目录已回收时引导先恢复目录或显式选择可写目录；目录已删除时允许授权用户选择新位置；来源权限已撤销时不能利用换位置绕过来源授权。多位置恢复检查全部位置，不静默只恢复其中一处。恢复失败保留原回收状态。

永久删除只允许已回收且具有对应权限的资源，显示一次明确确认及影响数量；提交携带版本与稳定请求键，重复请求返回原结果。永久删除后产品不可恢复，其他独立副本不受影响；不可变审计和仍有合法引用的 Blob 保留依既有策略处理，不宣称立即物理擦除所有字节。

文件夹作为一个可回收单元显示，用户可查看其内容。沿用目录 manifest、回收来源声明和实时 ACL；恢复文件夹不能复活先前单独删除的子资源。单独恢复子资源、原目录消失、多位置、永久删除后修复其他目录 manifest 均须回归。界面明确「从此文件夹移除」与「移至回收站」的不同影响。

从旧链接打开已回收资源时显示受权的回收状态与恢复入口；已永久删除或无权访问时给出不泄露内容的不可用提示。若展示回收内容预览，使用专用只读路径和同等 ACL，禁用保存、评论写入、AI 写入及历史恢复；不得为了预览把正常下载/编辑入口改成允许读取所有回收资源。

### 3.4 批量、搜索与刷新

混合选择时逐项计算可用动作，选区工具条说明不可操作的项。批量命令有界执行，返回成功/失败明细；仅移除成功项并保留失败项供重试，不能先提示「全部成功」。目录树的一次回收仍采用既有领域事务；跨独立资源的批量操作不假装是一个全有或全无事务。

全局快捷搜索接入原生资源 provider；主页搜索使用同一类型化结果与打开动作。文本和 Office 复用有界内容索引；无解析器的二进制仅搜元数据；扫描 PDF 不承诺 OCR。结果标明类型，索引未就绪时给出适度提示；正常搜索即时排除回收、永久删除及撤权资源。

删除面板内的常驻刷新按钮，保留既有通用刷新操作，并复用事件更新、聚焦/重连对账和可见页面轮询。失败区域就地提供重试。切换 Workspace、筛选或权限时取消旧请求，禁止迟到结果回填到新作用域；分页刷新保留已加载范围、选择和滚动位置。

## 4. 实现结构

### 4.1 类型化资源视图与动作适配

在前端既有 `@toeverything/infra` Workspace scope 下提供共享资源目录与动作服务，统一 `doc | office | file | folder` 身份、标题、格式、时间、状态、位置、版本及能力。稳定键包含 Workspace、资源类型和 ID，禁止将 Office ID/WorkspaceFile ID 强塞给 `DocRecord`。

数据仍来自 DocsService、目录服务及原生资源 API；共享层是读模型与行为适配，不另建可独立修改的资源状态或 parentId 真相来源。动作分派复用各类型已有领域服务；Page/Edgeless 内容仍由原编辑器负责，原生 Office 状态仍属于 OfficeRevision。

在线文档生命周期入口需复用 `WorkspaceOrganizationService.setDocumentTrashed` / `deleteDocumentPermanently` 等现有事务规则，必要时补内部 GraphQL 适配，避免新混合操作继续使用不带目录回收协调的直接元数据修改。本地 Workspace 保留原本地适配，不依赖不可用的在线资源服务。此接线需审查服务端调用者现有授权、回执和版本前置条件，不能直接裸露内部方法。

原生能力补为可区分的 `canRead/canEdit/canRename/canMove/canCopy/canTrash/canRestore/canDeletePermanently` 等；源于现有真实 ACL，不新设角色策略。修复 Office 页面过粗的编辑权限推导。UI 能力仅作提示，服务端提交仍重新校验；BlockSuite 当前权限差异作为兼容基线，不因操作按钮相同而扩权。

### 4.2 列表、位置与导航协议

优先扩展既有原生列表查询的类型、排序、位置、回收信息和能力投影，复用 DirectoryAccessStore 的授权目录结果。根目录查询不能只筛第一页再凭前端缺失位置判定。对已读入的文档流和分页原生流使用稳定排序键与游标合并，正确处理未读页面；禁止各取第一页后排序便宣称全局排序。大列表使用现有虚拟化设施，有界加载、取消与去重。

原位置只返回当前用户有权查看的描述与可恢复性，保留稳定 ID 和必要的目录版本；不暴露私有目录名称。普通文档、原生资源和目录的旧链接/位置依真实类型解析，同一 Office 旧 `doc` 节点与新 `office` 节点在主列表只显示一次，继续执行历史位置的权限检查。

补齐普通原生文件可重开的工作台导航；抽出当前弹窗中的预览/编辑内容，由统一打开动作消费。Office 使用现有路由，普通文档使用原路由。历史记录、搜索、侧栏、主页点击同一资源得到相同视图；重命名不改变链接身份。普通文本编辑器、Office 编辑器及 PDF 工具不因本方案重写。

### 4.3 回收与恢复接口

已有原生 `change` mutation 保持兼容，默认恢复传「原位置」语义，明确选择新位置时才发送目标和目录版本。目录回收列表及 UI mutation 复用现有组织服务，补结构化结果与权限过滤；不得另写客户端递归删除。

永久删除不能由 `canManage` 推断；直接调用接口、旧版本、重复点击、回收/恢复竞态同样受状态与权限约束。恢复需验证原位置仍有效，目标写权限不能替代来源权限；动作失败不得半恢复状态或半移动目录。

本轮不预设重建 schema 或重填全部数据。现有生命周期、原位置和修订已经有存储；仅在排序索引、审计/回执或兼容字段确实缺失时新增迁移，并验证旧数据升级。所有 GraphQL schema、operation、生成类型和消费者同步通过仓库生成流程更新。

### 4.4 AI 与作用域

UI 与内部 `workspace_*` 工具继续调用共享后端服务；「删除文件」默认回收，永久删除需要明确意图及现有确认/授权契约。资源 ID、版本、幂等、审计和来源边界不变。Project 对应工具继续经过项目执行/租约/审批路径。此 UI 整合不增加公开 MCP 工具，不扩大旧凭据或冻结任务的权限。
