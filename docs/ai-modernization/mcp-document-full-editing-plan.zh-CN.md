# LocalMind MCP 文档完整编辑与无损保留方案

日期：2026-11-04。

状态：当前模型范围的源码实施与本轮隔离验收已完成；实际范围、证据与边界见
[实施记录](mcp-document-full-editing.execution.zh-CN.md)。源码评审基线为 2c2fc997af；问题证据见
[文档改写交接](mcp-document-editing-handoff.zh-CN.md)。本方案定义 v2 产品契约；工具已接入源码，验收证据以实施记录为准，当前运行环境未变。

## 1 产品目标与完成边界

MCP 凭据对应的身份拥有某项文档操作权限，且凭据已授予对应工具能力时，应能直接、
确定地完成该操作。文档存在空段落、表格、批注、图片、引用、画布或复杂格式，
不能成为拒绝整篇文档编辑的理由。普通可逆编辑不增加逐次人工审批，不依赖模型、
BYOK、AI 会话或 delegate。

完整能力覆盖当前 LocalMind 文档模型允许的内容、结构、格式、资源、批注、元数据、
历史与生命周期操作。不能把完成空页修复、普通文本或表格支持称为整体完成。
“任意改动”指对这些模型进行合法的领域操作，不包括伪造创建历史、执行任意脚本、
绕过来源授权或直接修改内部数据库和 CRDT 存储。

交付分为两条内容引擎轨道，均须纳入能力覆盖清单：

| 资源                                | 完整能力目标                                                                           | 事实来源                                          |
| ----------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------- |
| BlockSuite Page 与 Edgeless         | 所有已注册内容块、富文本、数据库和画布元素的增删改、重排、转换，以及正文与画布并存编辑 | 原有 Yjs 文档、相关批注与领域元数据               |
| 原生 Docs、Sheets、Slides、PDF      | 通过对应原生命令引擎开放产品支持的全部编辑操作；引擎本身的能力缺口必须单独列项         | OfficeArtifact、OfficeRevision 及原生文件包       |
| TXT、Markdown、CSV、JSON 与普通文件 | 文本或结构化内容编辑、明确的文件版本替换及历史恢复                                     | WorkspaceFileState 与不可变 WorkspaceFileRevision |

本方案使用现有 Workspace MCP endpoint，作用域仍是凭据绑定的 Workspace。
Project 原生资源不属于该作用域；未来的 Project MCP 必须使用独立 project\_\* 契约、
成员权限与编辑租约，不能把 Workspace 凭据当成 Project 凭据。

文档专属分享、成员权限和所有权变更使用独立管理能力及对应实时 ACL。
内容编辑能力不隐式包含这些管理能力。Workspace 与 Project 的成员管理、全局配置、
模型配置不属于文档编辑。

目录归属继续使用目录领域服务。正文中的子页面引用不是归属关系；本方案不改变
既有“日志日期排序由用户在 UI 处理”的约定。

## 2 无损要求的精确定义

无损的默认含义是：只改变请求明确指定的语义，其余内容、结构、身份和历史证据保持不变。
删除文字、清除样式、删除行列本身可以是合法目标，但必须由请求明确表达，不能由
Markdown 无法表示某个字段而推导出来。

### 2.1 编辑不变量

1. 未触及的块、行列、单元格、画布元素保留原 ID、顺序、内容、属性和资源引用。
2. 存续文本在原 Y.Text 上应用文本与格式增量；不以新 Y.Text 替换整个已存在文本对象。
   未触及文字的 CRDT 身份和相对位置保持有效。
3. 未指定的富文本属性、行列宽度与颜色、批注状态、锚点、视图和隐藏属性保持不变。
4. 存续对象的创建证据不可改写；只维护实际受影响对象的修改信息。移动是否更新修改信息
   按统一领域规则定义，不能随入口改变。
5. 真实 no-op 不写文档增量、不改版本、块时间、目录和历史；可以记录成功操作回执。
6. 失败零业务提交；不产生部分正文、半张表格、同名副本或成功通知。
7. 文档 ID、标题、目录、资源类型、权限、引用源内容不会因普通正文编辑隐式改变。
8. 未知或暂不展开的数据原样保留；它不能阻断其他已支持对象的合法编辑。

无损不要求编辑后整个 Yjs 二进制或 OOXML ZIP 文件逐字节相同；增量、索引与容器编码
本来可能变化。验收分别检查语义、身份、未修改 CRDT 结构，以及未修改二进制资产和
原生文件包部件的内容指纹。序列化顺序变化不能被误当成内容丢失，内容丢失也不能
通过忽略属性或只比较截图来掩盖。

### 2.2 转换契约

普通 Markdown 无法完整承载表格行列身份、批注、画布、数据库 schema 和全部富文本。
因此完整编辑不能再强制执行“原生文档 → Markdown → 新原生文档”。

| 表达方式                 | 保证                                                    | 用途                     |
| ------------------------ | ------------------------------------------------------- | ------------------------ |
| 原生结构化读取与定点命令 | 对已定义语义无损编辑，服务端保留未展开数据              | 默认读写路径             |
| Markdown 投影            | 明确标记完整、部分、简化或不支持；不能冒充完整备份      | 阅读、检索、普通文字输入 |
| 原生无损包               | 原生状态、版本化 manifest、资产与批注关联足以按契约恢复 | 备份、迁移、同格式往返   |
| 跨格式导出或转换         | 先返回格式差异与损失清单；无损模式下有损即拒绝          | 用户明确要求的格式转换   |

原生无损包的引用清单只包含调用者有权读取或复制的数据。外部文档引用默认只保存引用，
不递归打包目标正文。格式包内的签名、宏、外部关系及特殊功能须由各引擎判定，
不能保证无法表达的跨格式转换也无损。

同文档读取后原样提交必须是 no-op。复制或导入为新文档时，文档及对象身份按复制契约
生成并返回映射，不能把“新副本 ID 不同”错误地计为编辑损失。

## 3 已确认问题与对应修复

| 问题                             | 源码原因                                               | 必须完成的修复                                                     |
| -------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------ |
| 清空后不可写                     | 空段落导出为换行，重建时没有段落，整树比较失败         | 原生编辑保留空块；旧 Markdown 路径定义严格、有限的空结构等价规则   |
| 可写标记与输入校验不一致         | 读取仅做往返检查，写入另有全局正则                     | 统一解析、能力判定与计划编译；可写标志和实际执行使用同一规则       |
| 代码和普通管道文字误判           | 正则不区分 Markdown 节点类型                           | 根据解析节点识别图片、HTML、表格；围栏和行内代码按字面量处理       |
| 一张表格阻断整页                 | 白名单与旧正文整页门禁                                 | 对目标操作检查能力，支持块可独立修改，不重建无关块                 |
| 表格单元格修改破坏行列身份与格式 | 原生 TableSpec 为字符串矩阵，修改时清空行列属性        | 表格原生适配器以行列 ID 定位，富文本和样式分别更新                 |
| 批注、对齐、折叠导致不可写       | Markdown 不包含属性，比较正确发现丢失                  | 原生属性适配与保留，不能把非默认属性加入忽略列表                   |
| 富文本格式范围漂移               | 导出器将格式边缘空白移出标记                           | 原生 Delta 编辑保留范围；格式转换单独验证并报告不能表达的情况      |
| 读取遗漏不可见                   | 原生已返回遗漏清单，公开结果没有完整性信息             | v2 输出覆盖范围与有界诊断；v1 不再把不完整正文作为完整读取成功返回 |
| 错误不能定位                     | catch 收敛原因，ResourceError 与严格 schema 无详情字段 | 版本化错误结构，包含操作、对象、字段、阶段和恢复动作               |
| 修改文本替换 Y.Text              | reconcile 按属性克隆目标文本                           | 在原对象应用增量，验证相对位置和批注锚点                           |

上述问题跨越接口、适配器和原生转换器。关闭结构检查或扩大白名单不构成修复。

## 4 总体架构与代码所有权

公开 MCP 适配器负责凭据、严格 schema 和结果映射；文档应用服务负责实时 ACL、
版本、操作编排、事务和回执；内容引擎负责各自原生模型的合法编辑。

调用顺序为：解析请求 → 读取权威状态 → 编译确定性计划 → 校验保留约束 →
在锁内重查授权与版本 → 应用原生增量 → 检查结果 → 原子提交 → outbox 通知。

读取、预检和执行共享同一个能力注册表与计划编译器。UI 和内部 AI 应复用相同领域
操作语义；公开 MCP 不透传内部 AI 工具，也不伪造会话调用它们。

### 4.1 原生块适配器

每个已注册块或元素类型提供版本化、强类型适配器，至少包含：

- 类型识别、schema 校验、公开属性分类及编辑操作 schema；
- 结构化读取、Markdown 投影及覆盖范围；
- 操作计划、原生增量应用、身份和未修改字段保留规则；
- 引用依赖、批注锚点、删除和类型转换规则；
- 无损比较、错误诊断及真实编辑器 fixture；
- schema 版本迁移与旧客户端兼容规则。

属性分成四类：用户可编辑、服务端维护、可证明等价的默认值、尚未解释但必须保留。
只允许明确的默认值归一化；未知属性不能按 prop: 或 meta: 前缀批量过滤。

共享的纯类型、属性规范与无浏览器依赖的校验放到现有模型包或其公开子入口。
后端不导入依赖 DOM 的编辑器组件；前端不反向依赖服务端。

### 4.2 能力覆盖清单

从实际 BlockSuite 注册表、surface 元素注册表、LocalMind 扩展块、Office 命令注册表
和文件引擎生成“模型类型 × schema 版本 × 操作”的覆盖清单，不能只手写七种常见块。

每一项记录读取、创建、编辑、移动、删除、类型转换、导出和保留的实现与验证状态。
当前产品可编辑的模型不得在最终验收时标为“以后支持”。新增模型或 schema 版本时，
CI 必须要求适配器及测试同步更新，否则阻止声明该版本具有完整 MCP 编辑能力。

未知未来类型先提供有界的身份、类型、保留状态与不透明引用，允许编辑其他块。
同一容器内的移动、明确删除等操作，只有能证明其所有权、子树和引用语义时才开放；
否则拒绝该项操作并定位原因。未知字段的任意写入不属于可验证的无损能力。

### 4.3 现有实现的复用与改造

[structured.ts](../../packages/backend/server/src/core/doc/structured.ts) 提供块、数据库、
画布操作的复用基础，但现有泛型 props、文本对象替换和独立 save 不能直接公开。
需要拆出可接入资源事务的强类型命令，并补齐 flat-data 表格、引用、元数据和锚点语义。

[resource-markdown.ts](../../packages/backend/server/src/core/doc/resource-markdown.ts)
保留为旧接口和 Markdown 投影适配，不再承担“整篇是否允许编辑”的总开关。
[原生 loader](../../vendor/affine_doc_loader-0.1.4/src/) 继续负责转换；
其字符串矩阵表格写入不得被用作已有富表格的无损编辑器。

## 5 公开协议

新协议使用 localmind-document-mcp/v2。现有 localmind-resource-mcp/v1 工具保持
严格 schema 与旧回执语义，新工具按凭据能力显式发现。下面的名称为实施目标，
落地时必须同步 schema、provider、凭据 UI、工具参考与测试，不能只写进说明文档。

### 5.1 读取和编辑入口

| 工具                                                    | 行为                                           | 关键约束                                       |
| ------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------- |
| workspace_doc_inspect                                   | 读取原生结构、版本、可编辑范围、相关属性及诊断 | 支持对象选择和绑定版本的分页，不返回未授权内容 |
| workspace_doc_edit_preview                              | 编译同一份编辑请求并返回确定性变更和保留计划   | 可选调用，不写业务状态，不充当授权或人工审批   |
| workspace_doc_apply                                     | 执行强类型编辑批次                             | 预期版本、幂等键、实时 ACL、原子提交           |
| workspace_doc_create_native                             | 创建指定类型文档及初始结构                     | 复用领域创建、目录放置和稳定预分配 ID          |
| workspace_doc_import                                    | 导入文件或无损包                               | 显式来源与目标类型、来源权限、配额和内容检查   |
| workspace_doc_export                                    | 原生无损包、同格式文件或明确选择的转换格式     | 精确版本、复制及下载权限、完整性报告           |
| workspace_doc_history_list / workspace_doc_history_read | 查看有权访问的历史版本                         | 分页、历史可见性与当前 ACL，不泄露私有修订     |
| workspace_doc_history_restore                           | 在原文档上恢复选定历史内容                     | 以当前版本为前提生成新提交，保留现有审计历史   |

新增接口使用明确的资源引用，例如 resource: { kind: "blocksuite", id: "…" }，
kind 为 blocksuite、office 或 file。Office 子类型由服务端真实资源决定，不能用
调用者伪造的类型选择更弱的权限路径。旧 documentId 不自动变成跨类型任意 ID。

workspace_doc_apply 接受原生结构操作、带明确保留策略的 Markdown 变更、
各 Office 引擎的强类型命令或文件编辑命令。各输入是判别联合，不接受任意 props、
任意 JSON Patch 路径、任意 Yjs update 或通用脚本。

### 5.2 文档周边操作

| 工具                                                       | 行为                                             | 授权边界                                                     |
| ---------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| workspace_doc_properties_update                            | 标题、图标、封面、标签与已定义文档属性           | 对应类型的元数据 ACL，服务端创建证据不可写                   |
| workspace_doc_comments_read / workspace_doc_comments_apply | 线程、回复、编辑、解决、重新打开、删除和锚点操作 | 逐操作检查 Comment 权限与现有作者规则                        |
| workspace_doc_asset_read / workspace_doc_asset_upload      | 有界读取、分块暂存和提交文档使用的资源           | Blob ACL、文档上下文、容量、来源和 MIME 检查                 |
| workspace_doc_duplicate                                    | 同 Workspace 明确复制为独立文档                  | 来源 Copy/Duplicate、目标创建和目录 ACL                      |
| workspace_doc_lifecycle                                    | 回收、恢复、永久删除                             | 各自生命周期权限；永久删除必须是明确操作                     |
| workspace_doc_access_read / workspace_doc_access_update    | 文档分享、文档成员和所有权操作                   | 单独管理能力，逐项 Publish、Users.Manage、TransferOwner 检查 |

评论、管理和生命周期保持独立操作族，不因正文编辑隐式触发。标题与正文的单次
原子编辑可以由 workspace_doc_apply 显式包含标题命令，服务端同时检查
workspace_doc_properties_update 能力、元数据权限和版本条件。
需要正文与批注共同提交的操作，批次也必须声明并检查相应批注工具能力；
批注命令复用相同强类型 schema，不能通过正文批次获得额外评论权限。

已有 workspace_doc_list、workspace_doc_keyword_search、目录工具和
workspace_operation_get 继续使用其独立能力。v2 资源类型查询使用版本化输入输出，
不静默改变 v1 列表类型；回执查询按存储的 contractVersion 投影相应严格结果。

### 5.3 输入与读取结果

每次编辑包含 resource、expectedVersion、idempotencyKey 和 commands。
每条命令有 request-local 的 opId、明确目标和强类型参数。新对象使用 clientRef，
服务端预分配 ID 并在回执返回映射；不得由数组下标或相同文字推断稳定身份。

commands 按请求顺序作用于同一候选状态；每条文本命令的坐标基于此前命令已应用后的
状态。clientRef 只能引用本批次先前创建的对象。无法一致解释的范围依赖、无效的前向
引用及重复 opId 在预检时明确拒绝，不能一部分按初始坐标、一部分按更新后坐标解释。
需要使用初始选择范围的客户端，由同一编译器进行显式范围映射。

读取返回 documentVersion、schemaVersion、adapterVersion、原生对象身份与操作能力。
内容版本、目录版本、批注版本、元数据版本分开描述；跨域批次携带所有实际依赖的版本。
并非所有用户都拥有批注或资产读取权，完整性须按已授权的请求范围说明。

完整性分别表达：

- scopeCoverage：此次选择范围是完整、分页中或截断；截断结果不可用于整体替换。
- representationFidelity：原生表示完整、含服务端保留的不透明数据、或仅为有损投影。
- externalReferences：哪些引用未展开；不能把“不展开引用目标”误报成删除内容。
- diagnostics：有界遗漏、简化、未知字段和操作限制，包含总数与是否仍有后续页。

每页绑定同一个版本。文档变化时返回 stale_read，而不是把新版本片段拼到旧结果中；
不为跨网络分页持有数据库长事务。大范围编辑可使用服务端版本绑定的选择句柄，
避免要求调用者下载整篇文档。

## 6 内容操作与保留规则

### 6.1 空页与空段落

原生编辑路径不进行 Markdown 重建。一个或多个空段落、只含空白字符的段落、
中间空行、末尾空段落均是可编辑对象，正常接受插入、替换、删除和块操作。
往空段落写字保留该段落 ID；清空段落文字保留块及其属性。

明确区分“清空某段文字”“删除某块”“清空正文选择范围”三个操作。
最后一个可编辑块删除后，如编辑器要求光标落点，使用与 UI 相同的空块策略，
并把新增空块列入结果；不能由 UI 与服务端反复相互增删空块。

旧 Markdown 接口的空结构规则只覆盖无语义属性的普通空文本段落：
视觉空页可以直接首次写入；原样空输入返回 no-op；不得把空标题、空列表项、
空代码块、表格空单元格、带批注或未知属性的空块一并忽略。
多余空段落作为布局状态默认保留，只有明确删除或替换范围才能移除。
含非空正文的编辑器文档也必须能保留其中的空段落，而非仅修复全空页。

### 6.2 普通文本与行内格式

文本命令包含插入、删除、替换、格式设置、格式清除和链接或引用编辑。
位置使用明确的 UTF-16 索引与固定文档版本，校验代理对和字素边界；禁止截断 emoji、
组合字符或把代码点索引误当 Y.Text 索引。读取同时返回调用者可直接使用的位置约定。

在原 Y.Text 上执行增量。替换范围之外的文字、属性和 CRDT 身份必须保持；
替换范围之内的新增文字明确选择格式策略：指定属性、继承统一的被替换范围、
继承左侧或右侧。空段落使用明确的默认插入属性。混合格式范围没有唯一继承结果时，
要求格式 runs 或更精确的范围，不能擅自清除格式。

格式设置只改指定键；格式清除必须列明键或明确选择全部已知格式。
未知属性默认保留。加粗、斜体、删除线、下划线、颜色、行内代码、超链接、
文档引用和格式边缘空白均按原生 Delta 保存，不依赖 Markdown 标记能否表达。

代码语言、原始文字和换行独立保存。围栏中的 HTML、图片、管道和反引号，
以及行内代码中的同类文字，不触发资源类型拒绝。

### 6.3 段落、标题、列表、引用、分隔线与容器

支持创建、修改文本、设置属性、拆分、合并、转换类型、移动、缩进、取消缩进、
重排和删除。标题等级、折叠状态、列表类型、勾选状态、编号起点、对齐及层级
使用明确字段，遵守当前模型的父子约束。

拆分与合并属于显式身份变化：保留一侧已有 ID，为新增对象生成 ID，
返回旧范围到新范围的映射并迁移锚点。移动不重建节点；同级重排按 ID 操作。
标题、列表和段落的合法转换保留可兼容属性，不可兼容属性通过转换计划列出；
默认无损模式下不接受隐式丢弃。

页面根、surface 与 note 的必要不变量由领域服务维护。允许编辑用户可修改的容器
属性和布局，不能用普通 block.delete 破坏文档根、引入环或制造悬空子节点。

### 6.4 表格

表格适配器直接处理编辑器的 flat-data 键和单元格 Y.Text。
行与列使用稳定 rowId、columnId，单元格使用二者的组合；文字和样式分别更新。

必须支持单元格文本与富文本编辑、清空、矩形粘贴、行列插入删除、移动排序、
列宽、行列背景色、表格对齐、批注，以及明确的整表替换。
当前模型若没有合并单元格等能力，不能虚构已支持；新增此能力属于表格模型开发，
须与 UI、适配器和导出同时实施。

插入只为新行列生成 ID；移动只修改 order；改单元格只修改目标 Y.Text。
原行列、其他单元格、宽度、颜色、元数据及关联线程必须保持。
删除行列仅删除选择范围，并处理其相关锚点；整表重写提供行列身份映射，
不能根据重复文字猜测对应关系。

禁用“修改一个单元格就 clear_table_props”的现有更新方式。
现有原生 loader 可以继续创建经过声明的基础导入表格；编辑已有富表格须走新适配器。

### 6.5 数据库与数据视图

数据库不是普通表格。支持当前注册的字段类型、类型配置、选项 ID、行、
类型化单元格、列宽、视图、筛选、排序、分组和显示配置。
操作复用类型转换、计算和验证逻辑，保留关联行块及视图关系。

修改选项名称保留选项 ID；字段类型转换先检查全部受影响值和视图引用。
无法无损转换时返回具体字段与受影响数量，不清空已有值。
产品允许的显式有损转换须使用单独的转换意图与精确影响范围。
空单元格、null、空字符串、零和 false 不得混同。

数据视图的 schema 与数据库版本须分别盘点；不能因为已有 StructuredDocService
支持基础列和行，就宣称 UI 中所有视图操作已覆盖。

### 6.6 图片、附件、书签与嵌入

支持现有资源的说明、标题、尺寸、裁剪、展示方式及对应模型公开属性修改；
支持有权资源的新增、替换和移除。只改说明不重新上传或复制 Blob。
删除块不立即物理删除仍被其他文档、历史或审计引用的资产。

上传走可恢复暂存、分块校验、MIME 与大小检查、配额预留和提交时绑定。
下载按文档上下文、当前 ACL 与复制权限执行。复制 Blob 引用、上传新资产、
替换已有资产和读取外部 URL 是不同动作，不能彼此隐式授予。

覆盖 bookmark、YouTube、iframe、Figma、GitHub、Loom、HTML 等实际注册嵌入类型。
HTML 内容使用产品已有的沙箱与内容规则，不提供任意脚本执行入口。
外部内容获取若被明确请求，继续经过已有网络访问控制与来源授权。

### 6.7 Callout、公式与其他内容块

Callout 的图标、子树、样式分别更新，保留未触及子块。
公式编辑保存原始公式字符串与显示属性，不通过渲染结果或 Markdown 反推公式。
对其他当前注册内容块按其原生 schema 完成相同的增删改和保留能力。

### 6.8 文档引用、同步块与子页面

区分链接目标、展开的只读投影和引用源正文。修改引用只修改当前块。
若用户明确要求修改同步源，命令必须指出真实源文档，读取该源的权威版本并检查
该源的写权限；不能只因可编辑引用所在文档就写源文档。

新增或改变引用按现有 UI 等价规则检查目标可见性、来源复制或分享约束；
无权读取目标时不泄露标题、正文和路径。保留既有不可见引用不等于获得目标读取权。

localmind:subpage 的内容引用和资源树归属分别建模。只改引用不移动资源；
移动归属显式调用目录领域操作并检查源、目标和目录版本。

### 6.9 批注与锚点

线程、回复、作者、创建时间、解决状态与锚点分别处理。正文编辑不自动删除、
解决或重新打开线程，也不产生无关 mention 通知。
逐类型盘点当前使用的块标记、Y.Text 相对位置、单元格定位和画布锚点。

存续文本的相对位置自然跟随增量；拆分、合并和类型转换提供确定性锚点映射。
原生操作明确删除被锚定内容时，保留线程并按统一领域规则显示“原内容已删除”
或失去锚点状态，不能随机绑定到相邻文字。若现有领域无此状态，需要新增持久状态、
迁移与 UI 表达，不能只返回日志警告。

评论正文修改、解决和删除仍检查对应评论权限；普通 Doc.Update 不因此获得
修改他人线程内容的能力。正文与锚点关系的维护由系统执行并单独审计。

### 6.10 画布

Page 与 Edgeless 的并存数据都要保留。支持实际注册的 shape、text、connector、
group、brush、highlighter、mindmap，以及 frame、note、image 和 surface-ref。
覆盖位置、尺寸、旋转、层级、样式、连线端点、分组和成员关系等 UI 已支持操作。

以元素 ID 定点修改，不替换整个 prop:elements。删除或移动有连接关系的对象，
按 UI 同一规则维护端点、分组和 frame 关系；必要时在一批中原子完成。
页面正文更新不得改变画布；画布更新不得改变正文。Markdown 整体替换不能承担画布编辑。

### 6.11 Office 与 WorkspaceFile

Office 通过独立引擎适配器接入已有命令服务，使用 OfficeRevision CAS、
不可变包、资产与评论语义。DOCX 段落和 run、XLSX 单元格与公式及视图、
PPTX 页面和元素、PDF 页面与批注等以当前产品命令清单逐项验收。
引擎尚不支持的编辑不得包装成 MCP 成功；若属于完整目标中的产品操作，
需要同步补齐引擎，不能把 Markdown 中间页作为替代结果。

未触及的 OOXML 部件、关系、媒体和格式须保留；存在数字签名等无法在修改后保持
原有效性的属性时返回确定的转换约束，不能默默失效。PDF 保持未触及页面资源、
表单和批注，明确区分修改、覆盖显示和真正内容删除等不同语义。

WorkspaceFile 对文本、CSV 和 JSON 分别使用可保持原编码、换行和未修改字节范围的
适配器；结构化修改不能默认重排 JSON 或改变 CSV 引号、列顺序和数据类型。
二进制替换是明确的新不可变版本，不覆盖创建证据；未知二进制格式的语义编辑
需要对应引擎，下载及显式版本替换仍可以提供。

## 7 整篇改写与 Markdown 兼容

### 7.1 原生整篇改写

整篇重写不是直接提交一份投影然后覆盖。编译器将输入转成新增、修改、移动、
删除和格式变化的原生计划，沿用同一执行器。

优先使用读取结果中的块、行列和元素 ID。未提及的字段默认保留；
未提及的块是否删除必须由操作模式明确指定。提供两种清晰模式：

- 更新并保留：只改映射到的对象，省略的对象保留。
- 替换选定范围：请求明确指出范围、预期版本和删除未列出对象的意图；
  计划列出实际删除对象、资产引用与锚点影响，范围外保持不变。

删除选择范围可以一次明确指定，不要求用户逐块人工审批。
重复文字、重复表格、无法唯一判断的行列对应关系返回 identity_ambiguous，
调用者通过 ID 或显式映射消除歧义。模型“猜到是哪个”不能替代身份条件。

### 7.2 Markdown 输入

Markdown 作为文字与结构的输入格式，解析为 AST 后编译成原生命令。
围栏、行内代码、表格、图片和受控 HTML 行内格式按节点类型区分。
Markdown 解析器、能力注册表和原生投影必须使用一致的格式集合。

对现有复杂文档，使用目标范围和身份映射把 Markdown 修改应用到对应对象，
未表达的格式、未知属性、批注、资产及画布保留。插入文字按显式样式规则处理；
不能因为 Markdown 未写加粗标记就默认清除原加粗。用户要求重设格式时，
请求明确选择格式重置范围并列入计划。

原样导出的内容回写首先识别真实 no-op，保留原文档而不是重建副本。
对于无法映射的变更返回可定位冲突，不能通过丢弃未支持内容换取“保存成功”。

### 7.3 v1 过渡策略

v1 保留旧工具名、输入输出形状及能力边界，修复空普通段落、代码字面量误判，
并使 contentWritable 与同接口原样校验一致。

无法以 v1 已声明格式无损回写的下划线、颜色等页面，过渡期诚实报告不可写，
完整操作由 v2 原生接口提供；不能继续返回 true 后在正则阶段拒绝。
是否把受控行内 HTML 纳入 v1 属于独立格式兼容变更，不能借修复自动开放任意 HTML。

v1 对确实遗漏正文的读取返回原有结构错误，而非伪装为完整内容；
标题与列表等元数据读取仍可用。v2 提供完整性、原生结构和局部编辑路径。
发布说明明确这一纠正，客户端工作流优先升级到 v2。

## 8 预检与执行示例

以下为合成参数。第一条在已有空段落插入文字；第二条只修改表格一个字符，
其他行列、单元格和样式均保持。真实 schema 中目标和格式属性采用严格判别联合。

```json
{
  "contractVersion": "localmind-document-mcp/v2",
  "resource": { "kind": "blocksuite", "id": "doc_example" },
  "expectedVersion": "version_from_inspect",
  "idempotencyKey": "edit_example_001",
  "commands": [
    {
      "opId": "fill_empty_paragraph",
      "type": "text.splice",
      "target": { "kind": "block_text", "blockId": "paragraph_empty" },
      "offset": 0,
      "deleteCount": 0,
      "insert": "今日完成",
      "marks": { "mode": "explicit", "attributes": {} }
    },
    {
      "opId": "change_cell_character",
      "type": "text.splice",
      "target": {
        "kind": "table_cell",
        "blockId": "table_example",
        "rowId": "row_example",
        "columnId": "column_example"
      },
      "offset": 0,
      "deleteCount": 1,
      "insert": "新",
      "marks": { "mode": "inherit_replaced_range" }
    }
  ]
}
```

相同请求可先提交 edit_preview，得到计划摘要、目标版本、输入指纹、适配器版本、
依赖版本、保留断言和 planDigest。预检可只返回签名摘要，不要求保存完整私密正文；
若需要持久计划，则使用独立受 ACL 保护、有过期时间的记录。

apply 可以直接接收命令并在内部预检，不强制先调用 preview。
若调用者携带 planDigest，必须重新计算并核对；版本、输入、适配器或依赖改变时，
返回计划过期或冲突。预检结果不授予权限，也不冻结未来 ACL。

计划指纹基于规范化命令、逻辑 clientRef、基准及依赖版本、适配器版本和保留策略，
不包含随机生成 ID、当前时间或展示文案。执行时新 ID 与操作身份稳定绑定，
重试复用同一映射；服务端时间只用于最终修改证据，不改变计划语义。

成功结果返回 operationId、前后版本、changed、writeOutcome、
新对象 ID 映射、实际影响范围和 preservationVerified。验证失败不得返回成功。
保留摘要只列类型、数量、身份和有界差异，不输出完整文档正文。

## 9 权限与凭据兼容

授权关系保持为“当前身份的实时权限 ∩ 凭据明确授予的能力 ∩ 当前资源状态”。
补充 MCP 编辑能力不增加 actor-only audience、无其他读者、私有来源等额外正文门禁。
有权进行的普通编辑不因调用者是 MCP 而增加网页批准、AI 审批或模型判断。

| 操作族                           | 必须复用的权限语义                                                 |
| -------------------------------- | ------------------------------------------------------------------ |
| 内容、块、表格、数据库、画布编辑 | Doc.Read、Doc.Update 及现有同步策略；其他类型走对应资源 ACL        |
| 创建和复制                       | Workspace.CreateDoc、目标目录权限；复制额外检查来源 Copy/Duplicate |
| 标题和文档属性                   | 既有标题更新规则、Doc.Properties.Update 或对应原生资源权限         |
| 附件上传与资源读取               | Workspace.Blobs.Write/Read 加文档上下文、配额、来源约束            |
| 批注和回复                       | 对应 Comments.Read/Create/Update/Delete/Resolve 及作者规则         |
| 回收、恢复、永久删除             | 对应 Trash、Restore、Delete，不从 Doc.Update 推导                  |
| 分享、文档成员和所有权           | Publish、Users.Manage、TransferOwner，单独工具能力                 |
| 引用源编辑与跨资源操作           | 每一个真实来源和目标各自的 ACL、版本与来源约束                     |

表中权限是既有语义的入口，不能只检查一条 action 就省略领域服务的其他约束。
Workspace 访问显式使用个人及 Workspace 范围，不借历史 Project grant 扩权。

新凭据可选择“文档完整编辑”预设，在创建时展开为明确工具集合；管理、分享与永久删除
能力清晰单列。预设不是自动包含未来工具的通配符。已有凭据通过现有设置一次性明确
授权新能力；旧凭据和轮换结果不自动扩权。已经具备新能力的凭据正常直接调用，
不需要额外的每次操作授权。

旧委托任务的冻结工具集合、契约版本和能力上限保持不变。新公开资源工具不注册为
退役内部工具别名，也不自动注入 ToolRuntime。

权限检查发生在读取或预检时，以及取得执行锁后的提交路径。权限撤销与内容写入使用
统一的权威状态和锁顺序，定义清晰的先后关系：在执行生效点之前已生效的撤权必须阻止
提交，之后的撤权影响后续操作。不能声称预检成功可以跨越权限撤销。

## 10 事务、并发和幂等

### 10.1 单文档原子提交

1. 严格解析协议，验证工具能力和基础权限，检查请求预算。
2. 创建或取得持久操作身份；冻结输入指纹和预分配 ID。
3. 已成功或失败的相同请求按原回执重放；同键不同输入返回冲突。
4. 可在事务外准备解析结果和候选计划；不将其视为已提交内容。
5. 进入既有资源事务，按统一顺序获取授权、目录和涉及文档的必要锁。
6. 读取包含全部已提交 updates 的权威状态，重查权限、状态及所有预期版本。
7. 在内存副本编译并应用命令，执行原生 schema、引用、锚点和保留验证。
8. 将精确增量、关联元数据、必要历史证据、批注变化、回执与 outbox 在同一事务提交。
9. 提交后发布同步和索引事件；投递失败只重试 outbox，不把成功操作改成失败。

保留 [Doc model](../../packages/backend/server/src/models/doc.ts) 的权威快照与更新读取、
内容写锁和单调版本基础。不能退回缓存 Markdown、搜索索引或只读旧 snapshot 做 CAS。
正文、元数据、评论和目录服务参与跨域批次时，必须证明实际共享事务。

仅执行 Y.Doc.transact 不等于数据库事务，也不能自动回滚已经发送的通知。
StructuredDocService 的独立 save 和评论的即时通知须改为可参与统一提交的领域接口。

### 10.2 并发编辑

首版 v2 使用文档级 expectedVersion，另加实际涉及的评论、目录等依赖版本。
Web、Electron、MCP 与原生同步写入都必须进入相同互斥与版本规则。
版本漂移返回冲突，禁止自动把旧整篇输入覆盖到新状态。

服务端版本只覆盖已到达并提交的变更。离线客户端尚未同步的操作不能提前反映在版本中；
恢复同步后由 CRDT 合并并验证原有文本身份和关系，不通过替换整个 Y.Text 或整文档
快照使离线变更失去原对象。并发语义冲突需要显式呈现，不能以“CRDT 已合并”代替验收。

多资源操作必须有明确命令范围、独立版本和稳定锁顺序。默认文档编辑不跨文档。
若关联编辑无法在同一存储事务原子提交，使用独立操作回执并如实返回结果，
不能伪造一个跨存储原子成功；需要原子性的调用应在预检阶段拒绝该组合。

### 10.3 无变更、重试与恢复

no-op 在原生语义与明确默认值规范化后判断；格式、布局、引用改变不能被当成 no-op。
幂等身份继续绑定 Workspace、actor、credential family、工具、键及契约版本指纹。
同键网络重试先核对原回执，再判断旧 expectedVersion。

业务错误映射为稳定领域错误。解析、类型和计划失败必须被识别为明确零提交，
不能把普通 native 异常一律误报为提交结果未知。
真正结果不明时返回 unknown 和 operationId；客户端查询或以原键原参数恢复。

成功或失败终态不可改写。进程退出前未提交的事务回滚；原键恢复不得重新创建另一份文档。
关闭新编辑开关后，已授权的回执查询继续可用。

### 10.4 Blob 与大操作

上传资源和 Office 候选包先进入受控暂存，按内容指纹校验，提交时原子绑定资源引用、
当前版本和回执。失败或超时的未引用暂存由有保留期的清理任务处理。
不得在已写一半正文后等待远程资源下载，也不得把外部对象存储写入误称为数据库原子写。

大操作可先分批暂存命令并编译候选结果，最终对同一预期版本一次发布。
暂存期间不能让用户看见半完成文档。异步准备如确有必要，使用专门持久状态、
租约和回执，不进入模型运行时；超时也不自动转 delegate。

## 11 历史证据与数据迁移

正常内容编辑继续存储 Yjs 增量、OfficeRevision 或 WorkspaceFileRevision，
不另建一套可变“规范 Markdown”作为正文真相来源，不批量重写历史文档。

实际需要的持久化扩展如下：

| 数据                 | 设计                                                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------------------------- |
| v2 操作回执          | 扩展现有 McpResourceOperation 的版本化结果，记录强类型资源引用、前后版本、计划和适配器指纹、ID 映射、有界保留验证    |
| 资源目标约束         | 现有 documentId/folderId 不能承载所有 Office/file 语义；新增明确类型化目标关联或字段及数据库约束，旧记录仍按 v1 解释 |
| 精确历史恢复证据     | 复用已有不可变修订；BlockSuite 如现有合并历史无法提供精确前态，则增加受 ACL 保护的检查点引用                         |
| 锚点失效与映射       | 优先复用评论领域；缺少持久语义时增加关联状态、映射与迁移，不改写线程正文                                             |
| 分块上传或大请求暂存 | 持久记录归属、输入指纹、分块校验、配额、到期与提交状态，避免重启丢失或重复绑定                                       |
| 适配器版本           | 代码发布清单与结果绑定；不建立只在单进程内生效的第二套文档状态                                                       |

正文和原始快照存于现有受保护内容存储。普通审计日志和 operation_get 不返回完整正文；
回执只引用相应历史版本。历史与暂存记录定义保留期、配额、去重和清理规则。
无变更操作不产生新的内容检查点。

历史恢复是对当前文档执行一次有前提的新变更，不是直接 merge 一个旧 Yjs snapshot。
恢复被明确删除的对象时按历史语义重建必要对象与锚点映射；已删除的 CRDT item
不能被承诺原地复活。未被删除的对象继续保留身份，原历史证据不覆盖。

无损包恢复历史作者和创建证据必须核对可信来源与服务器保存的证据关系。
外部导入文件携带的作者、时间仅作为来源元数据，不得伪造成 LocalMind 的创建、
审批或授权记录；包内资源 ID 和不透明句柄也不构成访问凭证。

所有 schema 变化新增迁移，验证从现有凭据、v1 回执、历史任务及旧文档升级；
不迁移扩大旧 capability，不修改冻结任务，不手工改生成 Prisma Client。

## 12 错误、完整性与客户端行为

v2 错误包含 code、stage、opId、允许公开的 target、propertyPath、
expected/currentVersion、writeOutcome、operationId 和 nextAction。
这些字段有长度与数量上限，不携带私密正文、凭据、原始数据库异常或不可见目标信息。

| 稳定错误                                          | 调用者动作                                       |
| ------------------------------------------------- | ------------------------------------------------ |
| permission_denied / capability_denied             | 停止该操作，按真实授权处理；不换工具绕过         |
| version_conflict / stale_read / plan_stale        | 读取相同目标的新版本，重新生成明确变更           |
| identity_ambiguous                                | 提交块、行列或元素 ID 映射                       |
| invalid_structure / invalid_range / invalid_value | 修正定位到的命令，原内容保持                     |
| unsupported_schema_version                        | 升级相应适配器；其他支持对象仍可单独编辑         |
| conversion_not_lossless                           | 保持原生格式，或明确选择另一种转换目标与影响范围 |
| preservation_failed / anchor_mapping_failed       | 零业务提交，保留原文并返回可定位的检查结果       |
| reference_constraint / resource_in_use            | 按引用与生命周期规则修正操作                     |
| request_too_large / quota_exceeded                | 使用分页、暂存或减小本次操作范围，不截断后保存   |
| idempotency_conflict                              | 核对原请求；不能用同键提交不同内容               |

保留旧错误码兼容，但不直接向旧严格 schema 塞新字段。
调用说明和日志工作流必须区分读到全部内容、只读到投影、未展开引用和分页尚未结束。
不得把 Markdown 投影当完整备份，或建议用户清空文档以解除适配器限制。

## 13 资源预算与执行效率

容量预算限制单次工作量，不限制合法块类型。完整覆盖的容量至少应与产品支持的文档
范围一致；不能把 UI 可编辑的大文档一律拒绝后仍宣称 MCP 全能力完成。

初始实现可沿用 1 MiB 文本请求、32 MiB 文件/权威状态预算，并为命令数量、
分页对象数、递归深度、文本范围、批注数和图关系设有界默认值。
具体数值须在 P0 登记并通过 Linux 压测确定，与现有产品容量差异须有可用的分段路径。

命令编译优先按 ID 定位和局部比较，避免整篇 Markdown 往返及全量二次方文本匹配。
大批次在事务外准备，在锁内重验版本和结果；锁内不调用模型、外部网络或长时间渲染。
超预算返回明确可执行的分页或暂存方案，不能默默漏块、删列、压平格式或分次提交半文档。

## 17 验证方法

### 17.1 测试数据

使用三类数据：由真实编辑器操作生成并冻结的合成 Yjs 样本、直接构造的边界样本、
由各原生文件引擎生成或导入的合成包。记录生成器、编辑器 schema 和 addon 版本。
真实业务日志、私密正文和原凭据不进入公共 fixture。

每类块覆盖最小样例、混合样例、默认/非默认属性、未知属性、空内容、
多个相同文字、嵌套和历史编辑状态。不能仅测试 createDocWithMarkdown 自己生成的文档。

### 17.2 无损检查

每个编辑测试同时检查：预期语义、目标 ID 与 CRDT 对象身份、未触及字段、
批注/引用/资产关系、修改元数据范围、版本、回执及编辑器实际读取。
无关子树采用规范化字段指纹和 CRDT 结构身份对比；资产采用内容指纹。

增加性质测试与随机操作序列，验证“编辑再无关编辑”“插入再删除新增内容”
“重复 no-op”“序列化后重新打开”的不变量。对不支持的字段和未知块采用生成样本，
禁止用忽略列表吞掉测试差异。

故障注入覆盖每个持久化步骤、跨域约束、锁等待撤权、并发同步、进程退出、
对象存储失败和通知失败。使用独立数据库与资源，验证前先核对实例身份。

### 17.3 Linux 与浏览器

日常复用固定 localmind-affine:test 或已验证的复用容器，不新建任务专属 tag。
Rust/native 变化必须运行 Linux 原生测试和 addon 回归，并记录源码与产物指纹。
已有测试入口包括：

```sh
NODE_OPTIONS="--import=/workspace/tools/cli/register.js" \
yarn workspace @affine/server ava --serial \
  src/__tests__/copilot/copilot-mcp-resources.spec.ts \
  src/__tests__/copilot/copilot-mcp-resources.e2e.ts
cargo test --locked -p affine_doc_loader --lib
```

新原生适配器、评论、Office/file、迁移和浏览器测试应接入仓库对应现有入口，
以真实登记的测试文件与命令为准。整体既有类型检查基线与本任务失败分别报告。

浏览器使用一次性合成 Workspace：UI 建文档 → MCP 读取并修改 → UI 重开核对 →
UI 再编辑 → MCP 读取与冲突验证。检查样式、选区/锚点、表格行列、画布关系、
资产、历史和错误状态；截图不能代替结构断言。

DOCX/XLSX/PPTX/PDF 还需独立解析、重开及适当外部渲染验证。
业务日志与生产 Workspace 不用作修复验收靶标。

## 18 发布、回滚与本轮交付

实施完成后按阶段发布新的文档编辑能力开关，默认关闭，独立于旧资源和委托入口。
发布前完成迁移、旧数据升级、备份恢复及凭据发现验证。
如需同步业务运行环境，必须使用仓库现有同步脚本及其备份/native 证据要求；
源码完成、测试完成、本地同步、生产部署分别记录。

关闭 v2 写入入口作为首选回滚，不删除已写内容、回执、迁移或历史版本。
关闭后保留已授权的读取、回执核对和必要恢复入口。
若新模型版本不能被旧程序读取，禁止直接回滚旧二进制；保留兼容读取程序，
或在完整备份和明确恢复计划下处理。

同步更新产品契约、应用内帮助、工具参考、凭据 UI 和客户端工作流。
只有逐项验收结果支持时，才宣传完整编辑；阶段性能力必须准确标识。
当前源码、native addon 和运行服务版本必须分别核对，不能用本机成功推断线上可用。

方案编制时仅更新文档；用户随后授权完整实施，代码、隔离验证和迁移证据见实施记录。
本轮不执行运行同步、生产部署、commit 或 push，不改写已恢复的 2026-11-03 日志。
