# Project 项目汇报工作台完整开发契约

日期：2026-10-12。状态：产品范围已由用户确认，本文定义完整开发与验收目标；尚未据此实施业务代码、迁移或部署。

Project 增加独立的项目汇报工作台。成员维护项目文档，项目 AI 根据文档整理详细进度和成果，生成可编辑、可协作审阅、可全屏演示、可导出、可受控分享且可追溯的汇报。所有本文列出的能力均属于完整交付范围，实施顺序不构成删减范围或将功能推迟到未定义后续版本的理由。

**负责人没有明确指定时，默认以创建该汇报的人为负责人。** 该规则同时适用于汇报整体及汇报内未明确负责人的事项。默认归属保留来源标识，不修改源文档、真实任务或工单的指派。

## 3 负责人规则

### 3.1 身份与优先级

创建证据保存不可变的 `createdByActorId`、创建时间及最小必要身份快照。当前负责人另存，改变负责人不能改写创建者。

| 场景                                     | 负责人规则                                                                           |
| ---------------------------------------- | ------------------------------------------------------------------------------------ |
| 创建汇报时明确指定汇报负责人             | 使用指定人员，记录 `manual`。                                                        |
| 创建汇报时未指定                         | 使用本份汇报创建者，记录 `creator_fallback`。                                        |
| 文档明确指定某事项负责人                 | 使用文档明确身份，记录 `document` 并关联来源。                                       |
| 用户在汇报中明确修改事项负责人           | 使用本次明确指派，记录 `manual`；仅改变报告表达。                                    |
| 某事项未明确负责人                       | 使用本份汇报创建者，记录 `creator_fallback`，界面显示「默认」。                      |
| 多份材料对负责人记载冲突                 | 显示冲突供核对；核对前使用创建者作为默认汇报责任人，保留冲突说明。                   |
| 同一汇报更新、重试、修订、由其他成员编辑 | 创建者不变，默认负责人不漂移。                                                       |
| 复制或基于上期创建另一份汇报             | 新汇报创建者为执行本次创建的真实用户；默认值重新绑定，明确指派按来源或用户选择保留。 |
| 周期任务创建汇报                         | 创建者为该次执行冻结并重新鉴权的委托用户；不是调度器、模型或系统账号。               |

身份字段使用有类型的联合：项目成员身份、文档明确的外部人员文本身份、创建者默认身份。重名不能仅凭姓名绑定账号，外部人员不能因此获得成员身份或权限。

### 3.2 变更与展示

负责人来源必须贯穿编辑页、演示、导出和历史版本。默认身份的来源可放在详情中，但不能被改写为“源文档明确指定”。该默认规则不证明创建者亲自执行了工作，也不发出工单或通知任务受让人。

创建者离开项目后，历史默认归属保留并显示离任状态；现有有效成员可以明确修改新草稿的负责人。创建者账号删除时按平台删除契约显示身份占位及最小审计关联，不泄露已删除身份，也不自动改派。以该用户执行的周期任务必须暂停。

## 4 数据来源与事实契约

### 4.1 允许的材料

项目文件树中的 Page、Edgeless 可读文字、DOCX、XLSX、PPTX、PDF 以及可解析的 TXT、Markdown、CSV、JSON 均通过各自领域服务读取。Office 读取固定修订；BlockSuite 读取服务端可重现快照并记录状态标识；普通文件读取不可变 Blob 与内容版本。

扫描件只有在实例已配置且授权的 OCR 能力可用时才提取文字。无法解析、受密码保护、超过配置上限或损坏的资源明确列为未覆盖，不假装已读，不临时把文件发送到未配置服务。

项目 Memory 只读取公开共享的项目 Memory，只补充背景、目标和已共享约定，不能替代文档生成成员详细进度。

工单（2026-10-13 用户决策，覆盖原 D02/D03 的“仅文档”口径）：只读取 `sourceProjectIdSnapshot` 等于本项目、当前执行者为发单人或接单人且仍是项目成员的工单。服务端只取元数据并生成确定性文字：标题、状态、版本、必需要求标题、最新交付修订号、提交时间、交付项数量、完成/更新时间；来源 `kind=work_order`，修订为 `状态:版本:最新交付修订号`，指纹由同一元数据计算。交付草稿、暂存 Blob、交付项文字/文件内容、往来正文和未确认派单草稿一律不读取。发单人一侧在派单未释放（同一派单全部工单已交付或取消之前）时只保留状态，不含交付修订、提交时间和完成时间。

声明规则：`document` 声明只能引用文档来源，不能引用 Memory 或工单；`business_state` 声明只能引用已解析的工单来源；混合来源只能作为 `inference`。工单事实只接受进展、成果、风险和计划，状态按记录映射（delivered→已完成，open/validating→进行中，waiting_sender/refused→受阻，cancelled→未知/未完成），不从工单推断负责人；只有已交付工单可作为成果。定稿时定稿人必须仍是所引用工单的参与方；同一版本指纹不一致即拒绝，旧版本保留为历史证据。

既有报告和其导出物默认不作为新的原始进度证据，避免汇报反复引用自己形成伪证据。上期报告用于差异比较，事实仍回查原始文档。

### 4.2 时间与覆盖

周期保存 IANA 时区和绝对时间 `[periodStart, periodEnd)`；“本周”使用界面明示的周起始日，不能按执行机器时区计算。生成时间、周期结束时间和资料截止时间分别保存。

全项目模式先分页枚举当前可用资源，再识别周期内变化、相关目标文档和必要背景。文件夹选择以稳定 ID 保存，生成时记录实际展开清单；移动、删除或新增资源不会静默改变已经冻结的清单。

每次运行保存 `discovered/selected/read/parsed/failed/omitted` 的有界计数与逐项原因。只对执行者获准知道的材料计数，不泄露不可访问文件名称或数量。RAG 用于补读和检索，不能用少量 top-k 结果冒充全量分析。

无法读取截止时刻历史版本时，记录实际读取版本及时间并显示时间差异。需要精确截止快照的定时汇报按快照任务捕获；不能把之后的新内容伪装为截止时刻状态。

### 4.3 事实、推断和人工内容

每条可核验结论记录 `claimId`、事实类型、来源定位、来源版本和验证状态。类型至少区分文档陈述、业务状态、计算结果、AI 推断和人工补充。

- 完成率必须有分子、分母、排除项、周期、计量单位和公式；任务数完成率不能冒充整个项目完成率。
- 最后修改时间只代表发生修改，不能证明实际业务进展。
- “计划完成”不能改写成“已经完成”；缺失数据不能当作零。
- 文档内部矛盾、跨文档冲突、文档与工单状态冲突应形成有来源的核对项。
- AI 推断展示「建议关注」；人工内容无依据时保持人工标识，不伪造引用。
- 缺少负责人直接应用第 3 节默认值；缺少进度、成果或日期仍明确说明未记录。

### 5.2 列表与创建

列表展示标题、周期、模板、创建人、负责人、更新时间、最近定稿版本和草稿状态；支持搜索、筛选、分页、复制、归档及移入回收站。一个报告只显示一行，历史版本在详情展开。首次空状态直接提供常用模板和新建入口。

创建面板的主要字段为模板、周期、补充要求。高级项包含受众、语言、时长、主题、全部／文件夹／指定文档范围和可选负责人。未填写负责人时直接展示创建者默认值，不要求用户额外确认这一常规默认。

创建后立即显示稳定的报告地址和生成任务，切页或关闭客户端不取消任务。重复点击沿用同一请求键；新建空白报告也使用相同领域模型。

### 5.3 编辑与审阅

2026-10-13 用户决策：编辑页为独立全宽「汇报工作室」。左侧是绑定本份汇报的项目 AI 会话（可收起为专注模式），会话随汇报记忆，并以 `reportContext`（汇报、修订、版本和当前选中的章节／节点）告知 AI 修改范围；右侧是所见即所得的幻灯片画布，顶栏提供标题、保存状态、章节目录、历史版本、缩放、选择／批注／编辑三种模式、来源、AI 任务、样式、演示（全屏／演讲者）、分享与导出和定稿。来源、AI 任务、评论、历史、样式、导出及检查器以右侧抽屉呈现。AI 的修改以候选形式出现，由用户在画布中对比并应用。支持直接编辑、章节重排、拆页、隐藏、删除、锁定、主题选择、图片、表格、图表、时间线及讲稿。

“隐藏”只是该版本的展示选择，不自动删除正文。外部导出和分享按明确的可见内容清单构建，隐藏内容不能藏在 HTML、PPTX 备注或包内数据中。

AI 局部修改绑定所选节点、草稿版本和来源版本，生成 patch 候选。人工采用时做三方合并：生成基线、当前草稿、候选结果。冲突逐项选择；锁定段落禁止自动改写。不能整篇重新生成后覆盖人工修改。

评论定位稳定章节／节点 ID 和文本锚点；正文变化后过期锚点转为「位置已变化」，保留原评论，不错误贴到另一段。评论可回复、解决、重新打开；审阅请求绑定草稿或定稿版本，后续修改使受影响审阅过期。审阅不是 Owner 强制审批。

### 5.4 更新与上期比较

「更新本份汇报」创建同一 report 的修订草稿；「基于上期生成」创建新 report，保存 `previousReportId` 和对比基线 revision。两者不能混用创建者规则。

比较新增成果、延续事项、状态变化、风险变化及计划变化，使用稳定事项标识和来源映射去重。名称相同不等于同一事项，AI 合并需保留依据及可撤销候选。资料更新只提示，不自动改写定稿。

## 6 模板与内容模型

### 6.1 模板体系

模板由内容结构、受众表达和展示主题组成。常用预设组合三者，避免强迫用户每次多层配置。

| 内置模板               | 必备章节                                                         |
| ---------------------- | ---------------------------------------------------------------- |
| 周报／月报／自定义周期 | 总体结论、本期成果、成员进度、阻塞、下一期计划。                 |
| 管理者决策             | 目标与结论、计划偏差、重要风险、资源需求、待决策事项、建议动作。 |
| 客户阶段成果           | 阶段目标、交付成果、成果展示、待确认事项、后续安排。             |
| 里程碑与验收           | 验收要求、逐项完成证据、未完成项、差异、后续处理。               |
| 项目结项               | 目标达成、最终交付、残余事项、交接与维护安排。                   |
| 项目复盘               | 计划与实际、关键决策、有效做法、问题及原因、改进行动。           |

自定义模板支持章节增删排序、必答问题、默认篇幅、受众与语气、默认提示词、布局、品牌色、Logo、许可字体和页面比例。支持从当前报告结构保存模板，默认不复制事实内容、私人备注和来源正文。

内置模板只读，可复制为项目模板。项目模板成员可维护，使用租约和版本检查；已发布模板版本不可变，停用不破坏历史引用。模板设置保存 DB-backed 版本，模型与系统提示继续复用现有注册表，禁止单进程配置成为第二真相源。

### 6.2 结构化内容

使用版本化 `ReportDocument` schema，包含报告元数据、章节、稳定节点 ID、页面布局、演讲备注、引用、核对项和附件引用。节点为明确联合类型：heading、paragraph、list、table、metric、timeline、image、chart、callout、pageBreak；不接受任意 HTML、脚本或无界 JSON。

图表支持柱状、折线、饼／环形及目标对比；每个序列保存可核验数据、单位、统计口径、空值和来源。无数值依据时使用文字表达，不能生成装饰性图表。默认负责人是确定性字段计算，不由模型自由生成。

章节、页面和节点身份在重排与内容修订中稳定。布局只引用内容节点，不复制第二份正文；渲染页号可以变化，内容定位使用节点 ID。

## 7 阅读 演示与离线使用

连续阅读保留完整正文、目录与可展开来源。分页演示默认 16:9，模板也支持 4:3；保持可读字号，表格和长内容按语义拆页，不通过无限缩小字体适配。

单屏演示支持全屏、左右方向键／空格翻页、Home/End、目录跳转、页码、进度、指示笔、临时黑屏、Esc 返回及焦点恢复。编辑输入时不抢占键盘快捷键。控制条自动隐藏但可通过键盘访问。

双屏模式提供独立观众窗口和演讲者窗口。演讲者显示当前页、下一页、备注、目标时长、计时和跳转。通过限定 origin、报告 ID、快照 ID 和随机会话 nonce 的通道同步翻页；观众窗口不接收备注正文。弹窗被阻止、显示器拔出或窗口关闭时可回到单屏，页面位置不丢失。

演示会话固定 immutable revision 或内部预览快照。草稿演示也先创建不可变预览快照，不跟随自动保存指针。项目成员被移除时在线会话终止访问并清理受控缓存。

离线演示包由明确下载操作生成，为自包含 HTML 与资源包，包含固定正文、所选主题和许可字体；无远程脚本、远程字体、在线项目接口或访问凭据。默认不含备注、评论、原始附件和内部来源；内部专用下载可显式选择备注。界面说明已下载副本不受后续在线撤销控制。

## 8 权限 协作与分享

### 8.1 项目内授权

有效成员可创建、阅读、编辑、评论、定稿、导出和按策略分享项目报告。负责人、创建者不是额外访问角色，不因默认责任归属取得管理成员或授权审批能力。

草稿默认项目内可见，创建界面明确提示。编辑使用独占租约，人工和 AI 共用状态与版本检查；Owner 不可强抢。报告独立租约记录复用既有租约算法和错误语义，不能通过伪造 ProjectResource 获得租约。

所有读取／写入先鉴权后读取正文；参数中的 projectId、reportId、revisionId、exportId、shareId 必须归属一致。列表、搜索、通知、WebSocket、缓存键和下载均做对应授权。

### 8.2 外部分享

创建外部分享时选择一个定稿版本和可见内容清单，预览后确认。支持指定账号访问；实例允许匿名链接时，才显示链接访问模式。可设置有效期、密码、允许下载，并随时撤销。改变访问对象、正文版本或下载范围形成新的授权版本并记录审计。

分享默认不包含评论、备注、核对面板、隐藏章节、内部节点／人员 ID、内部文档跳转或原始附件。来源标签可选择以不含内部链接的文字展示；源文件只在具有再分享权限且用户明确选择时单独发布。

共享投影由服务端从允许节点和资源生成。外部页面不复用内部详情接口后再靠 CSS 隐藏；HTML、预加载 JSON、PPTX 包、图表嵌入表格及 PDF metadata 均不得携带排除内容。图表只能嵌入实际使用的数据，不能附带整本原始工作簿。

每次在线访问重新检查链接状态、有效期、授权版本和身份。密码使用现有安全哈希能力，访问令牌只存哈希，凭据不进日志；下载通过可撤销的授权入口，不发长期绕过撤销的 Blob URL。设置 `noindex`、禁止共享缓存敏感正文并限制口令尝试。

项目归档时保留已授权定稿只读访问；项目进入回收站或删除、报告进入回收站时撤销外部链接并停止后续分发。恢复不自动恢复旧链接。链接授权人失去项目成员身份时，相关主动分享和周期分发暂停，其他有权成员可明确重新授权，旧访问不会静默继承。

## 9 版本与生命周期

报告的生命周期为 `active/archived/trashed`，正文状态由草稿指针和最新定稿指针表达；生成任务状态独立，禁止组合成难以验证的大枚举。

| 动作         | 持久结果                                                                |
| ------------ | ----------------------------------------------------------------------- |
| 自动保存     | 以 expectedVersion 和租约条件追加内容快照，CAS 更新草稿指针。           |
| 定稿         | 校验正文、来源清单与核对项，追加不可变正式 revision，记录操作者及时间。 |
| 继续修改定稿 | 以所选 revision 创建／复用修订草稿，不改写旧版。                        |
| 恢复历史版本 | 将历史内容复制为新草稿并保留恢复来源，不回退历史序号。                  |
| 归档         | 停止此报告的生成和更新，保留只读、历史和已授权查看。                    |
| 移入回收站   | 条件写入删除状态，取消运行、暂停关联计划、撤销分享，保留恢复证据。      |
| 永久删除     | 按现有保留／审计／legal hold 策略执行延迟 Blob 回收，不串删源文档。     |

存在来源缺失或事实冲突时允许人工编辑，但定稿需明确处理核对项：补充材料、修改表达，或保留真实的不确定性并记录处理理由。结构错误、跨域资源、缺失资产、无权限和伪造引用属于硬错误，不能靠点击确认放行。自动定稿不得越过任何未处理核对项。

源文档删除不会使已经合法保存的独立报告内容自动消失；原文跳转仍按实时权限处理。涉及来源保密撤销或平台删除义务时按既有删除／保留契约处置报告派生物，不能用“不可变”规避合法删除。

## 10 后台生成与运行状态

### 10.1 工作流

新增有版本的 Project 报告工作流：create、refresh、rewrite、export、scheduled-create、delivery。人工报告操作经领域服务执行；需要模型和长时间处理的操作进入既有 `AiAgentRun`，不要求创建私人会话作为报告所有权容器。

生成步骤为 discover、capture、extract、reconcile、compose、layout、validate、persist。UI 展示步骤和真实计数；未知总量不显示百分比。模型请求只使用全局 Project BYOK；缺失或停用时任务失败并显示可操作原因，不回退其他凭据。

资料和模板内容按不可信输入处理。来源文档中的“忽略规则”“发送文件”等文字只是材料，不得进入系统指令或触发额外工具。模型输出必须通过结构 schema、引用存在性、责任归属、数字口径及资产检查。

### 10.2 状态与竞争

复用运行时的 queued、running、waiting_approval、waiting_for_lease、cancel_requested、succeeded、failed、cancelled 等语义；名称按现有类型映射，不另外建立无持久依据的 UI 状态机。

- claim、heartbeat、step 提交和终态更新绑定 runId、attempt、lease token、expectedVersion。
- 过期 worker 即使取得模型结果也不能写回；新 worker 从持久 checkpoint 恢复。
- 模型阶段不长期占用人工编辑租约；提交候选或应用变更时重新校验基线，漂移转为待合并。
- 取消阻止后续副作用，已完成导出或已发出的分发不伪装为撤销成功。
- 幂等键绑定 actor、project、operation、目标 ID、输入指纹；同键不同输入拒绝，同键同输入返回原结果。
- 部分失败保留已确认的候选和覆盖证据，重试同一任务，不按标题创建新报告。
- 每次读取资料、发起模型调用、持久结果及对外分发前重查相关实时权限。

## 11 周期生成与明确授权的分发

计划保存项目、执行委托用户、模板固定版本、来源选择规则、周期算法、IANA 时区、当地执行时间、状态和配置版本。默认生成草稿并发送站内完成通知。无变化时明确写明没有新的文档进展，不能重新包装旧成果。

Occurrence 唯一键为 `(scheduleId, nominalLocalOccurrence, timezone)`，关联冻结的配置版本和真实 UTC 执行时间。夏令时重复时刻只执行一次；不存在的当地时刻顺延到下一个有效时刻。停机错过执行时默认补最近一次并记录其他漏执行，不集中制造大量历史报告；用户可以明确回补选定周期。

重试沿用 occurrence 和 reportId。修改计划只影响未 claim 的未来 occurrence；已 claim 的任务使用冻结配置。委托用户失权、Project 不可用或全局 BYOK 停用时暂停并通知，不自动换成 Owner 执行。

自动定稿与自动分发是分别配置的能力，默认关闭。启用时用户确认模板版本、内容投影、接收对象、通道、有效期、下载范围和上限，形成不可变授权快照。只有数据覆盖完整、没有冲突／未核对项、结构及引用校验全部通过时允许自动定稿；否则保留草稿等待处理。

分发通道为站内通知和实例已配置的邮件通道，不以新增第三方聊天集成为完成前提。外部邮件仅发送确认的说明和受控链接；附件分发须额外明确选择。发送前重新检查当前配置与冻结授权的交集，不能扩大收件人、字段或文件范围。

分发保存每个目标的 queued/sending/sent/failed/unknown 结果、幂等键和通道回执。发送结果不确定时先核对回执，不盲目重发；缺少幂等／回执能力的通道将不确定项交由用户处理，不能宣称跨外部系统严格 exactly-once。撤销计划停止未来执行，不抹掉历史回执。

## 12 导出与原生 Office

导出固定 revision 或明确的预览快照、受众投影、主题／字体版本及导出器版本。每次产物保存 MIME、大小、指纹、来源 revision、可见内容清单、兼容性结果和生成任务 ID。

| 格式   | 完整要求                                                                                         |
| ------ | ------------------------------------------------------------------------------------------------ |
| PDF    | 固定分页、可搜索正文、正确字体及图表；无裁切、溢出或缺失图片，支持打印。                         |
| PPTX   | 标题、正文、列表、表格、基础图形和图表为原生可编辑对象，图片为独立对象；保留明确选择的演讲备注。 |
| 离线包 | 自包含、安全的静态演示，图片和许可字体齐全，无项目凭据或在线数据依赖。                           |

默认生成下载产物，不自动污染项目文件树。用户选择「保存到项目」时，PDF/PPTX 创建具有 Project 归属的 OfficeArtifact/OfficeRevision 和对应 ProjectResource；离线 ZIP 使用原生普通文件。已有导出物更新绑定资源 ID 与版本，冲突不创建同名副本。

内部导出可选择备注和来源附录；外部预设默认排除。模板使用的特殊字体不可嵌入时显示替代字体并在预览中确认。支持节点必须实现完整导出；超出明确支持范围的效果列出兼容性提示，不以整页截图冒充可编辑 PPTX。

报告结构是报告内容的 source of truth，导出文件是独立快照。用户继续编辑导出 PPTX 不反向静默改变报告；再次导出也不覆盖外部编辑，必须选择新副本或受版本保护的显式更新。

## 13 数据模型与数据库约束

名称为本功能新增逻辑实体，落库遵循现有 Prisma 命名；正文及大清单放不可变 Project Blob，DB 保存关系、指纹、状态与指针。禁止用无 schema 的 JSON 代替所有关系。

| 实体                               | 核心字段与职责                                                                                                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ProjectReport                      | id、projectId、title、createdByActorId、responsibleIdentity、responsibilityOrigin、lifecycle、version、draftRevisionId、latestFinalRevisionId、previousReportId、周期及时区。          |
| ProjectReportRevision              | reportId、projectId、sequence、kind、parentRevisionId、contentBlobKey/hash、templateRevisionId、sourceManifestId、actor、reason、createdAt；kind 区分 draft snapshot、preview、final。 |
| ProjectReportSourceManifest        | 执行者、来源选择、截止时间、覆盖计数、固定来源项及定位、提取器版本、引用／核对项和内容指纹；正文引用放受控 Blob。                                                                      |
| ProjectReportTemplate / Revision   | project 或内置归属、状态、稳定身份、版本化内容结构／主题／默认提示词、创建和发布证据。                                                                                                 |
| ProjectReportEditLease             | reportId、projectId、holder/tab 或 task、lease token、epoch、到期时间；复用既有租约机制。                                                                                              |
| ProjectReportComment / Review      | 版本化锚点、作者、内容、回复、解决状态；审阅请求、受审版本与结果分开。                                                                                                                 |
| ProjectReportExport                | revision、audienceManifest、格式、任务、状态、产物 Blob／原生资源 ID、指纹、兼容性及下载授权。                                                                                         |
| ProjectReportShare / Revision      | report/revision、投影、访问模式、目标账号、token/password hash、授权人、期限、下载策略、撤销状态、授权版本。                                                                           |
| ProjectReportSchedule / Occurrence | 配置、委托身份、时区和周期、冻结授权、执行唯一键、runId/reportId、结果。                                                                                                               |
| ProjectReportDelivery              | occurrence 或手动请求、目标身份、授权版本、状态、发送指纹与通道回执。                                                                                                                  |
| ProjectReportAuditEvent            | 谁在何时对什么 ID/版本做何操作及结果，引用 run/outbox；不存私密全文或令牌。                                                                                                            |

运行状态复用 AiAgentRun/step/timeline/result；新表只能保存报告业务扩展和外键，不复制第二套 run 状态。ReportDocument 中每个需要责任归属的事项保存有类型的负责人及来源，默认字段在服务端填充。

必须在数据库层落实：

1. `(id, projectId)` 组合键和同项目复合外键，禁止报告指向另一项目的 revision、来源清单或 Blob。
2. `(reportId, sequence)` 唯一；父 revision 必须同报告；不可变 revision 和创建证据禁止一般更新。
3. 报告创建请求、导出请求、occurrence 和分发目标均有唯一幂等约束，输入指纹不允许后写覆盖。
4. report current pointers 只能指向自己的合法 revision；递增序号、定稿与 outbox 在事务内提交。
5. 同报告只有一个有效编辑租约，条件更新包含 token/epoch/expiry；跨表检查不能只靠前端。
6. share 当前授权指针只指向同 share 的不可变版本；撤销与下载鉴权串行化，过期状态不能被迟到请求重新激活。
7. 来源 Blob、导出 Blob 的删除使用引用关系与保留策略，禁止级联删除原始项目文档。
8. 账号删除采用平台既有最小身份保留策略，不使用删除用户导致全部历史报告丢失的级联关系。

## 14 API 与模型工具契约

以下为目标 operation 名称及职责，全部通过仓库 GraphQL 生成流程维护，禁止手改生成类型。列表统一 cursor/limit，默认 30、最大 100；资源 ID 不以标题代替。

| 类别           | Operation                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 查询           | `projectReports`、`projectReport`、`projectReportRevisions`、`projectReportSources`、`projectReportComments`、`projectReportTemplates`、`projectReportSchedules`、`projectReportExports`。 |
| 创建与编辑     | `createProjectReport`、`saveProjectReportDraft`、`updateProjectReportMetadata`、`duplicateProjectReport`、`createProjectReportFromPrevious`。                                              |
| AI             | `generateProjectReport`、`refreshProjectReport`、`rewriteProjectReportSection`、`applyProjectReportCandidate`。                                                                            |
| 版本与生命周期 | `finalizeProjectReport`、`restoreProjectReportRevision`、`archiveProjectReport`、`trashProjectReport`、`restoreProjectReport`。                                                            |
| 协作           | 租约 acquire/renew/release、comment/reply/resolve、requestReview/submitReview。                                                                                                            |
| 模板           | create/save/publish/duplicate/archive 模板，发布绑定 expectedVersion。                                                                                                                     |
| 输出           | `exportProjectReport`、`saveProjectReportExport`、`createProjectReportShare`、`updateProjectReportShare`、`revokeProjectReportShare`。                                                     |
| 周期           | create/update/pause/resume/rebind/runNow/backfill 计划；修改或重绑授权必须明确确认。                                                                                                       |

写入输入统一包括 requestKey、projectId、目标 ID、expectedVersion，编辑再加 lease token；长任务返回 runId 和稳定 reportId，不把尚未完成的生成说成成功。导出、分享绑定 revisionId 和投影指纹，不能使用会漂移的 latest 字符串。

外部分享走独立 controller/DTO，先完成账号或链接认证，只返回共享投影。不得使公开请求访问内部 GraphQL 的任意报告、来源或项目列表。

内部 Project AI 可注册 `project_report_list/read/create/update` 等有类型工具，复用相同领域服务并仅在 Project 上下文注册。工具只读取报告显式选择的文档，不因从私人会话发起而导入聊天正文。分享权限、计划授权和审批决定由用户通过 UI 或现有明确确认机制完成，模型不能自行扩大。

新能力不注册 Workspace 别名，不把内部工具自动暴露给公开 MCP。公开扩展若日后提出，必须另定独立授权及冻结能力迁移契约。

## 16 实时 错误和可访问性

通过现有 Project realtime/outbox 增加 report/template/schedule 的 changed 事件。事件只携带获准订阅的 ID、版本和变化类型，正文经授权查询读取。重连用版本恢复，忽略其他项目和旧 run 的迟到消息，不能重置用户选中章节、滚动位置或未保存内容。

| 原因码                             | 用户行为                                       |
| ---------------------------------- | ---------------------------------------------- |
| `REPORT_SOURCE_INCOMPLETE`         | 展示可见的未覆盖项，重试或在正文明确范围。     |
| `REPORT_FACT_CONFLICT`             | 跳到核对项，查看证据，修改或保留不确定性。     |
| `REPORT_VERSION_CONFLICT`          | 保留本地内容，展示差异并重新合并。             |
| `REPORT_LEASE_UNAVAILABLE`         | 只读和查看持有人，允许等待，不强抢。           |
| `REPORT_PERMISSION_CHANGED`        | 停止读取／写入，撤销受控会话，不暴露来源详情。 |
| `REPORT_PROVIDER_UNAVAILABLE`      | 说明项目 AI 配置不可用，保留报告和任务记录。   |
| `REPORT_EXPORT_INCOMPATIBLE`       | 列出具体元素和替代结果，返回预览。             |
| `REPORT_SHARE_EXPIRED` / `REVOKED` | 外部页展示统一不可用状态，不泄露项目内容。     |
| `REPORT_DELIVERY_UNKNOWN`          | 显示需核对通道结果，不自动重复发送。           |

每个异步入口覆盖 loading、empty、error、success、disabled、重复提交、取消和失权。编辑支持键盘、输入法、撤销重做、焦点恢复；状态不只靠颜色。浅色／深色、减少动画、屏幕阅读器标签、窄屏阅读和长标题都属于完整验收。

## 17 边界 预算与性能

所有输入和任务有界。初始可配置默认：报告最多 100 个演示页、60 个章节、200 个媒体对象，单次 command JSON 不超过现有 2 MiB 上限；正文和来源大清单使用 Blob，不塞进命令。列表最大 100 项／页。导入文件大小沿用其原生资源上限，不另行放大。

全量枚举分页继续直到完成或达到明确的资源预算；达到预算必须显示覆盖不足并要求缩小范围或经配置增加预算，不能静默截断。模型上下文按实际 token 上限分批，单次提示保留系统、安全和输出预算，任务总费用／token 上限由实例配置控制。

素材只能来自授权 Blob 或经过现有导入流程的资源，阻止模型引入远程追踪图片、任意 URL 抓取、路径穿越和压缩炸弹。来源正文、备注、密码、token 和完整模型提示不进入普通日志；调试证据按权限、大小与保留期控制。

性能验收使用记录硬件、网络和构建版本的固定 fixture：1000 份项目文档、1000 份汇报列表、30 页常规报告和 100 页上限报告。参考环境为应用 4 vCPU/8 GiB、独立 PostgreSQL/Redis、受控网络；列表查询 P95 不超过 1 秒，已加载演示翻页 P95 不超过 100 毫秒。冷启动／大资源加载单独记录，不用缓存结果冒充冷启动。

AI 时延按模型、输入规模、输出页数分别记录，不承诺与模型无关的固定完成秒数。断线、后台恢复、多个项目并发和大项目预算触发都须证明数据不会遗漏或串域。

## 18 迁移 发布与回退

新增 Prisma 表、索引、复合外键、不可变约束与 outbox 类型，迁移为增量。既有 project_summary 不自动迁移为报告，历史私人会话不回填成报告来源；内置模板通过幂等版本种子建立。

必须验证空库全量迁移，以及包含现有 Project、Memory、Office、工单、任务和 Blob 的旧库升级；升级后旧入口和数据不变。用户删除／Project 删除的关系与 GC 队列要同时验证，不能只通过 prisma generate。

发布顺序为备份并验证恢复、兼容 schema、后端领域与 worker、生成协议及前端、模板种子、完整验收后开放入口。功能开关作为发布控制，不能把只读占位页面当交付。

回退先关闭新生成／分享／分发入口并暂停对应 worker，保留既有定稿可读和授权撤销能力；不 drop 报告表或删除 Blob。已发送的外部副作用保留回执，不能回退代码后重发。

业务环境同步只有在用户明确授权时执行，使用 `yarn localmind:sync:*`。涉及 schema/native 时先备份，按 Docker 契约提供 `LOCALMIND_RUNTIME_SOURCE_CONTAINER` 和 `LOCALMIND_DATABASE_BACKUP`；同步容器不等于更新发布镜像。

完整交付必须包含全部业务入口、持久数据、服务端规则、生成文件、迁移、模板、原生导出、分享与周期任务，并通过 A01—A60。功能开关关闭、占位按钮、静态假数据、只有类型生成或只有顺利路径测试均不满足交付。

执行记录逐项列明源文件、迁移与恢复证据、真实模型结果、浏览器和原生 Electron 证据、导出样本、容器命令、固定镜像及是否重建、磁盘状态、未通过项与剩余风险。区分源码完成、隔离验收、运行环境同步和生产状态。

任何能力不能完成时，保持为未完成项，不自行改称“后续增强”。commit、push、PR、业务同步和部署仍需各自明确授权；本文档请求不授予这些操作权限。
