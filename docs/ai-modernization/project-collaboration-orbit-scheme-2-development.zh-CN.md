日期：2026-09-29。状态：源码回填与本机运行容器同步完成，正式验收部分完成；逐项结果与剩余证据见[执行记录](project-collaboration-orbit-scheme-2.execution.zh-CN.md)。

## 1. 目标与范围

将独立方案二原型接入 LocalMind `/project` 总览的「关系」视图，形成可以查看真实协作关系、预览工单、读取详情和打开本人授权会话的正式功能。

目标体验为：本人头像居中，协作者围绕本人排列；悬停或点击头像后，小球依次绕行并逐颗滑出成为透明胶囊；点击胶囊在原位展示真实工单详情。

本轮按用户最新决定，不考虑大数量场景：不新增大数量布局策略、虚拟化、分页、动画批处理、跳过动画或「立即展开全部」按钮，不安排大数量性能专项验收。现有服务端查询边界和 `truncated` 提示继续有效；正常数据完整呈现，不额外添加工单数量截断。

本次交付包括：

1. 正式关系视图的布局、头像、工单胶囊、动效、有限相机及详情浮层。
2. 真实头像、关系摘要、工单详情、草稿和授权会话导航的接入。
3. 主题、i18n、触屏与键盘适配，聚焦测试和真实产品验收。
4. 实际执行配套 Goal 时，在验证通过后按仓库脚本同步本机 LocalMind，并复验 `/project`。

方案一和方案二原型保留在仓库外作为对照。正式页面不引入原型的示例数据、调试控制台、随机照片和模拟加载逻辑；不新增关系数据库或 BlockSuite Surface/YDoc。

## 3. 页面与视觉结构

### 3.1 页面接入

- 使用 `/project` 现有「条目／关系」切换入口，方案二成为「关系」视图的默认内容。
- 星图铺满主区域的可用空间，移除「我的协作」外框、图表四周线条、横向分隔和右侧固定工单栏。
- 复用页面已有项目筛选及「个人工单」来源筛选；同一筛选只保留一个状态源，避免原型和页面各放一套。
- 顶部提供搜索、方向统计和历史协作开关；底部提供缩放与「查看全图」。项目导航使用现有展开／恢复工作区能力。
- 使用组件容器尺寸分配高度，防止嵌入产品壳后重复使用 `100vh` 导致溢出。浮动工具条、详情层和项目导航的层级明确。
- 无关系时仍显示本人头像与空态说明；筛选无结果时保留清除筛选入口。

### 3.2 人物和方向

- 全图只有一个本人节点，每位协作者只有一个节点；同一个人的双向工单聚合到同一头像。
- 本人头像直径固定为 112 个世界坐标像素。
- 协作者头像大小按当前筛选范围内未完成工单数 `n` 计算：`n = 0` 时为 40；否则为 `min(112, sqrt(44² + (n - 1) × 700))`。同时显示明确数量。
- 正常状态使用真实照片，缺失或加载失败时由现有 `Avatar` 组件显示姓名首字；无工单时本人资料从现有登录账户服务获得。
- 蓝色表示「对方 → 我」，橙色表示「我 → 对方」。浅色参考为 `#3658d8 / #b34f0b`，深色参考为 `#8dacf9 / #ffb36b`，映射为局部语义 token。
- 头像环、胶囊边框、小标记和方向筛选共用方向语义；方向同时有文字，不能只靠颜色识别。
- 人物所在左右位置决定展开朝向，不决定交付方向。
- 保留本人至协作者的浅灰轨道、两端渐隐的蓝色流光。双向交付使用两条分开的曲线，沿相反交付方向流动。协作者之间无外层连线，头像与胶囊之间无连线。

### 3.3 胶囊与详情

- 每张未完成工单对应唯一胶囊，稳定 key 为工单 ID。交付要求不拆成多个胶囊。
- 胶囊尺寸沿用 276 × 40、完全圆角、2px 方向色边框，只显示方向标记和标题。
- 默认、悬停、选中、固定详情时底色均透明；强调使用方向色外轮廓。
- 沿头像朝外方向以小弧度排列，每列最多 5 张，相邻角度 13°，新增列沿外侧排列，列基线间距 332。正常数量的全部胶囊均显示。
- 详情采用屏幕坐标，不随相机缩小字号；靠边自动换侧或约束到可用区域。
- 手机和窄容器使用底部详情面板，具有关闭按钮、滚动区域、焦点管理及安全区留白。

## 4. 正式数据契约

### 4.1 单一数据来源与方向

沿用现有 `copilotCollaborationGraphGetQuery / myCollaborationGraph`。正式类型来自生成的 GraphQL 类型，不能将原型自定义 DTO 当成正式协议另存一份。

现有字段为 `from = 发单人`、`to = 接单人`。成果交付方向必须投影为：

```text
deliveryFrom = to
deliveryTo = from
incoming = deliveryTo 等于当前用户 ID
outgoing = deliveryFrom 等于当前用户 ID
```

先按项目／来源及搜索范围过滤，再按工单 ID 去重、按协作者用户 ID 聚合。交付方向、人数、数量、颜色及工单筛选从同一模型得出。本人给本人或缺失合法参与者的异常数据不生成第二个本人节点。

搜索沿用协作者姓名、工单标题和来源项目名；历史开关只控制历史展示，不增加头像的未完成数量。普通刷新中的现有协作者保持稳定位置，新增或移除身份局部调整；项目／搜索范围切换允许重新布局。

### 4.2 状态与计数

| 服务端事实                                      | 星图处理                                                         |
| ----------------------------------------------- | ---------------------------------------------------------------- |
| 已发送且为 `open / waiting_sender / validating` | 计入未完成数、头像大小和相应方向数；显示真实状态文案             |
| `delivered / adopted / refused / cancelled`     | 进入历史入口，不计入未完成数；拒绝和取消不能写成成功交付         |
| 有效 `kind = draft`                             | 当前用户专属「待确认」入口，独立计数，不进入未完成义务或交付动效 |
| 草稿过期、确认发送或来源失权                    | 按既有契约移除／刷新，草稿与正式工单不能重复计数                 |

`adopted` 继续采用服务端基于当前交付版本和对应来源会话判断的结果，不能由前端根据「曾经查看」或历史采用自行推算。

待确认入口按项目／搜索范围筛选，点击原位展示摘要与「打开来源对话」，仅从本人原会话继续确认。仅有草稿时仍可发现待确认入口。

保留 `truncated` 反馈；若存在截断，标明数量和头像大小基于已加载范围。此项属于既有数据真实性约束，不扩展为大数量专项。

### 4.3 真实头像

当前正式节点仅有 `id / label / self`。在既有节点类型中增加可空 `avatarUrl`，模型、resolver、查询及生成类型一起更新。

- 只给当前 actor 已获授权的关系人物返回账号允许展示的头像。
- 复用现有用户头像存储和 URL 生成机制，不假设数据库直接存在 `avatarUrl` 字段。
- 在现有批量参与者读取中取值或批量补齐，避免逐头像独立查询。
- 不新增头像表，不从网络随机下载正式人物照片，不携带额外个人资料。
- 所有既有 `myCollaborationGraph` 消费者必须兼容这个可空字段。

预计无需 Prisma 迁移。若实施时发现确需改变持久结构，应给出必要性及升级验证，不能仅为视图便利新增表或字段。

### 4.4 摘要、详情与日期

- 悬停预览使用图查询已有字段：标题、状态、成果交付双方、来源项目、交付要求短标题。
- 点击胶囊后按工单 ID 使用现有 `copilotCollaborationOrderDetailsQuery / myWorkOrder` 读取目的、必交付项和说明；不把完整正文装入批量图查询。
- 详情请求按用户与工单身份隔离；切换工单后旧请求结果不得覆盖新浮层。刷新、删除或失权时清理失效详情。
- 用真实 loading、error/retry、unavailable 状态替代原型定时器。错误通过现有友好错误映射显示。
- `expiresAt` 用于草稿失效，正式已发送投影当前返回空值；不能把它标成工单截止日期。没有真实截止字段时不显示虚构截止日期。
- 点击详情底部「打开／新建对话」才调用现有 `onOpenRelation` 及 `openWorkOrderConversationMutation`。沿用本人会话恢复、项目／Workspace／个人工单导航、pending 防重及失败反馈。
- 悬停、展开、筛选、选中和打开详情均为读操作，不创建会话、不确认草稿、不提交交付或采用。

## 5. 交互状态与有限相机

### 5.1 状态约束

建议集中管理 `hoverUserId`、`pinnedUserId`、`directionFilter`、`activeOrderId`、详情预览／固定模式和动画代次；不要分散创建互相冲突的选中状态。

| 操作             | 行为                                               |
| ---------------- | -------------------------------------------------- |
| 悬停头像 140ms   | 临时展开一名协作者；快速划过不触发                 |
| 点击该头像       | 固定已有展开，动画继续；不重新播放                 |
| 再次点击固定头像 | 收起该人物工单                                     |
| 点击另一头像     | 取消并退出旧动画，切换到新人物                     |
| 已固定时悬停他人 | 仅强调关系线，不抢走固定展开或方向筛选             |
| 鼠标移出 450ms   | 未固定时收起；经过头像至胶囊的几何安全通道不误关   |
| 悬停胶囊 220ms   | 原位摘要预览，不抢焦点                             |
| 点击胶囊         | 固定真实详情；关闭后焦点回到对应胶囊               |
| Esc              | 优先关闭详情，再收起展开；点击空白按原型解除展开   |
| 触屏和键盘       | 点击／Enter 展开，Tab 定位，Esc 关闭；不依赖 hover |

任一时刻只展开一名协作者。固定详情时禁止鼠标经过其他头像替换当前内容。方向筛选精确作用于此人的工单。

### 5.2 相机与刷新

- 所有人物、胶囊和 SVG 连线共用同一世界坐标与视角变换；节点不能单独拖动。
- 场景是有限图；保留既有中心缩放、平移、触屏双指缩放、键盘与边界约束。
- 初次及项目／搜索范围切换可以适配；普通数据刷新、头像加载、历史切换、详情打开及尺寸变化保留缩放比例，必要时仅约束有限边界。
- 展开前预留正常胶囊范围，悬停和出场动画不移动相机。点击固定后的必要定位只平移到本人操作对象及第一列可见；已打开详情时不被迟到的动画完成事件带走。
- 方向筛选或数据更新不重播整圈出场；保留仍有效的选中身份，移除已失效的工单／人物状态。
- 复用 `useProjectRefresh(null, 'task', ...)`、页面聚焦、网络重连和草稿最近到期的刷新机制；不另加固定轮询。
- 账户切换、退出页面、组件卸载时清理定时器、动画、观察器和请求关联；旧回调不得恢复已离开的状态。

## 6. 动效规格：实施锁定值

| 项目         | 当前确定值与行为                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 逐颗出发间隔 | **216ms**，按绕圈时长的六分之一向上取整；等待期间隐藏，最多六颗同时绕行，所有在轨小球之间保持超过 6px 的边缘间隙 |
| 起点         | 头像上方；第一颗出现后立即开始运动                                                                               |
| 旋转时间     | **`2000 / 1.5 / 1.5 / 2 / 0.7 / 0.7 / 0.7` ms，约 1296ms**，转动速度降至上次 907ms 版本的 70%                    |
| 左右旋转     | 右侧人物顺时针、左侧逆时针；共用圆周路径，转过一圈多 30° 后立即沿各自曲线分向目标胶囊                            |
| 绕行动作     | 减轻先慢后快再放缓的速度起伏（90% 匀速、10% 原缓动），避免紧凑出球时追撞；出口速度不降到零，与滑出曲线衔接       |
| 小球形态     | 绕行全程宽高相等；100ms 淡入，从直径约 5.8px 随绕行持续平滑增大，出口恰好达到原尺寸 32px，无缩小或过冲           |
| 圆周变化     | 多球轨道基准半径固定为 **50px**，保留最多 8% 的半径变化；单球与头像边缘至少相隔 8px；胶囊和场景边界预留轨道空间  |
| 转场         | 每颗转完即独立滑出，同时开始变成胶囊，不等待其他球；分流在滑出阶段完成                                           |
| 滑出与变形   | 滑出 400ms、变形 640ms **同时开始**；轻微过冲并回弹，单颗总时长约 1936ms                                         |
| 底色         | 绕行最后 100ms 褪去小球填充，胶囊整个变形和稳定阶段透明                                                          |
| 标题         | 变形阶段经过 25% 时开始淡入；不缩放或拉伸文字                                                                    |
| 完成与退出   | 每颗落位后独立可操作，不等待整组；退出 160ms，清理尚未出发的球                                                   |

使用原生 Web Animations API 和已有 SVG 动画，不增加动画依赖、不逐帧 setState。复用原型的代次校验、动画取消及 StrictMode 清理机制。

交付线的流光方向继续表示成果交付方向。动画在页面隐藏或图离开视口时按现有规则暂停。工单出场沿用原型已有系统动效偏好处理，不新增“减少动态效果”界面选项。

## 10. 验证、同步与完成条件

### 10.1 验证方式

- 使用仓库既有 GraphQL／i18n 生成命令，不手工修改生成文件。实施时核对脚本并记录实际命令。
- 聚焦运行新旧关系图模型、布局、相机、组件、头像投影及参与者授权测试；保留原有数据和权限回归。
- 按影响运行 `yarn lint:ox <changed-files>`、Prettier、相关 typecheck 及 `git diff --check`。具体测试文件随新增组件确定，使用现有 Vitest／服务端测试入口。
- Linux 验证优先复用 `localmind-affine:test` 和已有容器。日常源码变更不默认重建镜像；确需构建遵守固定镜像角色和磁盘门槛。
- 浏览器必须验收集成后的 LocalMind，不能用独立原型页面替代。动效检查留录制或时间点证据；截图用于布局、主题和浮层。
- 如果工具访问策略拒绝浏览器操作，报告拒绝的操作和原因；不通过其他浏览器、CDP 或地址绕过，相关项保持待验收。

### 10.2 本机同步

本文档的创建不会执行同步。用户实际提交配套 `/goal` 后，任务范围包含验证通过后的本机 LocalMind 同步及 A19；不包含远端部署。

同步前检查实际差异及运行时基线。头像字段涉及后端和共享 schema 时必须匹配前后端版本，按现有 `yarn localmind:sync:all` 流程处理，不仅更新 Web。遵守根级 AGENTS 中的数据库备份、同平台 Linux 运行证据、`LOCALMIND_RUNTIME_SOURCE_CONTAINER` 和 `LOCALMIND_DATABASE_BACKUP` 条件。

当前工作区存在其他改动，不得把无关且未验证的后端、迁移或 native 差异随本专项悄然同步。先确认受支持的同步路径能保持范围且运行证据一致；不能满足时记录具体阻塞，保留已完成的代码和测试结果。禁止手工散拷文件绕过脚本核对。

同步日志应说明实际更新范围、使用的源容器、备份位置、是否重启／重建及复验结果。同步容器不能表述为已更新发行镜像。

本任务不自动 commit、push、创建 PR、部署远端或删除持久化数据；不启动子代理。用户后续明确调整范围时，以最新指示更新实施记录。
