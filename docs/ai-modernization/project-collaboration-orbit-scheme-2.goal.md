### 二、必须实现

1. **正式入口与无框布局。** 保留现有「条目／关系」入口，将关系视图替换为方案二，星图铺满主区域可用空间。去掉旧“我的协作”外框、横向分隔和右侧固定工单清单，合并现有项目／个人工单筛选，加入搜索、方向统计和历史入口。复用项目导航展开、恢复机制。
2. **真实身份和统一模型。** 本人唯一、每名协作者一个头像；双向和跨项目工单按用户 ID 聚合，工单按 ID 去重。头像大小按当前范围的未完成工单数计算。保持正式 `from = 发单人 / to = 接单人`，视图采用 `deliveryFrom = to / deliveryTo = from`。布局位置不能代替交付方向判断。
3. **状态与权限。** 已发送的 `open / waiting_sender / validating` 计入未完成；已交付、已采用、已拒绝、已取消进入历史。有效本人草稿进入独立待确认入口，不形成交付义务、不计入头像大小。保留草稿期限、确认去重、来源权限、当前交付版本采用语义和截断反馈；不扩大其他参与者资料或私人会话访问范围。
4. **真实头像。** 在既有 actor-scoped 关系节点中补充可空 `avatarUrl`，批量取得允许展示的头像，复用已有头像存储／URL 机制和 `Avatar` 回退。同步 resolver、查询及生成类型，检查其他消费者。预计不新增数据库结构；若确有必要，按仓库迁移约束说明与验证。
5. **原位详情。** 悬停读取已有摘要，点击胶囊按 ID 调用现有 `myWorkOrder` 查询完整目的与交付要求。实现 loading、失效、错误重试、旧请求隔离及焦点恢复。桌面原位浮层，窄屏底部面板。`expiresAt` 是草稿到期，不当作截止日期；没有真实截止字段就不显示虚构日期。
6. **授权导航。** 详情内“打开／新建对话”复用 `onOpenRelation` 和既有 `openWorkOrderConversationMutation`，保留本人会话恢复、项目／Workspace／个人来源路由、pending 防重和错误反馈。悬停、展开、筛选和读取详情不能创建会话、确认草稿或修改工单状态。
7. **锁定动效。** 出球间隔 280ms，绕行时间 `2000 / 1.5` ms；第一颗出现后立即转动，后续从同一起点依次出现。右侧顺时针、左侧逆时针，先慢后快再放缓；绕行全程圆形，取消拉长和压扁。每颗到各自出口立即带着连续速度滑出并变形，不能到顶部集合或等待其他球。滑出 400ms 与变形 640ms 同时开始，胶囊透明、轻微回弹，标题不变形；每颗完成后即可操作。保留 160ms 退出、动画取消及迟到回调防护。全参数以开发文档第 6 节为准。
8. **统一交互。** 一次展开一个人物；140ms 悬停临时展开，点击固定不重播，再点收起，点击其他人物切换；固定详情不被悬停抢走。保留 450ms 离开宽限和几何安全通道、220ms 工单预览、Tab／Enter／Esc 和触屏等价操作。工单胶囊为 276 × 40 全圆角、方向色边框，所有胶囊状态底色透明。
9. **有限相机与刷新。** 人物、胶囊、连线同一视角变换，禁止节点拖拽。沿用中心缩放、平移、边界约束和查看全图；悬停及动画不移动相机，点击后的定位保留比例。普通刷新、头像加载、详情和尺寸变化不重播、不重置缩放。项目／搜索切换按场景更新。复用现有事件、聚焦、重连及草稿到期对账，正确清理动画、观察器和定时器。
10. **工程接入。** 使用现有 React、HTML、SVG、Web Animations、`@affine/component`、`.css.ts`、主题 token、图标和 i18n。原型只是视图参考，不能复制调试入口、随机照片、模拟加载、第二套领域数据或业务逻辑。保留现有 GraphQL 授权与领域服务。
