# Workspace 文件夹与页面双容器开发方案

状态：双容器产品方向确认于 2026-10-09。v2 实现已按用户授权集成本地 main，隔离验证范围与限制见[执行记录](workspace-resource-tree-dual-container.execution.zh-CN.md)。本文保留完整目标；页面转文件夹尚未开放，不能把本地集成视为全部验收或部署完成。

Workspace 在同一棵资源树中保留文件夹和 LocalMind 原生页面。文件夹用于整理资源，页面用于编写正文并组织下级；用户每次新建时选择类型，两者可以相互嵌套。资源仍只有一个真实位置，正文引用不决定归属。

本方案覆盖[原页面树方案](workspace-page-tree-development.zh-CN.md)中“页面是唯一容器”“文件夹退场”“旧文件夹全部转页面”的规则。原方案的唯一归属、内容隔离、授权、不可变证据、读路径和同步边界继续适用。发生冲突时，以本方案为准。

## 1 实施基线与范围

当前独立 worktree 为 `/Users/dev2/.codex/worktrees/workspace-page-tree/LocalMind`，分支为 `codex/workspace-page-tree`。其中 `localmind-page-tree/v1` 候选实现及隔离验证见[执行记录](workspace-page-tree.execution.zh-CN.md)。该候选版本只允许页面作为容器；不能将它的测试结果计作本方案的完成证据。

开发和体验在该 worktree 中完成，保留领域服务、唯一归属、回执、迁移基础和 UI 组件。用户于 2026-10-09 授权合并到本地 main；此授权不包含推送、部署或实际业务库迁移。主目录其他未提交改动继续保留。

### 1.1 用户可见规则

| 类型                            | 能否容纳下级 | 打开方式                     | 正文与内容存储                     |
| ------------------------------- | ------------ | ---------------------------- | ---------------------------------- |
| Workspace 根目录                | 可以         | 工作区导航与既有主页         | 不是新建资源类型                   |
| 文件夹                          | 可以         | 文件夹直属资源列表           | 仅组织元数据，没有 BlockSuite 正文 |
| 页面                            | 可以         | 原生编辑器及直属资源列表     | 独立、真实 BlockSuite 文档         |
| 白板                            | 不可以       | 原生白板编辑器               | 保持原有存储                       |
| Word、Excel、PPT、PDF           | 不可以       | 对应原生 Office 编辑器或预览 | OfficeRevision                     |
| TXT、Markdown、CSV、JSON 等文件 | 不可以       | 对应文件编辑器或预览         | WorkspaceFile 及不可变 Blob        |

本文“页面”专指 LocalMind 原生文档，不包括 Word 文件。纯本地 Workspace 本期提供文件夹、页面和白板；原生 Office／文件的离线能力不因双容器而扩大。

文件夹内可以创建文件夹和页面；页面内也可以创建文件夹和页面。两种容器都允许放入在线 Workspace 已支持的 Office 和普通文件。不存在整个 Workspace 的“文件夹模式／页面模式”开关。

### 1.2 保留的不变量

1. 每个活动或已回收资源具有唯一父级，根用 `null` 明确表示。文件夹也有唯一位置，不能通过重复放置实现多父级。
2. 父级只能为当前 Workspace 内的活动文件夹或原生页面；不能指向自身、后代、叶子、已回收节点或其他 Workspace。最大深度仍为 64 层。
3. 移动只改变归属，不复制内容、不改变后代身份，也不改变文件 Blob 或 OfficeRevision。
4. 正文普通引用、收藏、标签、集合和搜索结果只承担内容或导航用途。它们不产生第二个位置。
5. UI、内部 AI、导入、本地上传及 Project 发布复用同一领域服务与实时权限检查；不恢复旧侧栏链接写协议。
6. Workspace 双容器不改变 Project 内部文件树、成员能力或显式发布的独立副本语义。

## 2 交互方案

### 2.1 统一创建菜单

根目录、文件夹行和页面行均提供「＋」。菜单顶部显示“创建于：工作区／父级路径”，首组为“新建文件夹”“新建页面”“新建白板”，其余沿用现有 Office、文本格式和上传入口。模板入口按既有支持范围保留。

- 新建文件夹：输入名称后提交，成功后展开父级、选中新文件夹并打开其列表。名称在客户端和服务端均 trim，长度限制沿用 1—512 字符；允许同父级同名，以身份区分，不按名称覆盖。
- 新建页面：等待资源与归属共同提交，再打开编辑器。失败保留输入，重试沿用同一请求键，不降级为根页面。
- 页面正文“子页面”命令保持创建真实页面并插入明确入口。首版不增加“正文内新建文件夹”块；页面旁「＋」已能创建下级文件夹。
- 创建与上传过程中显示目标、进行中和错误状态；提交中防止重复操作。迟到响应不得切换到另一个账号或 Workspace。

### 2.2 侧栏与移动

侧栏复用现有树行、文件夹和页面图标。点击箭头展开，点击名称打开对应内容。文件夹和页面的「＋、排序、更多」顺序、焦点行为、悬停与触屏入口一致。

拖入行内代表“移动到该容器”；拖到行间代表同级重排。提供“移动到…”对话框，目标选择器同时显示文件夹和页面，并明确根位置。禁止目标显示不可选原因，不能靠图标或颜色让用户猜测。

排序保留名称正序、名称倒序、手动排序；默认不强制“文件夹置顶”。同一层的全部类型一起参与当前排序。手动重排必须提交完整受权同级顺序；个人排序只改变显示，组织重排需要相应写权限。撤销绑定提交版本，遇到其他人结构变更时提示刷新后重新操作。

### 2.3 文件夹页面

文件夹路由建议使用 `/workspace/:workspaceId/folder/:nodeId`。它是资源位置视图，不调用 `openDoc(folderId)`，不生成空白文档。

界面复用现有资源列表：面包屑、文件夹标题、创建按钮、显示菜单、直属混合列表。标题菜单提供重命名、移动、转换为页面、回收及符合权限的目录管理。空态显示“此文件夹为空”和可用创建入口。

列表支持文件夹、页面、白板及原生资源，复用现有选择、快捷操作、元数据和分组组件。文件夹行不显示正文摘要；创建者和时间、更新者和时间必须成对展示，历史未知值显示未知，不能伪造为迁移操作者。

首版不为文件夹新增标签系统，也不把它塞入 `WorkspaceNativeTag` 或页面标签模型；文件夹标签属性显示不适用。在按标签分组的直属列表中，文件夹进入明确的“文件夹”组；其他按创建者、日期或类型分组规则照常适用。现有“全部文档”继续列文档和文件，不因增加文件夹而混入组织节点；文件夹在主树、容器列表和位置搜索中可见。

### 2.4 页面直属列表与导航

页面维持正文编辑优先，直属列表增加文件夹行。文件夹和页面视图共用同一列表实现，查询参数改为稳定 `parentNodeId`，不能将 `docId` 当作所有容器的 ID。

面包屑根据节点实际类型跳转：文件夹打开文件夹路由，页面打开原生文档，Office 和普通文件保持各自路径。权限过滤后的祖先路径不降级伪造为根位置。

正文已有子页面入口仍校验真实父子关系。子页面移入文件夹后，原正文入口显示为普通引用及最新可见位置，不继续声称它是直属子页；不为维护显示自动改写原正文或更新时间。旧引用的内容、身份和历史保留。

### 2.5 必须覆盖的状态

覆盖加载、空目录、只读、无权目标、加载失败、断线、提交中、重复请求、版本冲突、已回收、已永久删除、已转换类型及旧客户端不兼容。切换目标或账号取消旧请求；错误不透露无权资源的名称、数量或路径。

桌面浅色／深色及窄屏共用同一语义。键盘与触屏必须能完成新建、选择目标、移动、排序和生命周期操作；不能仅提供拖放路径。大目录按层分页，不能把部分页面作为完整目录或操作全集。

## 3 领域模型与存储

### 3.1 协议版本

在现有命名下新增契约 `localmind-page-tree/v2`，不为命名整洁而批量重命名模块。v2 表示双容器，v1 仍表示页面唯一容器。查询显式返回当前契约和客户端可用能力；`enabled: true` 不能再代表客户端理解全部节点类型。

以下为拟实施的领域类型，不是已存在的生成代码：

```ts
type TreeTarget = { kind: 'folder'; resourceId: string } | { kind: 'doc'; resourceId: string; primaryMode: 'page' | 'edgeless' } | { kind: 'office'; resourceId: string } | { kind: 'file'; resourceId: string };

type ResourceTreeNode = {
  nodeId: string;
  parentNodeId: string | null;
  order: string;
  resource: TreeTarget;
  trashed: boolean;
  trashRootNodeId?: string;
};
```

`folderId` 通过 `resource.kind === 'folder'` 明确解释；它不是 docId。`nodeId` 表示树中位置实体，是稳定、不透明身份。当前 `pageTreeNodeId()` 的类型前缀只能用于首次分配，转换后不能据当前资源类型重新计算 nodeId。

统一 `isPageTreeContainer()`：文件夹，或持久主模式为 page 的 doc。前端不能到处复制 `kind === 'doc' && primaryMode === 'page'` 条件；是否可创建、移动、重命名、转换等由服务端能力字段补充，不能从“是容器”推断用户权限。

### 3.2 唯一权威与文件夹元数据

继续使用现有 `folders` Yjs 表作为唯一归属权威，不增加 SQL parentId、不创建隐藏页面、不创建隐藏 Workspace。v2 文件夹记录同时保存其组织元数据：稳定 folderId、标题、创建证据、成对更新事件、元数据版本及生命周期。页面、Office、文件继续从各自内容域读取这些数据。

只有经验证的领域写入可以修改 v2 文件夹记录。旧客户端写出的 `type: folder` 增量不能仅凭类型相同而被接受；契约版本、原始同步写门禁及可信服务端事务上下文同时生效。

文件夹重命名属于真实元数据变更，推进它自己的更新事件和版本。移动、排序、子项增删、回收恢复、权限变更不推进文件夹或后代的内容更新时间。迁移保留已知旧创建证据，缺失则保留未知；迁移时间单独记入审计。

文件夹盘点来自受信任组织记录，内容资源盘点来自各自权威存储；合并后检查图完整性。不能把任意客户端提供的 folderId 清单当作资源存在证明。

### 3.3 数据库调整

不修改已经生成的 `20261009010000_workspace_page_tree` 迁移。新增按实际实施时间命名的迁移，至少处理：

- `WorkspacePageTreeState` 支持从已切换 v1 升级到 v2；状态检查和 CAS 不再只接受 `contractVersion === null`。
- 迁移计划显式区分来源契约和目标契约。历史 v1 plan、JSON、指纹、操作回执保持原值；新增字段对旧记录的解释有明确兼容规则，不重算历史证据。
- 新增带类型的 v2 迁移映射，按计划及来源身份唯一绑定目标 nodeId 与目标资源身份。现有 `WorkspacePageTreeMapping.documentId` 是必填，不得把 folderId 填入冒充文档；旧 v1 映射表保持只读解释。
- 容器转换保存不可变转换证据，包括前后类型、资源身份、稳定 nodeId、版本、权限摘要及正文快照引用。大正文存入受权不可变 Blob，不放进日志或无界 JSON。
- `(workspaceId, actorId, requestKey)` 的操作唯一约束继续生效。迁移映射、转换证据与 Workspace／plan／operation 之间设置外键及合适唯一键；SQL 只保存状态与证据，不成为另一套父级来源。

## 4 命令与 GraphQL

继续扩展现有 resolver 和领域服务。GraphQL 边界使用明确 input、枚举与严格 schema，不依赖若干可选字段推测命令含义。

| 命令                         | 核心输入                                 | 结果与约束                                     |
| ---------------------------- | ---------------------------------------- | ---------------------------------------------- |
| `createFolder`               | parentNodeId、title                      | 文件夹身份、位置、元数据及回执共同提交         |
| `createPage`／既有页面创建   | parentNodeId、title、primaryMode         | 文件夹和页面均可为父级；正文插入锚点仅接受页面 |
| `renameFolder`               | nodeId、expectedResourceVersion、title   | 更新文件夹自身证据，重复值不推进事件           |
| `move`／同级重排             | nodeId、parentNodeId、锚点或完整同级顺序 | 全图与实时权限校验；类型转换后的旧输入拒绝     |
| `trash`／`restore`／`delete` | nodeId、动作、期望位置／恢复目标         | 使用完整混合子树、独立回收 claim 和有界预览    |
| `previewContainerConversion` | nodeId、目标类型                         | 返回受权影响、正文状态、前置版本和拒绝原因     |
| `convertContainer`           | nodeId、目标类型、预览绑定版本           | 原子转换或持久恢复任务，重复请求返回同一结果   |

所有写入都带 Workspace、契约、树版本、授权版本和请求键；转换另绑定资源及正文版本。查回执、查询目录和预览本身不写正文或更新元数据。相同请求键但参数不同须拒绝。

查询条目增加实际 kind、`isContainer` 和当前 actor 的操作能力。文件夹元数据供直属列表读取；分页游标绑定契约、树版本、权限版本及查询排序，转换、撤权或升级后失效。

共享 `.gql`、真实 Nest schema、GraphQL 客户端类型和所有 Web／Admin／Electron／mobile 消费端同步更新，通过仓库生成命令产生。不得手工修改 generated 文件。

## 5 权限和生命周期

### 5.1 权限矩阵

| 行为                 | 文件夹                                   | 页面                                                 |
| -------------------- | ---------------------------------------- | ---------------------------------------------------- |
| 读取                 | Workspace 访问＋可披露路径＋目录读取权   | 前述条件＋文档读取权                                 |
| 新建容器             | 原有创建分类容器能力＋目标创建／组织权   | 文档创建能力＋目标创建／组织权                       |
| 新建 Office／文件    | 对应格式创建能力＋目标创建／组织权       | 同左；不额外要求编辑父页正文                         |
| 重命名               | 文件夹更新／组织权限及元数据版本         | 文档自身更新权                                       |
| 移动／重排           | 源与目标组织权及受影响授权约束           | 同左，同时维持资源自身 ACL                           |
| 转换为页面           | 目录管理条件＋文档创建能力＋权限等价验证 | 不适用                                               |
| 转换为文件夹         | 不适用                                   | 文档管理／生命周期条件＋创建文件夹能力＋权限等价验证 |
| 回收／恢复／永久删除 | 对完整涉及子树逐项检查生命周期权限       | 同左                                                 |

`canCreateFolder` 不等于任意文档创建权。UI 能力提示与服务端检查共用解释；只读成员可改个人排序，不可组织重排。父容器能读不代表可以编辑所有后代。

新建继承目标路径限制，移动保留资源自身 ACL。导致有效访问范围变化的普通移动或转换不能静默放宽或收紧；无法证明等价时拒绝，并指向现有权限管理流程。AI 不获得修改策略或批准授权的能力。

目录权限设置页同时列出文件夹与页面容器，以 nodeId 为策略锚点。文件夹无 doc ACL，不能默认“没有 doc ACL 就所有成员可写”；页面转换新增 doc ACL 后也必须证明有效主体权限与转换前等价。

首版不新增文件夹公开分享。父页面公开分享不自动公开文件夹及其后代。直接访问某资源仍按其权限处理，不能借此泄露隐藏祖先。

### 5.2 混合子树回收

文件夹和页面都使用“移至回收站”，确认框列出可披露的类型、数量和有限标题。任意必要后代无权处理则整项拒绝；无权的数量和标题也不能出现在错误中。

已单独回收的子项不随父容器恢复；旧位置失效时由用户明确选择可用文件夹、页面或根。永久删除先处理全子树及恢复依赖，再记录墓碑，不产生活动孤儿。内容和 Blob 的物理保留清理由既有保留策略处理，不能因为文件夹无正文而提前清除后代。

所有影响预览绑定提交版本。超时保留请求键并查询持久回执；确认失败不得展示成功通知或跳转。恢复／撤销不覆盖并发产生的新状态。

## 6 容器转换

### 6.1 文件夹转页面

这是首批必交付能力，入口为文件夹“更多 → 转换为页面”，确认文案说明“增加可编辑正文，现有下级及位置保留”。

转换保留 nodeId、父级、同级顺序、下级边、目录策略和个人容器偏好，建立真实 BlockSuite 文档并绑定同一节点。页面拥有本次真实创建事件，文件夹旧创建信息保存在来源证据中；不能伪装成早已存在的页面历史。

旧文件夹身份进入转换映射，旧文件夹链接受权解析到同一 nodeId 的当前页面；旧类型写命令拒绝，不能悄悄改写新页面。映射解析以稳定 nodeId 查当前类型，不维护可能循环的跳转链。

资源创建、权限配置、节点切换与回执应在现有可用事务边界内共同完成；若无法原子完成，使用 `prepared → applying → committed` 的持久阶段及可恢复失败状态，绑定确定资源 ID、租约和 checkpoint。未 committed 前不暴露半成品；取消仅在可安全撤销阶段生效。

### 6.2 空白页面转文件夹

作为独立阶段实施，不能通过删除 BlockSuite 内容或仅改图标实现。限制为当前正文在服务端判定为空，且不属于日记、模板等有额外语义的页面。空白判定只允许已知初始化骨架和空段落；未知块、附件、白板元素、数据库、同步块及子页面入口一律视为非空，不以提取文本为空作为证明。页面拥有下级本身不影响空白判断。

即使当前正文为空，也可能存在旧正文历史、评论或外部引用。因此必须先提供转换归档机制：

1. 冻结该次转换所需的正文、元数据和授权版本，保全旧 docId、正文快照、历史及必要关联证据。
2. 原 doc 进入明确的“转换归档”状态，退出活动内容盘点，不能以第二个活动节点挂在根目录。保留期、读取权限和物理清理由既有文档规则约束，不直接永久删除。
3. 同一 nodeId 改为真实文件夹身份，保留位置、下级、排序和等价目录权限。旧 doc URL 受权指向新容器并提供历史入口；原正文引用按映射显示当前容器，规范正文不批量重写。
4. 原 doc 同步写、旧 AI 编辑任务和旧版本命令拒绝，并给出“已转换为文件夹”的可操作错误；不能复活旧活动页面。
5. 若历史／评论／直接授权／引用不能被完整保全，当前对象禁止转换。普通新建文件夹和双容器能力不依赖放宽此门禁。

从该文件夹再次转页面时，按转换记录受控恢复同一 docId 及历史，检查期间权限与版本漂移，不随机创建另一个同名页面。单次重放与多次往返转换各有独立回执，不允许旧回执覆盖新类型。

本阶段的归档、路由、授权、同步及恢复验证全部通过后才能显示反向转换入口。前一阶段只开放文件夹转页面，不把完整反向转换描述为已实现。

## 7 迁移与旧客户端

### 7.1 三类来源

| 来源                       | v2 处理                                            | 禁止的处理                               |
| -------------------------- | -------------------------------------------------- | ---------------------------------------- |
| 尚未切换的旧目录           | 文件夹保留为真实文件夹；原有文档和文件绑定唯一位置 | 先转页面再改回文件夹                     |
| 已切换 v1 的体验 Workspace | 所有现有页面原样保留，升级协议并允许新建文件夹     | 根据名称、空白外观或旧来源自动降回文件夹 |
| 新建 Workspace             | 初始化根及 v2 能力，按用户选择创建两种容器         | 初始化旧目录后依赖后台补齐身份           |

旧目录多位置资源仍按完整路径、权限等价和稳定规则收敛为一个位置；权限冲突进入人工解决，不取最宽松路径，不复制内容规避冲突。旧 tag／collection 放置退出主归属树，正文引用及资源标签保留。

v1 中旧文件夹已经产生真实页面及 docId；这些页面可能已被编辑、引用或分享。v1→v2 不逆转该事实。当前隔离体验数据需要呈现文件夹时，直接新建样例文件夹并通过领域移动命令整理，保留用户原页面；不得重置整个体验库。

### 7.2 计划与执行

预检计划绑定来源／目标契约、树与内容指纹、权限摘要、迁移策略、typed 身份映射、回收依赖及备份证据。未执行的旧 v1 plan 可以明确失效后重新预检，不能改写其原始 JSON；已经冻结或部分执行的 v1 plan 必须先按原计划完成或恢复匹配备份，再进入 v2，禁止混用两套 checkpoint。

保留现有持久化阶段、租约、重试上限、取消和严格 CAS。v1 升级不能绕过现有 switched 状态直接重写契约字段；在锁内绑定来源契约和版本，拒绝并行迁移。

切换前备份数据库、Blob、映射及操作回执，完成隔离恢复演练，并暂停受影响 worker／写入口。最终清点全部活动和已回收资源的身份、正文、Blob、Office 修订、权限、标签、顺序与创建证据。先写 v2 图及映射，验证后发布切换状态，再恢复 v2 写入。

切换后有新写入时，不支持只改版本号回退。故障恢复须先冻结并保存切换后证据，再按明确范围恢复成套备份或前向修复；不能自动丢弃后续体验或业务写入。

### 7.3 客户端和协议兼容

v1 客户端不能将 folder 节点当作 doc、忽略后拼出“完整目录”，或继续用 v1 命令写 v2 树。不兼容时明确显示需升级，目录相关功能只读或禁用；现有受权正文读取／编辑仅在不涉及转换归档和结构写入时按兼容路径保留。

原始 Yjs 结构同步、根生命周期、文档主模式和目录策略更新仍经过权威检查。已转换归档文档的迟到增量被拒绝；旧快照不能重新创建文件夹或页面位置。仅增加 v2 类型白名单不构成协议切换。

## 8 本地 Workspace、导入和外部入口

### 8.1 本地与上传

本地适配支持 folder typed 身份及持久元数据，复用排他锁、持久日志、幂等和断点恢复。不得为每个文件夹调用 `DocsService.createDocAsync()`。本地 v1 升级同样保留已存在页面，旧目录迁移保留文件夹。

上传清单增加文件夹 kind、元数据证据、位置、排序和回收关系；文件夹无正文 Blob，不得通过补空白文档上传。服务端校验冻结清单与真实内容盘点，并在同一受控 adoption 中建立完整图。源变更、账号切换、目标不支持 v2 或响应不确定时保留本地来源，不能删除后重建同名 Workspace。

根及容器偏好以实例、账号、Workspace 和稳定 nodeId 隔离；迁移尊重目标显式值。模板／ZIP／文件夹导入中的目录默认成为文件夹，文档成为页面，导入中的子页面块仍降为普通引用；结构来自可信导入清单，不从正文反推。

### 8.2 内部 AI 与公开 MCP

内部 Workspace AI 增加明确的 `workspace_folder_create`、`workspace_folder_rename`，目录查询返回 folder 类型。现有 `workspace_page_tree_*` 的 v2 实现复用相同服务。容器转换使用独立工具及明确用户意图，绑定预览和版本，不让普通改名／移动隐式执行转换。

工具 schema／能力快照按契约版本固定。旧冻结任务不能因服务端支持 folder 就自动获得新目标类型；旧 v1 任务维持原解释并在不兼容时拒绝或退役，审计仍可读。Project 和私人工单不因此注册 Workspace 工具，AI 不管理权限或批准授权。

公开 MCP 本期不新增双容器写能力，不复用旧模糊名称注册别名，不扩大旧凭据或默认打开资源开关。对 v2 不兼容的目录操作返回明确契约错误；独立的资源内容读写仅在原授权和当前资源状态允许时继续。后续公开 v2 能力必须单独定义 schema、授权和客户端验收。

### 8.3 Project 发布

发布目标选择器允许受权文件夹、页面或根，绑定 Workspace、parentNodeId、目标 kind、v2 契约和预览版本。由于候选 `project-publication/v3` 冻结的是页面容器语义，新增 `project-publication/v4` 预览／回执解释，不能原地扩大已批准 v3 目标。

历史 v3 回执仍可查询；在 v2 目标上重新发布需要重新预览并确认 v4，不能把旧发布参数静默升级。Project 内部资源、成员、Office 内容和复制审批维持现行契约。发布创建独立副本，后续更新绑定既有目标资源身份，目标被转换、回收或撤权时拒绝，不新建替代副本。

## 12 验证与交付方式

文档阶段仅运行格式和差异检查。本次不重新构建镜像，不改变正在运行的 v1 体验环境。

开发阶段遵守[Docker 开发约束](../localmind-docker-development-constraints.md)，优先复用固定 `localmind-affine:test` 或已有验证容器。当前环境若继续复用 `localmind-affine:dev-base`，需如实记录该事实。新建专用 v2 数据库、Blob 根目录和运行实例，先备份 v1 合成体验内容，不覆盖正在使用的 v1 数据。

现有 v1 体验实例挂载本 worktree 并有前端热更新。P0 必须先保存完整的 v1 源码状态，让 v1 实例使用受控的冻结源码快照并确认可打开；不能一边直接编辑同一挂载目录，一边声称旧体验版本保持不变。v2 实例再挂载开发 worktree，使用独立回环地址端口、数据库和 Blob 根。该步骤属于隔离体验环境维护，不使用正式部署或运行同步脚本，也不要求重建完整镜像。

```sh
yarn prettier --ignore-unknown --check <changed-doc-files>
git diff --check

# 以下在匹配源码的隔离 Linux 容器中执行。
yarn workspace @affine/server prisma validate
yarn workspace @affine/server prisma generate
yarn workspace @affine/server prisma migrate deploy
yarn workspace @affine/server test --timeout=3m src/__tests__/copilot/workspace-page-tree.e2e.ts
yarn workspace @affine/server test --timeout=3m src/__tests__/copilot/project-publication.e2e.ts
yarn vitest run packages/common/graphql/src/workspace-page-tree.spec.ts packages/frontend/core/src/modules/organize --maxWorkers=1
yarn typecheck
```

实施时补充新增 folder／conversion 单元和 e2e、生命周期／导入／资源显示测试、MCP 与同步回归，以及真实仓库 GraphQL／i18n 生成命令。数据库验收包括全新库应用全部迁移、旧目录 fixture→v2、v1 fixture→v2、失败恢复和至少一次完整回滚演练；生成成功不能替代行为验证。

每个阶段记录精确命令、退出结果、镜像标签、是否重建、磁盘状态、截图和剩余风险。最终交付独立 worktree、体验入口、合成账号、源码改动范围及逐条验收证据；只有用户另行决定保留和集成后，才处理主线或部署。
